# Контент: как писать роадмапы, конспекты и тесты

Папка `content/` — это **хранилище Obsidian**. Откройте её в Obsidian через «Open folder as vault» и пишите как обычные заметки. Сайт сам соберёт из них карту роадмапа, страницы тем, практику и тесты.

```
content/
├── README.md                ← эта инструкция
├── _templates/Тема.md       ← шаблон темы (плагин Templates в Obsidian)
└── roadmaps/
    └── devops/              ← адрес роадмапа: /roadmaps/devops (латиница, цифры, дефис)
        ├── roadmap.md       ← карта: разделы и порядок тем
        └── topics/          ← заметки-темы, можно раскладывать по любым подпапкам
            └── 01 Основы ИТ/
                ├── Устройство компьютера.md
                └── ...
```

## 1. Карта роадмапа — `roadmap.md`

```markdown
---
title: DevOps — от нуля до L2
description: Короткое описание для карточки роадмапа.
mode: sequential     # sequential — темы открываются по порядку; free — всё открыто сразу
passScore: 80        # процент для зачёта теста по умолчанию
order: 1             # порядок в списке роадмапов
---

## Название раздела
Описание раздела одной строкой.

- [[Устройство компьютера]]
	- Подтема
	- Ещё подтема
- [[BGP]] #optional
```

- `## Раздел` — раздел на карте.
- `- [[Заметка]]` — тема. Порядок пунктов = порядок прохождения.
- Вложенные пункты — подтемы: показываются на карте и в шапке темы.
- `#optional` — необязательная тема: открыта всегда и не блокирует следующие.
- `- [[Заметка|Другое название]]` — показать тему под другим именем.
- Если заметки ещё нет (ссылка в Obsidian «пустая»), тема всё равно появится на сайте с пометкой «нет конспекта», и её можно будет отметить изученной вручную. Кликните по ссылке в Obsidian — заметка создастся.

## 2. Тема — отдельная заметка

Начните с шаблона `_templates/Тема.md`. Поля в начале заметки (frontmatter):

| Поле | Зачем |
| --- | --- |
| `title` | Название темы (иначе — имя файла) |
| `slug` | Адрес темы и ключ прогресса в базе. **Задайте один раз и не меняйте** — иначе прогресс по теме потеряется. Без slug адрес строится из имени файла |
| `description` | Подзаголовок темы |
| `duration` | Сколько минут занимает тема |
| `level` | Уровень: Основы, Продвинутый… |
| `quizSize` | Сколько вопросов давать за попытку (случайно из банка) |
| `passScore` | Процент для зачёта, если отличается от роадмапа |
| `materials` | Список ссылок `title` + `url` (+ `type`, `note`) |
| `aliases` | Другие названия заметки для ссылок `[[...]]` |
| `draft: true` | Пометить тему черновиком |

Всё, что написано в заметке, становится **конспектом**, кроме специальных разделов второго уровня:

- `## Практика` — пункты `- [ ] ...` превращаются в чек-лист, который отмечается на сайте.
- `## Материалы` — строки `- [Название](https://...) — комментарий`.
- `## Тест` — вопросы (формат ниже).

Работают ссылки `[[Другая тема]]`, картинки `![[схема.png]]` (файл кладите в любую папку внутри `content/`), `==выделение==`, таблицы, код с подсветкой и callout-блоки `> [!tip]`, `> [!warning]`, `> [!note]`, `> [!danger]`.

## 3. Тест

```markdown
## Тест

### Вопрос с одним ответом?
- [ ] неверно
- [x] верно
> Пояснение после сдачи.

### Вопрос с несколькими ответами?
- [x] верно
- [x] верно
- [ ] неверно

### Какой командой посмотреть таблицу маршрутов?
= ip route
= ip r
```

- Один `[x]` — один ответ (радиокнопки), несколько `[x]` — несколько ответов (чекбоксы).
- Строки `= ответ` — вопрос с вводом текста; можно перечислить все допустимые варианты.
- `> текст` — пояснение. Показывается только после успешной сдачи, чтобы тест нельзя было пройти «по подсказкам».
- Вопросы и варианты перемешиваются при каждой попытке. Если вопросов больше, чем `quizSize`, каждый раз выпадает случайный набор — делайте банк вопросов побольше.
- Пишите вопросы **не только по конспекту, а по всему важному в теме**: понимание, команды, диагностика, «что сделать, если…».

## 4. Проверка

```bash
npm run content:check
```

Покажет, сколько тем с конспектами и тестами, и найдёт ошибки: вопросы без правильного ответа, `quizSize` больше банка вопросов.
