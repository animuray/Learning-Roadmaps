# TLS и сертификаты

**TLS** (Transport Layer Security, раньше — SSL) решает три задачи:

1. **Шифрование** — посторонний не прочитает трафик.
2. **Аутентификация сервера** — клиент убеждается, что говорит именно с `example.com`, а не с подменой.
3. **Целостность** — данные нельзя незаметно изменить по дороге.

TLS используется в HTTPS, а также в защищённых подключениях к базам, почте, Kubernetes API, gRPC. Актуальные версии — **TLS 1.2** и **TLS 1.3**. SSL 3.0, TLS 1.0 и 1.1 устарели и должны быть отключены.

## Немного криптографии

- **Асимметричная** криптография: пара ключей. Что зашифровано открытым ключом, расшифрует только закрытый; подпись закрытым ключом проверяется открытым. Это медленно, поэтому используется для установления соединения и подписей.
- **Симметричная** криптография: один общий ключ (AES, ChaCha20). Быстро — ей шифруется сам трафик.
- TLS handshake нужен, чтобы стороны **безопасно договорились об общем симметричном ключе** и клиент проверил сертификат сервера.

## TLS handshake (упрощённо, TLS 1.3)

Происходит после TCP-рукопожатия:

1. **ClientHello** — клиент отправляет поддерживаемые версии и наборы шифров, случайное число, свою часть обмена ключами (Diffie-Hellman) и **SNI** — имя сайта, к которому идёт подключение.
2. **ServerHello** — сервер выбирает версию и шифр и отправляет свою часть обмена ключами. С этого момента обе стороны вычисляют общий секрет, и дальше всё шифруется.
3. Сервер отправляет **сертификат** и подпись, доказывающую, что у него есть закрытый ключ от этого сертификата, затем **Finished**.
4. Клиент **проверяет сертификат**: имя совпадает с доменом, срок действия не истёк, цепочка ведёт к доверенному корневому сертификату. Затем отправляет **Finished**.
5. Дальше идут зашифрованные HTTP-запросы.

TLS 1.3 укладывается в одну пару сообщений туда-обратно (1-RTT), TLS 1.2 — в две.

**SNI** позволяет держать много HTTPS-сайтов на одном IP: по имени из ClientHello сервер понимает, какой сертификат отдать.

## Сертификаты и цепочка доверия

**Сертификат X.509** содержит: доменные имена (поле **SAN**), открытый ключ, срок действия, издателя и подпись издателя.

```
Корневой сертификат УЦ (Root CA)       ← встроен в ОС и браузеры, «якорь доверия»
   └── Промежуточный сертификат (Intermediate CA)
          └── Сертификат сайта (leaf): example.com
```

- Сервер должен отдавать **свой сертификат и промежуточные** (fullchain). Если промежуточный не отдать, часть клиентов (особенно не браузеры: curl, Java, мобильные приложения) не сможет построить цепочку и выдаст ошибку.
- **Самоподписанный** сертификат подписан сам собой — ему никто не доверяет, кроме тех, кому вы вручную его добавили. Подходит для тестов и внутренних сервисов с собственным УЦ.
- **Wildcard** `*.example.com` подходит для `api.example.com`, но не для `example.com` и не для `a.b.example.com`.
- Типы проверки: **DV** (проверено только владение доменом), OV и EV (проверена организация).

## Let's Encrypt

**Let's Encrypt** — бесплатный автоматизированный УЦ. Сертификаты DV живут **90 дней** и обновляются автоматически по протоколу **ACME**.

Проверка владения доменом:

- **HTTP-01** — УЦ запрашивает файл `http://домен/.well-known/acme-challenge/…`. Нужен открытый порт 80.
- **DNS-01** — нужно создать TXT-запись `_acme-challenge.домен`. Единственный способ получить **wildcard**-сертификат.

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com   # получит сертификат и настроит nginx
sudo certbot renew --dry-run                             # проверить автопродление
systemctl list-timers | grep certbot                     # таймер продления
```

Файлы лежат в `/etc/letsencrypt/live/example.com/`: `fullchain.pem` (сертификат + промежуточные) и `privkey.pem` (закрытый ключ, права 600).

## Проверка сертификатов через openssl

```bash
# Какой сертификат отдаёт сервер, цепочка, версия TLS
openssl s_client -connect example.com:443 -servername example.com </dev/null

# Срок действия и имена
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates -ext subjectAltName

# Посмотреть файл сертификата
openssl x509 -in fullchain.pem -noout -text

# Самоподписанный сертификат для тестов
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 30 -subj "/CN=test.local"
```

## Частые ошибки

| Ошибка | Причина |
| --- | --- |
| `certificate has expired` | Истёк срок — не сработало автопродление. Мониторьте сроки! |
| `hostname mismatch` / `no alternative certificate subject name matches` | Сертификат выпущен на другое имя |
| `unable to get local issuer certificate` | Сервер не отдаёт промежуточный сертификат, или у клиента нет корневого |
| `self-signed certificate` | Самоподписанный или внутренний УЦ, которому клиент не доверяет |
| Сертификат не того сайта | Клиент не отправил SNI или на сервере неверно настроен виртуальный хост |

## Практика

- [ ] Посмотреть сертификат и цепочку любого сайта через `openssl s_client` и найти SAN, издателя и сроки
- [ ] Выполнить `curl -v https://...` и найти в выводе версию TLS, шифр и проверку сертификата
- [ ] Создать самоподписанный сертификат, подключить его к nginx (в теме про Nginx) и посмотреть на ошибку в браузере и curl
- [ ] Если есть домен и сервер — получить сертификат Let's Encrypt через certbot и проверить `renew --dry-run`
- [ ] Написать однострочник, который выводит, сколько дней осталось до истечения сертификата сайта
