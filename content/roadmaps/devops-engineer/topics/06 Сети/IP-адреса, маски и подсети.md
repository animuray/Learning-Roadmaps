# IP-адреса, маски и подсети

Без подсетей не настроить ни облачную сеть (VPC), ни Docker, ни Kubernetes, ни файрвол. Вопрос «что такое маска подсети» звучит почти на каждом собеседовании.

## IPv4-адрес

IPv4-адрес — 32 бита, записанные как четыре числа от 0 до 255 через точку (октеты):

```
192.168.1.10  =  11000000.10101000.00000001.00001010
```

Адрес состоит из двух частей: **адрес сети** и **адрес узла** в этой сети. Где проходит граница, говорит **маска**.

## Маска и CIDR

Маска — тоже 32 бита: единицы отмечают сетевую часть, нули — часть узла.

```
IP:      192.168.1.10   11000000.10101000.00000001.00001010
Маска:   255.255.255.0  11111111.11111111.11111111.00000000
Сеть:    192.168.1.0    (побитовое И адреса и маски)
```

**CIDR**-запись — число единиц в маске после слеша: `192.168.1.10/24`.

| CIDR | Маска | Адресов всего | Узлов (адресов минус 2) |
| --- | --- | --- | --- |
| /8 | 255.0.0.0 | 16 777 216 | 16 777 214 |
| /16 | 255.255.0.0 | 65 536 | 65 534 |
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /30 | 255.255.255.252 | 4 | 2 |
| /32 | 255.255.255.255 | 1 | один конкретный хост |

Число адресов = 2^(32 − префикс). Из них два служебных:

- **адрес сети** — все биты узла равны 0 (`192.168.1.0`);
- **широковещательный** (broadcast) — все биты узла равны 1 (`192.168.1.255`).

> [!note] В облаках адресов ещё меньше
> Облачные провайдеры резервируют в каждой подсети ещё несколько адресов под шлюз, DNS и служебные нужды. Точное число смотрите в документации провайдера.

### Пример расчёта

`10.0.5.77/26`: префикс 26 → в последнем октете блоки по 2^(32−26) = 64 адреса: 0–63, 64–127, 128–191, 192–255. 77 попадает в блок 64–127.

- сеть: `10.0.5.64`;
- первый узел: `10.0.5.65`;
- последний узел: `10.0.5.126`;
- broadcast: `10.0.5.127`.

Проверить себя: `ipcalc 10.0.5.77/26` (пакет `ipcalc`).

## Шлюз по умолчанию

Если адрес назначения в **той же** подсети — пакет отправляется напрямую (через ARP узнаётся MAC). Если в **другой** — пакет уходит на **шлюз по умолчанию** (default gateway), маршрутизатор, который знает, куда дальше.

```bash
ip a                 # адреса интерфейсов с префиксом: inet 10.0.0.5/24
ip route             # default via 10.0.0.1 dev eth0 — шлюз по умолчанию
ip route get 8.8.8.8 # каким маршрутом пойдёт пакет к адресу
```

## Частные адреса и NAT

Для внутренних сетей зарезервированы диапазоны (RFC 1918) — в интернете они не маршрутизируются:

| Диапазон | CIDR |
| --- | --- |
| 10.0.0.0 – 10.255.255.255 | `10.0.0.0/8` |
| 172.16.0.0 – 172.31.255.255 | `172.16.0.0/12` |
| 192.168.0.0 – 192.168.255.255 | `192.168.0.0/16` |

Другие особые адреса:

- `127.0.0.0/8` — **loopback**, сама машина (`127.0.0.1`, `localhost`);
- `169.254.0.0/16` — link-local: адрес, который система выдаёт себе сама, если DHCP не ответил;
- `0.0.0.0` — «все адреса» (сервер слушает на всех интерфейсах) или маршрут по умолчанию `0.0.0.0/0`;
- `100.64.0.0/10` — адреса для операторского NAT (CGNAT).

**NAT** (трансляция адресов) позволяет машинам с частными адресами ходить в интернет через один публичный адрес маршрутизатора. Так работают домашний роутер, NAT-шлюз в облаке и сеть Docker по умолчанию.

## Планирование подсетей

Типичная схема в облаке: VPC `10.0.0.0/16`, внутри подсети `10.0.1.0/24` (публичная — балансировщики), `10.0.2.0/24` (приложения), `10.0.3.0/24` (базы). Важно, чтобы подсети не **пересекались** — ни между собой, ни с сетями офиса, VPN и Docker. Иначе маршрутизация сломается.

Docker по умолчанию использует `172.17.0.0/16`, а Kubernetes — свои диапазоны для подов и сервисов. Конфликт с корпоративной сетью — частая причина «странной» недоступности.

## IPv6 в двух словах

128 бит, запись шестнадцатеричными группами: `2001:db8::1`. Адресов хватает всем, поэтому NAT обычно не нужен. `::1` — loopback, `fe80::/10` — link-local. На серверах всё чаще встречаются оба протокола одновременно (dual stack).

= 256
> Из них 254 доступны узлам: адрес сети и broadcast служебные.

### Какая маска соответствует префиксу /26?
- [ ] 255.255.255.0
- [x] 255.255.255.192
- [ ] 255.255.255.224
- [ ] 255.255.0.0
> 26 единиц: три октета по 8 и ещё 2 бита в последнем (128 + 64 = 192).

### Для чего нужна маска подсети?
- [ ] Для шифрования адреса
- [x] Чтобы определить, какая часть IP-адреса — адрес сети, а какая — адрес узла
- [ ] Чтобы скрыть адрес от сканирования
- [ ] Для выбора DNS-сервера
> По маске узел понимает, отправлять пакет напрямую или через шлюз.

### Какой адрес сети у узла 10.0.5.77/26?
= 10.0.5.64
> Блоки по 64: 0–63, 64–127… 77 попадает в блок 64–127.

### Какой broadcast-адрес у подсети 10.0.5.64/26?
= 10.0.5.127
> Все биты узла равны единице: последний адрес блока.

### Какие диапазоны являются частными (RFC 1918)?

- [x] 192.168.0.0/16
- [ ] 8.8.8.0/24

### Куда отправляется пакет, если адрес назначения не в локальной подсети?
- [ ] Отбрасывается
- [x] На шлюз по умолчанию (default gateway)
- [ ] Всем узлам подсети
- [ ] На DNS-сервер
> Шлюз знает, куда передавать пакеты в другие сети.

### Какой командой посмотреть шлюз по умолчанию в Linux?
= ip route
= ip r
> Строка `default via ...` — это и есть шлюз.

### Что означает адрес 127.0.0.1?
- [ ] Шлюз по умолчанию
- [x] Loopback — сама машина
- [ ] Широковещательный адрес
- [ ] Адрес DNS-сервера
> Сервис, который слушает 127.0.0.1, недоступен с других машин.

### Сколько адресов узлов доступно в подсети /30?
= 2
> 4 адреса минус адрес сети и broadcast. Классическая подсеть для соединения двух маршрутизаторов.

### Зачем нужен NAT?
- [ ] Чтобы шифровать трафик
- [x] Чтобы машины с частными адресами выходили в интернет через публичный адрес шлюза
- [ ] Чтобы ускорить DNS
- [ ] Чтобы раздавать адреса по DHCP
> Так работают домашние роутеры, NAT-шлюзы в облаке и сеть Docker по умолчанию.

### Почему важно, чтобы подсети VPC не пересекались с сетью офиса, VPN и Docker?
- [ ] Иначе не будет работать DNS
- [x] При пересечении узел не сможет понять, куда отправлять пакеты, и часть адресов станет недоступна
- [ ] Иначе облако выставит больший счёт
- [ ] Пересечение подсетей ускоряет сеть
> Планируйте адресацию заранее.

### Какой адрес система назначает себе сама, если DHCP-сервер не ответил?
- [ ] 127.0.0.1
- [ ] 10.0.0.1
- [x] Адрес из диапазона 169.254.0.0/16 (link-local)
- [ ] 0.0.0.0
> Увидели 169.254.x.x — проблема с получением адреса по DHCP.
