# Работа с текстом

Логи, конфиги, вывод команд — всё это текст. Умение быстро отфильтровать, посчитать и преобразовать строки однострочником — повседневный навык при отладке. Утилиты маленькие, а их сила — в комбинации через пайпы.

## grep — найти строки

```bash
grep error app.log              # строки со словом error
grep -i error app.log           # без учёта регистра
grep -v DEBUG app.log           # строки БЕЗ DEBUG (инверсия)
grep -n "listen" nginx.conf     # с номерами строк
grep -c 500 access.log          # только количество совпадений
grep -r "password" /etc/app/    # рекурсивно по каталогу
grep -rl "TODO" src/            # только имена файлов
grep -w port config             # целое слово (не сработает на «export»)
grep -A 3 -B 2 Exception app.log  # 3 строки после и 2 до совпадения (-C 3 — вокруг)
grep -E "error|warn" app.log    # расширенные регулярные выражения: | + ? ()
grep -o "[0-9]\+ms" app.log     # вывести только совпавшую часть
```

Основы регулярных выражений: `^` — начало строки, `$` — конец, `.` — любой символ, `*` — повтор 0 и более раз, `[0-9]` — символ из набора. Пример: `grep -v "^#" sshd_config | grep -v "^$"` — конфиг без комментариев и пустых строк.

## cut — вырезать поля

```bash
cut -d: -f1 /etc/passwd        # имена пользователей (разделитель «:», поле 1)
cut -d, -f2,4 data.csv         # поля 2 и 4
cut -c1-10 file                # символы с 1 по 10
```

`cut` понимает только один символ-разделитель. Если поля разделены несколькими пробелами, используйте `awk`.

## awk — работа с колонками

awk делит каждую строку на поля по пробелам: `$1`, `$2`, …, `$NF` — последнее поле, `$0` — вся строка, `NR` — номер строки.

```bash
awk '{print $1}' access.log                 # первая колонка — IP-адреса
awk -F: '{print $1, $7}' /etc/passwd        # свой разделитель
awk '$9 == 500' access.log                  # строки, где 9-е поле равно 500
awk '$3 > 80 {print $1}' usage.txt          # условие на число
awk '{sum += $10} END {print sum}' access.log   # сумма колонки (байты ответов)
df -h | awk 'NR > 1 {print $5, $6}'         # пропустить заголовок
```

## sed — потоковый редактор

```bash
sed 's/8080/9090/' config          # заменить первое вхождение в каждой строке (вывод на экран)
sed 's/8080/9090/g' config         # все вхождения
sed -i 's/8080/9090/g' config      # изменить файл на месте
sed -i.bak 's/old/new/g' config    # то же с резервной копией config.bak
sed -n '10,20p' file               # напечатать строки 10–20
sed '/^#/d' config                 # удалить строки-комментарии
sed -i 's|/var/www|/srv/www|g' nginx.conf   # другой разделитель, если в тексте есть /
```

## sort, uniq, wc

```bash
sort names.txt            # по алфавиту
sort -n numbers.txt       # как числа (иначе 10 окажется раньше 9)
sort -rn                  # по убыванию
sort -k2 -t, data.csv     # по второму полю с разделителем «,»
sort -h                   # «человеческие» размеры: 1K, 5M, 2G
sort -u                   # сортировка с удалением дубликатов

uniq                      # убирает СОСЕДНИЕ повторы → сначала sort!
uniq -c                   # посчитать, сколько раз встретилась строка
uniq -d                   # только повторяющиеся

wc -l file                # число строк
wc -w file                # слов
wc -c file                # байтов
```

## xargs — превратить строки в аргументы

Многие команды (`rm`, `kill`, `chmod`) не читают stdin — им нужны аргументы. `xargs` собирает их из входа:

```bash
find . -name "*.tmp" | xargs rm
find . -name "*.log" -print0 | xargs -0 gzip      # безопасно для имён с пробелами
cat hosts.txt | xargs -I{} ssh {} uptime          # подставить каждую строку в {}
echo 1 2 3 4 | xargs -n 2 echo                    # по 2 аргумента за вызов
```

## Боевые однострочники

```bash
# Топ-10 IP-адресов по числу запросов в логе nginx
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

# Сколько ответов с каждым HTTP-кодом
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# Ошибки за последние 1000 строк лога, без дубликатов
tail -n 1000 app.log | grep -i error | sort | uniq -c | sort -rn

# Пользователи с оболочкой bash
grep 'bash$' /etc/passwd | cut -d: -f1
```

Ещё пригодятся `tr` (замена или удаление символов: `tr a-z A-Z`, `tr -d '\r'`), `head`, `tail`, `diff` и `column -t` для выравнивания таблиц.

### Топ IP-адресов

По логу `~/logs/access.log` найдите **три** IP-адреса, с которых пришло больше всего запросов. Сохраните результат в `~/top-ip.txt` — от самого активного, по строке на адрес (рядом с адресом может стоять число запросов).

```bash check
f=/home/student/top-ip.txt
[ -s $f ] || fail "~/top-ip.txt пуст или не создан"
want=$(awk '{print $1}' /home/student/logs/access.log | sort | uniq -c | sort -rn | head -3 | awk '{print $2}')
got=$(grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' $f | head -3)
[ "$(echo "$got" | wc -l)" -ge 3 ] || fail "В файле меньше трёх IP-адресов"
[ "$got" = "$want" ] || fail "Не тот топ (или не тот порядок). У вас:
$(head -3 $f)"
ok "$(echo $want)"
```

```text hint
1. Вырезать из каждой строки первое поле — IP.
2. Отсортировать, чтобы одинаковые адреса оказались рядом.
3. Схлопнуть повторы, посчитав их.
4. Отсортировать по числу, по убыванию, и взять первые три строки.
```

```bash solution
awk '{print $1}' ~/logs/access.log | sort | uniq -c | sort -rn | head -3 > ~/top-ip.txt
```

```text review
Эталон: `awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -3`.

- Это самый частый однострочник на собеседованиях и в инцидентах: «кто нас долбит».
- `uniq` схлопывает только **соседние** повторы — поэтому перед ним обязательно `sort`.
- `sort -rn`: `-n` — по числу (иначе «9» окажется выше «100»), `-r` — по убыванию.
- `cut -d' ' -f1` вместо awk тоже работает для первого поля. На больших логах `awk '{c[$1]++} END {for (ip in c) print c[ip], ip}'` быстрее: не нужна сортировка всего потока.
```

```text notes
^(?:(?!\bsort\b).)*\buniq\b => uniq без предварительного sort схлопывает только соседние строки — счёт получится неверным.
sort\s+-r(?!n)\b|sort\s+-r\s*\| => sort -r без -n сортирует числа как текст: «9» окажется выше «100». Для счётчиков нужен sort -rn.
```

### Ошибки сервера

Сколько в логе ответов с кодом **5xx** (500–599)? Запишите одно число в `~/5xx.txt`.

```bash check
[ -f /home/student/5xx.txt ] || fail "Нет ~/5xx.txt"
want=$(awk '$9 ~ /^5[0-9][0-9]$/' /home/student/logs/access.log | wc -l)
got=$(tr -d '[:space:]' < /home/student/5xx.txt)
[ "$got" = "$want" ] || fail "В файле «$got», а ответов с кодом 5xx в логе — другое число"
ok "ответов 5xx: $want"
```

```text hint
Код ответа — отдельное поле строки (посчитайте, какое по счёту, если делить строку по пробелам). Отберите строки, где это поле начинается с 5 и состоит из трёх цифр, и посчитайте их.
```

```bash solution
awk '$9 ~ /^5/' ~/logs/access.log | wc -l > ~/5xx.txt
```

```text review
Эталон: `awk '$9 ~ /^5/' access.log | wc -l` (или `awk '$9 >= 500 {n++} END {print n}'`).

- Код ответа в формате combined — девятое поле. Условие по полю надёжнее поиска по всей строке: `grep ' 5'` найдёт и размер ответа «5012», и минуты «10:05».
- `grep -cE '" 5[0-9]{2} '` — рабочий вариант через grep: код всегда идёт сразу после закрывающей кавычки запроса.
- Распределение по всем кодам одной командой: `awk '{print $9}' access.log | sort | uniq -c`.
```

```text notes
grep\s+(-c\s+)?["']?\s?5["']? => Поиск «5» по всей строке находит и размеры ответов, и время. Ищите по полю кода ответа (awk '$9 ~ /^5/') или с привязкой к кавычке перед кодом.
```

### Конфиг без комментариев

Выведите `/etc/ssh/sshd_config` **без строк-комментариев и без пустых строк** и сохраните в `~/sshd-clean.txt`.

```bash check
f=/home/student/sshd-clean.txt
[ -s $f ] || fail "~/sshd-clean.txt пуст или не создан"
want=$(grep -Ev '^[[:space:]]*(#|$)' /etc/ssh/sshd_config)
got=$(cat $f)
grep -Eq '^[[:space:]]*#' $f && fail "В файле остались комментарии"
grep -Eq '^[[:space:]]*$' $f && fail "В файле остались пустые строки"
[ "$got" = "$want" ] || fail "Вместе с комментариями пропали строки настроек (их должно быть $(echo "$want" | wc -l), а в файле $(wc -l < $f))"
ok "строк настроек: $(wc -l < $f)"
```

```text hint
Нужен поиск с инверсией — вывести строки, которые НЕ подходят под шаблон. Шаблон: «строка начинается с # (возможно, после пробелов) ИЛИ строка пустая». Для «ИЛИ» включите расширенные регулярные выражения.
```

```bash solution
grep -Ev '^\s*(#|$)' /etc/ssh/sshd_config > ~/sshd-clean.txt
```

```text review
Эталон: `grep -Ev '^\s*(#|$)' /etc/ssh/sshd_config`.

- `-v` — инверсия, `-E` — расширенные регулярки (`|` и скобки без экранирования).
- `^\s*#` учитывает комментарии с отступом; `^$` — пустые строки. Объединив их, получаем один проход вместо двух grep подряд.
- Это первое, что делают с незнакомым конфигом: из 120 строк sshd_config значимых обычно 5–10.
- Два grep через пайп (`grep -v '^#' | grep -v '^$'`) работают, но пропустят комментарии с отступом.
```

### Порт в конфиге

В `~/app.conf` замените порт `8080` на `9090` **прямо в файле**, сохранив резервную копию исходника как `~/app.conf.bak`. Сделайте это одной командой `sed`.

```bash setup
printf 'host=0.0.0.0\nport=8080\nworkers=4\n# старый порт был 8080\n' > /home/student/app.conf
rm -f /home/student/app.conf.bak
chown student:student /home/student/app.conf
```

```bash check
h=/home/student
[ -f $h/app.conf.bak ] || fail "Нет резервной копии ~/app.conf.bak"
grep -qx 'port=8080' $h/app.conf.bak || fail "В app.conf.bak должен остаться исходный port=8080"
grep -qx 'port=9090' $h/app.conf || fail "В app.conf нет строки port=9090"
grep -qx 'port=8080' $h/app.conf && fail "В app.conf осталась строка port=8080"
grep -qx 'host=0.0.0.0' $h/app.conf && grep -qx 'workers=4' $h/app.conf || fail "Пропали другие настройки"
grep -q 'старый порт был 8080' $h/app.conf || fail "Комментарий «старый порт был 8080» тоже поменялся — замена задела лишнее"
ok "$(grep port $h/app.conf | head -1)"
```

```text hint
Потоковый редактор умеет править файл на месте, сразу оставляя резервную копию с указанным суффиксом. Заменяйте не «8080» везде, а именно строку параметра port — иначе поменяется и комментарий.
```

```bash solution
sed -i.bak 's/^port=8080$/port=9090/' ~/app.conf
```

```text review
Эталон: `sed -i.bak 's/^port=8080$/port=9090/' app.conf`.

- `-i.bak` правит файл на месте и сохраняет исходник с суффиксом `.bak`. На macOS (BSD sed) синтаксис другой: `-i '.bak'` — частая ловушка в скриптах для разных ОС.
- Якоря `^` и `$` ограничивают замену строкой настройки. `s/8080/9090/g` поменяет все вхождения — включая комментарии, URL и чужие параметры вроде `metrics_port=18080`.
- После правки — `diff app.conf.bak app.conf`: видно ровно то, что поменялось.
- В Ansible ту же задачу решают модулем `lineinfile` — он ещё и идемпотентен.
```

```text notes
s/8080/9090/g? => Замена «8080» без привязки к параметру меняет все вхождения — в этом файле задела бы и комментарий. Ограничивайте замену: s/^port=8080$/port=9090/.
sed\s+-i\s+(?!\.bak)['"]?s => sed -i без суффикса не оставляет резервной копии — при ошибке в выражении исходник не восстановить.
```

### Пользователи и оболочки

Выведите из `/etc/passwd` для **каждого** пользователя имя и оболочку через пробел (`root /bin/bash`) и сохраните в `~/shells.txt`.

```bash check
f=/home/student/shells.txt
[ -s $f ] || fail "~/shells.txt пуст или не создан"
want=$(awk -F: '{print $1, $7}' /etc/passwd)
got=$(sed 's/[[:space:]]\+/ /g; s/ $//' $f)
[ "$got" = "$want" ] || fail "Список не совпал с /etc/passwd. Первые строки в файле:
$(head -3 $f)"
ok "пользователей: $(wc -l < $f)"
```

```text hint
Поля в /etc/passwd разделены двоеточием. Имя — первое поле, оболочка — седьмое. Нужна команда, которой можно задать разделитель полей и напечатать два поля через пробел.
```

```bash solution
awk -F: '{print $1, $7}' /etc/passwd > ~/shells.txt
```

```text review
Эталон: `awk -F: '{print $1, $7}' /etc/passwd`.

- `-F:` — разделитель полей. Запятая в `print $1, $7` вставляет разделитель вывода (по умолчанию пробел); `print $1 $7` склеил бы поля без пробела.
- `cut -d: -f1,7 /etc/passwd | tr : ' '` тоже работает: cut умеет только вырезать поля, а awk — ещё и фильтровать и считать (`awk -F: '$7 ~ /bash/ {print $1}'`).
- В скриптах лучше `getent passwd` — учитывает и сетевых пользователей.
```

### Объём трафика

Посчитайте **суммарный объём ответов в байтах** по логу (поле после кода ответа). Запишите одно число в `~/bytes.txt`.

```bash check
[ -f /home/student/bytes.txt ] || fail "Нет ~/bytes.txt"
want=$(awk '{s += $10} END {print s}' /home/student/logs/access.log)
got=$(tr -d '[:space:]' < /home/student/bytes.txt)
[ "$got" = "$want" ] || fail "В файле «$got», а сумма поля с размером ответа другая"
ok "всего байт: $want"
```

```text hint
Пройти по всем строкам, накапливая в переменной значение поля с размером ответа, и в самом конце напечатать сумму. У awk есть блок, который выполняется после всех строк.
```

```bash solution
awk '{s += $10} END {print s}' ~/logs/access.log > ~/bytes.txt
```

```text review
Эталон: `awk '{s += $10} END {print s}' access.log`.

- Блок `END` выполняется после последней строки — здесь печатают итоги. Переменные awk не нужно объявлять: пустая переменная в арифметике — 0.
- Тот же приём даёт любую статистику по логу: `awk '{s += $10; n++} END {print s / n}'` — средний размер ответа.
- В nginx combined поле с размером — `$body_bytes_sent`; для `-` (нет тела) awk посчитает 0.
```

## Тест

### Как вывести строки файла app.log, которые НЕ содержат слово DEBUG?
= grep -v DEBUG app.log
= grep -v "DEBUG" app.log
> `-v` инвертирует условие.

### Какая опция grep делает поиск нечувствительным к регистру?
- [ ] -r
- [x] -i
- [ ] -v
- [ ] -c
> `-r` — рекурсивно, `-v` — инверсия, `-c` — счётчик.

### Как вывести первую колонку (IP-адрес) из каждой строки access.log?
- [ ] cut access.log 1
- [x] awk '{print $1}' access.log
- [ ] sed 's/1//' access.log
- [ ] grep $1 access.log
> По умолчанию awk делит строку по пробелам и табам.

### Почему перед uniq почти всегда ставят sort?
- [ ] uniq работает только с числами
- [x] uniq убирает только соседние одинаковые строки, поэтому дубликаты нужно сначала собрать рядом
- [ ] sort ускоряет uniq
- [ ] Без sort uniq выдаёт ошибку
> `sort | uniq -c | sort -rn` — классическая цепочка «посчитать и отсортировать по частоте».

### Как заменить 8080 на 9090 во всём файле config прямо на месте?
- [ ] sed 's/8080/9090/' config
- [x] sed -i 's/8080/9090/g' config
- [ ] grep -r 8080 9090 config
- [ ] awk 's/8080/9090/g' config
> Без `-i` sed только выводит результат на экран, без `g` заменяет лишь первое вхождение в строке.

### Как посчитать количество строк в файле?
= wc -l file
= wc -l < file
> `-w` — слова, `-c` — байты.

### Как получить список имён пользователей из /etc/passwd?
- [x] cut -d: -f1 /etc/passwd
- [x] awk -F: '{print $1}' /etc/passwd
- [ ] sort /etc/passwd
- [ ] grep -f1 /etc/passwd
> Оба способа берут первое поле с разделителем «:».

### Что выведет команда sort -n для строк 10, 9, 100?
- [ ] 10, 100, 9
- [x] 9, 10, 100
- [ ] 100, 10, 9
- [ ] 9, 100, 10
> Без `-n` строки сортируются как текст, и порядок будет 10, 100, 9.

### Зачем нужен xargs?
- [ ] Чтобы сортировать строки
- [x] Чтобы превратить строки из stdin в аргументы команды, которая не читает stdin (rm, kill, chmod)
- [ ] Чтобы перенаправить ошибки
- [ ] Чтобы запускать команды в фоне
> `find ... -print0 | xargs -0 ...` безопасно обрабатывает имена с пробелами.

### Что делает grep -A 3 Exception app.log?
- [ ] Ищет 3 первых совпадения
- [x] Выводит каждое совпадение и 3 строки после него
- [ ] Выводит 3 строки до совпадения
- [ ] Ищет во всех файлах на 3 уровня вглубь
> Удобно, чтобы увидеть стектрейс после строки с исключением. `-B` — строки до, `-C` — вокруг.

### Как в awk вывести последнее поле строки, не зная, сколько в ней полей?
- [ ] $0
- [ ] $LAST
- [x] $NF
- [ ] $-1
> NF — число полей в строке, значит `$NF` — последнее поле. `$0` — вся строка.

### Какая цепочка выведет 10 IP-адресов с наибольшим числом запросов?
- [x] awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
- [ ] sort access.log | head -10
- [ ] uniq -c access.log | head -10
- [ ] awk '{print $1}' access.log | head -10 | sort
> Выделить поле → сгруппировать сортировкой → посчитать → отсортировать по числу → взять верх.

### Как вывести строки с 10-й по 20-ю?
- [x] sed -n '10,20p' file
- [x] head -n 20 file | tail -n 11
- [ ] grep 10-20 file
- [ ] cut -l 10-20 file
> `-n` отключает вывод всех строк, а `p` печатает только выбранный диапазон.
