# Терминал и базовые команды

**Терминал** — окно, в котором вы печатаете команды. **Оболочка** (shell) — программа внутри него, которая читает команды и запускает их. В большинстве дистрибутивов это **bash**; на macOS и у многих разработчиков — zsh. Команды из этой темы одинаково работают везде.

## Приглашение и устройство команды

```
user@server:~/projects$ ls -la /etc
```

- `user@server:~/projects$` — **приглашение**: кто вы, на какой машине и в каком каталоге. `$` — обычный пользователь, `#` — root.
- `ls` — команда, `-la` — **опции** (флаги), `/etc` — **аргумент**.
- Короткие опции можно склеивать: `ls -l -a` = `ls -la`. Длинные пишутся через два дефиса: `ls --all`.

## Пути

- **Абсолютный** путь начинается с `/` — от корня: `/var/log/nginx/access.log`.
- **Относительный** — от текущего каталога: `logs/app.log`.
- `~` — домашний каталог (`/home/user`), `.` — текущий каталог, `..` — родительский.
- Имена в Linux **чувствительны к регистру**: `File.txt` и `file.txt` — разные файлы.
- Имя с пробелами берут в кавычки: `cd "My Documents"`.

## Навигация

```bash
pwd                 # где я? (print working directory)
cd /etc             # перейти по абсолютному пути
cd ..               # на уровень выше
cd ~  или просто cd # домой
cd -                # в предыдущий каталог
ls                  # содержимое каталога
ls -l               # подробно: права, владелец, размер, дата
ls -la              # плюс скрытые файлы (имя начинается с точки)
ls -lh              # размеры в удобном виде: K, M, G
ls -lt              # сортировка по времени изменения
```

## Файлы и каталоги

```bash
mkdir backup                 # создать каталог
mkdir -p app/config/dev      # создать вместе с родительскими
touch notes.txt              # создать пустой файл (или обновить время изменения)
cp file.txt copy.txt         # копировать файл
cp -r src/ src-backup/       # копировать каталог рекурсивно
mv old.txt new.txt           # переименовать
mv file.txt /tmp/            # переместить
rm file.txt                  # удалить файл
rm -r dir/                   # удалить каталог с содержимым
rmdir empty-dir              # удалить только пустой каталог
```

> [!warning] rm -rf
> `rm` удаляет **без корзины** и без вопросов. `-r` — рекурсивно, `-f` — без подтверждений и без ошибок на отсутствующие файлы. Перед `rm -rf` всегда проверяйте путь через `ls`. Особенно опасны пути из переменных: если переменная окажется пустой, `rm -rf "$DIR/"` превратится в `rm -rf /`.

Шаблоны (wildcards) раскрывает оболочка: `*` — любые символы, `?` — один символ.

```bash
ls *.log          # все файлы .log
rm report-202?.txt
```

## Просмотр файлов

```bash
cat file.txt         # вывести целиком (для коротких файлов)
less /var/log/syslog # постранично: пробел — вперёд, / — поиск, n — следующее совпадение, q — выход
head -n 20 file      # первые 20 строк
tail -n 50 file      # последние 50 строк
tail -f app.log      # следить за файлом в реальном времени (Ctrl+C — выход)
```

## Справка

- `man ls` — подробное руководство (управление как в `less`, выход — `q`). `man -k слово` — поиск по описаниям.
- `ls --help` — краткая справка.
- `tldr ls` — короткие примеры (отдельная утилита, ставится пакетом).

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| Tab | Дополнить команду или путь; двойной Tab — варианты |
| ↑ / ↓ | История команд |
| Ctrl+R | Поиск по истории |
| Ctrl+C | Прервать выполняющуюся команду |
| Ctrl+L | Очистить экран (как `clear`) |
| Ctrl+A / Ctrl+E | В начало / конец строки |
| Ctrl+D | Выйти из оболочки (конец ввода) |

`history` покажет историю, `!!` повторит последнюю команду — например, `sudo !!`, если забыли sudo.

## Практика

## Лаборатория

### Структура проекта

Создайте в домашнем каталоге структуру:

```
~/practice/
├── logs/
├── config/
└── scripts/
```

Постарайтесь уложиться в **одну** команду.

```bash setup
rm -rf /home/student/practice
```

```bash check
for d in logs config scripts; do
  [ -d /home/student/practice/$d ] || fail "Нет каталога ~/practice/$d"
done
[ "$(stat -c %U /home/student/practice)" = student ] || fail "~/practice принадлежит $(stat -c %U /home/student/practice), а не student"
ok "$(cd /home/student && find practice -type d | sort | tr '\n' ' ')"
```

```text hint
Создать каталог practice и сразу три подкаталога внутри.
У команды создания каталогов есть ключ «создавать родителей по пути и не ругаться, если уже есть», а оболочка умеет раскрывать перечисление в фигурных скобках.
```

```bash solution
mkdir -p ~/practice/{logs,config,scripts}
```

```text review
Эталон: `mkdir -p ~/practice/{logs,config,scripts}`.

- `{logs,config,scripts}` раскрывает сама оболочка ещё до запуска mkdir: команда получает три пути. Посмотреть, во что раскроется выражение, можно через `echo ~/practice/{logs,config,scripts}`.
- `-p` создаёт недостающих родителей и не выдаёт ошибку, если каталог уже есть, — поэтому `mkdir -p` безопасно повторять в скриптах.
- Четыре отдельных `mkdir` тоже решают задачу, но в скриптах и Ansible ценится идемпотентность: команду можно запустить второй раз без ошибки.
```

```text notes
sudo\s+mkdir => В своём домашнем каталоге sudo не нужен — с ним каталоги станут принадлежать root, и потом вы не сможете в них писать.
```

### Разобрать входящие

В `~/inbox` лежат два файла. Нужно:

1. **скопировать** `~/inbox/report.txt` в `~/practice/logs/` под именем `report-2026.txt`;
2. **переместить** `~/inbox/draft.txt` в `~/practice/config/` под именем `app.conf`;
3. удалить каталог `~/inbox` целиком.

```bash setup
rm -rf /home/student/inbox /home/student/practice
mkdir -p /home/student/inbox /home/student/practice/{logs,config,scripts}
echo "Отчёт за 2026 год: всё работает" > /home/student/inbox/report.txt
echo "listen=8080" > /home/student/inbox/draft.txt
chown -R student:student /home/student/inbox /home/student/practice
```

```bash check
h=/home/student
[ -f $h/practice/logs/report-2026.txt ] || fail "Нет ~/practice/logs/report-2026.txt"
grep -q "Отчёт за 2026" $h/practice/logs/report-2026.txt || fail "В report-2026.txt не то содержимое"
[ -f $h/practice/config/app.conf ] || fail "Нет ~/practice/config/app.conf"
grep -q "listen=8080" $h/practice/config/app.conf || fail "В app.conf не то содержимое"
[ -e $h/inbox ] && fail "Каталог ~/inbox ещё существует"
ok "файлы на месте, ~/inbox удалён"
```

```text hint
1. Копирование: откуда → куда, причём «куда» может сразу содержать новое имя файла.
2. Перемещение делается той же командой, что и переименование.
3. Удалить каталог вместе с содержимым — команда удаления с ключом рекурсии.
```

```bash solution
cp ~/inbox/report.txt ~/practice/logs/report-2026.txt
mv ~/inbox/draft.txt ~/practice/config/app.conf
rm -r ~/inbox
```

```text review
Эталон: `cp`, `mv`, `rm -r`.

- `mv` — это и перемещение, и переименование: для файловой системы это одна операция (в пределах одного диска файл никуда не копируется, меняется только запись в каталоге).
- `rm -r` удаляет без корзины. Привычка перед `rm -r` выполнить `ls` по тому же пути спасает от удаления не того каталога. `rm -rf` с переменной в пути (`rm -rf $DIR/`) — классическая катастрофа, если переменная пустая.
- `cp -i` и `mv -i` спрашивают перед перезаписью существующего файла.
```

```text notes
rm\s+-[a-z]*f[a-z]*\s+(/|~)\s*$ => Команда вида rm -rf / или rm -rf ~ уничтожает всё. Всегда указывайте точный путь к тому, что удаляете.
```

### Скрытый файл

В каталоге `~/quest` спрятан скрытый файл с кодом. Найдите его и запишите код (только сам код, одной строкой) в `~/found.txt`.

```bash setup
rm -rf /home/student/quest /home/student/found.txt
mkdir -p /home/student/quest/docs
code="LX-$(shuf -i 1000-9999 -n 1)"
echo "$code" > "/home/student/quest/.secret-$(shuf -i 10-99 -n 1)"
echo "$code" > /var/lib/lab/quest-code
echo "Здесь кода нет" > /home/student/quest/readme.txt
echo "И здесь тоже" > /home/student/quest/docs/notes.txt
chown -R student:student /home/student/quest
```

```bash check
[ -f /home/student/found.txt ] || fail "Нет файла ~/found.txt"
want=$(cat /var/lib/lab/quest-code)
got=$(tr -d '[:space:]' < /home/student/found.txt)
[ "$got" = "$want" ] || fail "В ~/found.txt «$got» — это не тот код"
ok "код $want найден"
```

```text hint
Скрытые файлы в Linux — те, чьё имя начинается с точки; обычный список каталога их не показывает. У команды просмотра каталога есть ключ «показать все». Потом выведите содержимое файла и перенаправьте его в ~/found.txt.
```

```bash solution
cat ~/quest/.secret-* > ~/found.txt
```

```text review
Эталон: `ls -la ~/quest`, затем `cat ~/quest/.secret-* > ~/found.txt`.

- Файлы с точкой в начале имени скрыты только «по договорённости»: `ls` и `*` их пропускают, но это обычные файлы. Так хранят настройки: `.bashrc`, `.ssh`, `.gitignore`.
- `ls -a` показывает всё, `ls -A` — всё, кроме `.` и `..`.
- Шаблон `.secret-*` подставляет имя за вас — не нужно перепечатывать случайные цифры.
```

### Сколько строк

Сколько строк в файле `/etc/services`? Запишите одно число в `~/answer.txt`.

```bash setup
rm -f /home/student/answer.txt
```

```bash check
[ -f /home/student/answer.txt ] || fail "Нет файла ~/answer.txt"
want=$(wc -l < /etc/services)
got=$(tr -d '[:space:]' < /home/student/answer.txt)
[ "$got" = "$want" ] || fail "В ~/answer.txt «$got» — это не число строк /etc/services"
ok "в /etc/services $want строк"
```

```text hint
Есть команда подсчёта строк, слов и байт; нужен её ключ «только строки». Обратите внимание: если передать ей имя файла, она напечатает и имя. Если подать файл на вход перенаправлением — только число.
```

```bash solution
wc -l < /etc/services > ~/answer.txt
```

```text review
Эталон: `wc -l < /etc/services > ~/answer.txt`.

- `wc -l /etc/services` печатает «число имя_файла», а `wc -l < /etc/services` — только число: файл приходит на стандартный ввод, и имени wc не знает. Это частый приём в скриптах, когда нужно число без `awk` и `cut`.
- Альтернатива: `wc -l /etc/services | cut -d' ' -f1` — длиннее и ломается, если перед числом есть пробелы.
- `grep -c ''` тоже считает строки, но `wc -l` понятнее читателю.
```

## Тест

### Какая команда показывает текущий каталог?
= pwd
> print working directory.

### Что выведет ls -la по сравнению с обычным ls?
- [ ] Только каталоги
- [x] Подробный список (права, владелец, размер, дата), включая скрытые файлы
- [ ] Файлы, отсортированные по размеру
- [ ] Только скрытые файлы
> `-l` — подробный формат, `-a` — все файлы, включая начинающиеся с точки.

### Какой путь абсолютный?
- [ ] logs/app.log
- [ ] ../config
- [x] /var/log/app.log
- [ ] ./run.sh
> Абсолютный путь всегда начинается от корня `/`.

### Куда переведёт команда cd без аргументов?
- [ ] В корень /
- [x] В домашний каталог пользователя
- [ ] В предыдущий каталог
- [ ] Никуда, выдаст ошибку
> То же самое, что `cd ~`. В предыдущий каталог переводит `cd -`.

### Как создать каталог app/config/dev, если каталогов app и config ещё нет?
- [ ] mkdir app/config/dev
- [x] mkdir -p app/config/dev
- [ ] touch app/config/dev
- [ ] mkdir -r app/config/dev
> `-p` создаёт недостающие родительские каталоги и не ругается, если каталог уже есть.

### Как переименовать файл old.txt в new.txt?
- [ ] rename old.txt new.txt
- [ ] cp old.txt new.txt
- [x] mv old.txt new.txt
- [ ] rn old.txt new.txt
> В Linux переименование — это перемещение файла под новым именем.

### Чем опасна команда rm -rf?
- [x] Удаляет рекурсивно, без подтверждения и без корзины
- [x] Если путь собран из пустой переменной, можно удалить совсем не то
- [ ] Она удаляет файлы только после перезагрузки
- [ ] Она требует пароль root
> Проверяйте путь перед удалением, а в скриптах используйте `set -u` и проверки переменных.

### Как скопировать каталог src со всем содержимым в src-backup?
- [ ] cp src src-backup
- [x] cp -r src src-backup
- [ ] mv -r src src-backup
- [ ] copy src src-backup
> Без `-r` cp откажется копировать каталог.

### Как следить за новыми строками в логе app.log в реальном времени?
= tail -f app.log
= tail -F app.log
> `-F` дополнительно переоткрывает файл, если его заменили при ротации логов.

### Как найти слово в файле, открытом в less?
- [ ] Ctrl+F
- [x] Нажать / , ввести слово и Enter; n — следующее совпадение
- [ ] :find слово
- [ ] Только через grep
> Тот же поиск работает в `man`, потому что он показывает страницы через `less`.

### Что означает символ # в конце приглашения командной строки вместо $?
- [ ] Включён режим комментариев
- [x] Вы работаете от имени root
- [ ] Предыдущая команда завершилась с ошибкой
- [ ] Терминал подключён по SSH
> Работая под root, будьте особенно внимательны: система не остановит опасную команду.

### Какая комбинация клавиш прерывает выполняющуюся команду?
- [ ] Ctrl+Z
- [x] Ctrl+C
- [ ] Ctrl+D
- [ ] Ctrl+X
> Ctrl+Z не прерывает, а приостанавливает процесс — об этом в теме про процессы.

### Как получить подробное руководство по команде cp?
= man cp
> Краткую справку даёт `cp --help`.
