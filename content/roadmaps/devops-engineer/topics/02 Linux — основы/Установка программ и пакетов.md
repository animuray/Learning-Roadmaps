# Установка программ и пакетов

В Linux программы обычно не скачивают с сайтов вручную, а ставят **из репозиториев** через менеджер пакетов. Он сам скачает нужные **зависимости** (библиотеки), проверит подписи, разложит файлы по местам и потом обновит всё одной командой.

## Пакеты и репозитории

- **Пакет** — архив с программой, метаданными (версия, зависимости) и скриптами установки: `.deb` в семействе Debian, `.rpm` в семействе Red Hat.
- **Репозиторий** — сервер с пакетами и подписанным индексом.
- Низкоуровневые утилиты (`dpkg`, `rpm`) ставят один файл пакета и не умеют скачивать зависимости. Высокоуровневые (`apt`, `dnf`) работают с репозиториями и сами разрешают зависимости.

## apt (Debian, Ubuntu)

```bash
sudo apt update                 # обновить списки пакетов из репозиториев (ничего не ставит!)
sudo apt install nginx git      # установить
sudo apt install -y htop        # без вопроса «Продолжить?» — для скриптов
sudo apt upgrade                # обновить установленные пакеты
sudo apt full-upgrade           # обновить, разрешая удаление и замену пакетов
sudo apt remove nginx           # удалить, оставив конфиги
sudo apt purge nginx            # удалить вместе с конфигами
sudo apt autoremove             # удалить ненужные больше зависимости
apt search postgres             # поиск
apt show nginx                  # описание, версия, зависимости
apt list --installed
dpkg -l | grep nginx            # установлен ли пакет
dpkg -L nginx                   # какие файлы поставил пакет
dpkg -S /usr/sbin/nginx         # какому пакету принадлежит файл
sudo dpkg -i package.deb        # поставить скачанный .deb (зависимости потом: apt -f install)
```

Репозитории описаны в `/etc/apt/sources.list` и `/etc/apt/sources.list.d/`. Сторонние репозитории (Docker, PostgreSQL, Grafana) добавляют вместе с их **GPG-ключом**: APT проверяет подпись и не поставит подменённый пакет.

## dnf (Fedora, RHEL, Rocky, AlmaLinux)

```bash
sudo dnf install nginx
sudo dnf upgrade                # обновить всё (dnf update — то же самое)
sudo dnf remove nginx
dnf search postgres
dnf info nginx
dnf provides /usr/sbin/nginx    # какой пакет даёт файл
rpm -qa | grep nginx            # установленные пакеты
rpm -ql nginx                   # файлы пакета
```

Репозитории — файлы `.repo` в `/etc/yum.repos.d/`. Важный дополнительный репозиторий для RHEL-совместимых систем — **EPEL**.

## Другие способы установки

- **snap** и **flatpak** — пакеты со всеми зависимостями внутри, изолированные от системы. Удобны на десктопе.
- **Бинарник** с сайта или GitHub Releases — положить в `/usr/local/bin` и выставить права `755`.
- **Сборка из исходников** — `./configure && make && sudo make install`. На серверах так делают редко: такие программы не обновляются менеджером пакетов.

## Менеджеры пакетов языков

Приложения ставят свои библиотеки не через apt, а через менеджер пакетов своего языка. Это пригодится в главной практике по Linux, когда вы будете запускать приложение без Docker.

### Python: pip и venv

```bash
sudo apt install python3-venv python3-pip
python3 -m venv .venv           # создать виртуальное окружение в каталоге проекта
source .venv/bin/activate       # активировать (в приглашении появится (.venv))
pip install -r requirements.txt # поставить зависимости проекта
pip install flask==3.0.3        # конкретная версия
pip freeze > requirements.txt   # зафиксировать версии
deactivate
```

- **venv** изолирует библиотеки проекта: у двух приложений могут быть разные версии одной библиотеки, и они не мешают друг другу и системному Python.
- В современных Debian и Ubuntu `pip install` в системный Python запрещён ошибкой `externally-managed-environment`. Это защита системных пакетов — используйте venv.
- Каталог `.venv` не коммитят в Git.

### Node.js: npm

```bash
npm install          # поставить зависимости из package.json в node_modules/
npm ci               # чистая установка строго по package-lock.json — для CI и серверов
npm run build        # выполнить скрипт из раздела scripts в package.json
npm start
```

`package.json` описывает зависимости, `package-lock.json` фиксирует точные версии. Каталог `node_modules` не коммитят.

### Java: Maven

```bash
sudo apt install openjdk-21-jdk maven
mvn package          # скомпилировать, прогнать тесты и собрать target/app-1.0.jar
mvn clean package -DskipTests
java -jar target/app-1.0.jar
```

Проект описывается в `pom.xml`. Зависимости скачиваются в локальный кэш `~/.m2/repository`.

> [!tip] Версии языков
> Если нужна версия Python или Node.js, которой нет в репозитории дистрибутива, используют менеджеры версий: `pyenv`, `nvm` — или официальные репозитории проекта.

## Практика

- [ ] Обновить систему: `sudo apt update && sudo apt upgrade`
- [ ] Установить nginx, найти через `dpkg -L` его конфиги и бинарник, затем удалить через `purge`
- [ ] Подключить официальный репозиторий Docker по инструкции с docs.docker.com и разобраться, где лежат ключ и запись о репозитории
- [ ] Создать venv, поставить flask, сохранить `requirements.txt`, удалить venv и восстановить окружение из файла
- [ ] Собрать простой проект на Node.js (`npm ci`, `npm run build`) и на Java (`mvn package`)

## Тест

### Что делает команда apt update?
- [ ] Обновляет все установленные пакеты
- [x] Обновляет списки доступных пакетов из репозиториев, ничего не устанавливая
- [ ] Обновляет ядро
- [ ] Удаляет старые пакеты
> Обновляет пакеты `apt upgrade`. Перед установкой на свежем сервере всегда сначала `apt update`.

### Чем apt purge отличается от apt remove?
- [ ] Ничем
- [x] purge удаляет пакет вместе с его конфигурационными файлами, remove оставляет конфиги
- [ ] remove удаляет и зависимости
- [ ] purge только помечает пакет на удаление
> Ненужные больше зависимости удаляет `apt autoremove`.

### Почему dpkg -i package.deb может завершиться ошибкой, а apt install — нет?
- [ ] dpkg работает только с rpm
- [x] dpkg ставит один файл и не скачивает зависимости; apt сам разрешает и ставит зависимости из репозиториев
- [ ] dpkg требует интернета
- [ ] apt не проверяет подписи
> Недостающие зависимости после dpkg можно доставить через `apt -f install`.

### Каким менеджером пакетов ставят программы в Rocky Linux?
= dnf
= yum
> yum — старое имя; в современных версиях это ссылка на dnf.

### Как узнать, какому пакету принадлежит файл /usr/sbin/nginx в Ubuntu?
- [ ] apt show /usr/sbin/nginx
- [x] dpkg -S /usr/sbin/nginx
- [ ] which -p nginx
- [ ] dpkg -L /usr/sbin/nginx
> `dpkg -L пакет` — наоборот, список файлов пакета. В RHEL-семействе — `rpm -qf` или `dnf provides`.

### Зачем при подключении стороннего репозитория добавляют его GPG-ключ?
- [ ] Чтобы ускорить скачивание
- [x] Чтобы менеджер пакетов мог проверить подпись и не установить подменённый пакет
- [ ] Для шифрования трафика
- [ ] Чтобы обойти лицензию
> Без доверенного ключа apt откажется работать с репозиторием.

### Зачем в Python использовать виртуальное окружение venv?
- [ ] Чтобы Python работал быстрее
- [x] Чтобы изолировать зависимости проекта от системного Python и других проектов
- [ ] Чтобы запускать Python без интерпретатора
- [ ] Это обязательное требование pip для любых пакетов
> У разных приложений могут быть несовместимые версии одной и той же библиотеки.

### Ubuntu на pip install requests отвечает ошибкой externally-managed-environment. Что правильно сделать?
- [ ] Удалить системный Python
- [x] Создать виртуальное окружение (python3 -m venv .venv), активировать его и ставить пакеты туда
- [ ] Выполнить pip install от root
- [ ] Удалить файл /etc/apt/sources.list
> Ошибка защищает системные пакеты, на которых работает сам дистрибутив.

### Как сохранить точные версии установленных Python-пакетов в файл?
= pip freeze > requirements.txt
> Восстановить окружение: `pip install -r requirements.txt`.

### Чем npm ci отличается от npm install?
- [ ] npm ci устанавливает пакеты глобально
- [x] npm ci делает чистую установку строго по package-lock.json, не меняя его, — подходит для CI и серверов
- [ ] npm ci только проверяет зависимости
- [ ] Ничем
> Так на каждой сборке получается одинаковый набор версий.

### Какая команда Maven собирает Java-проект в jar-файл?
- [ ] mvn run
- [x] mvn package
- [ ] mvn build-jar
- [ ] mvn install-jar
> Результат появляется в каталоге `target/`.

### Какие каталоги с зависимостями обычно не коммитят в Git?
- [x] .venv
- [x] node_modules
- [ ] src
- [ ] Файлы requirements.txt и package-lock.json
> Коммитят описание зависимостей (`requirements.txt`, `package-lock.json`, `pom.xml`), а не сами библиотеки.

### Куда принято класть вручную скачанный бинарник, чтобы он запускался по имени у всех пользователей?
- [ ] /tmp
- [ ] /etc
- [x] /usr/local/bin
- [ ] /var/log
> `/usr/local` — для программ, установленных не менеджером пакетов. Этот каталог уже есть в PATH.
