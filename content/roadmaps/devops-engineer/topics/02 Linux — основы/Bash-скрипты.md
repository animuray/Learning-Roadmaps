# Bash-скрипты

Скрипт — текстовый файл с командами, которые вы иначе набирали бы руками. DevOps-инженер пишет скрипты для бэкапов, деплоя, проверок и обслуживания, а шаги CI/CD-пайплайнов — по сути тоже bash. Сложную логику лучше писать на Python, но читать и писать bash нужно уверенно.

## Первый скрипт

```bash
#!/usr/bin/env bash
# backup.sh — архивирует каталог
set -euo pipefail

SRC="${1:-/etc}"
DEST="/backup/etc-$(date +%F).tar.gz"

tar czf "$DEST" "$SRC"
echo "Готово: $DEST"
```

- Первая строка — **shebang**: какой интерпретатор запустит файл. `#!/usr/bin/env bash` находит bash через PATH, `#!/bin/bash` — указывает путь явно.
- Запуск:
  ```bash
  chmod +x backup.sh
  ./backup.sh /var/www      # нужен shebang и право x
  bash backup.sh /var/www   # право x не нужно
  ```

## Переменные и кавычки

```bash
name="Alice"            # без пробелов вокруг =
echo "Привет, $name"    # в двойных кавычках переменные подставляются
echo 'Привет, $name'    # в одинарных — нет, текст как есть
files=$(ls /etc | wc -l)
echo "${name}_backup"   # фигурные скобки отделяют имя от текста
echo "${PORT:-8080}"    # значение по умолчанию, если PORT пуст или не задан
```

> [!important] Всегда берите переменные в двойные кавычки
> `rm $file` с именем `my file.txt` превратится в `rm my file.txt` — две разные цели. Правильно: `rm "$file"`.

## Аргументы скрипта

| Переменная | Значение |
| --- | --- |
| `$0` | Имя скрипта |
| `$1`, `$2`, … | Позиционные аргументы |
| `$#` | Количество аргументов |
| `"$@"` | Все аргументы, каждый отдельным словом (почти всегда нужен именно он) |
| `$?` | Код возврата последней команды |
| `$$` | PID текущей оболочки |

```bash
if [[ $# -lt 1 ]]; then
  echo "Использование: $0 <каталог>" >&2   # сообщения об ошибках — в stderr
  exit 1
fi
read -rp "Продолжить? [y/N] " answer      # прочитать ввод пользователя
```

## Условия

```bash
if [[ -f /etc/nginx/nginx.conf ]]; then
  echo "nginx установлен"
elif [[ -d /etc/apache2 ]]; then
  echo "apache"
else
  echo "веб-сервера нет"
fi
```

| Проверка | Смысл |
| --- | --- |
| `-f файл` / `-d каталог` / `-e путь` | Существует файл / каталог / что угодно |
| `-r` / `-w` / `-x` | Можно читать / писать / исполнять |
| `-z "$s"` / `-n "$s"` | Строка пустая / непустая |
| `"$a" == "$b"`, `!=` | Сравнение строк |
| `-eq -ne -lt -le -gt -ge` | Сравнение чисел |
| `&&`, `\|\|`, `!` | И, или, не |

`if` проверяет **код возврата** команды, поэтому можно писать проверки прямо командами:

```bash
if grep -q "error" app.log; then echo "Есть ошибки"; fi
if ! systemctl is-active --quiet nginx; then systemctl restart nginx; fi
```

Арифметика: `count=$((count + 1))`, `(( used > 90 ))`.

Выбор из вариантов — `case`:

```bash
case "$1" in
  start)   systemctl start app ;;
  stop)    systemctl stop app ;;
  *)       echo "start|stop"; exit 1 ;;
esac
```

## Циклы

```bash
for host in web1 web2 db1; do
  ssh "$host" uptime
done

for f in /var/log/*.log; do
  echo "$f: $(wc -l < "$f") строк"
done

for i in {1..5}; do echo "$i"; done

# Чтение файла построчно
while read -r line; do
  echo "Хост: $line"
done < hosts.txt

# Ждать, пока сервис не поднимется
until curl -sf http://localhost:8080/health; do sleep 2; done
```

## Функции

```bash
log() {
  echo "[$(date '+%F %T')] $*"
}

check_disk() {
  local mount="$1"      # local — переменная видна только внутри функции
  local used
  used=$(df --output=pcent "$mount" | tail -1 | tr -dc '0-9')
  if (( used > 90 )); then
    log "Диск $mount заполнен на $used%"
    return 1            # функция возвращает код возврата, а не значение
  fi
}

check_disk / || exit 1
```

## Коды возврата и безопасный режим

- `exit 0` — успех, `exit 1` (или другое ненулевое значение) — ошибка. CI/CD, cron и systemd смотрят именно на код возврата.
- Строгий режим в начале скрипта:
  ```bash
  set -euo pipefail
  ```
  - `-e` — завершить скрипт при ошибке любой команды;
  - `-u` — ошибка при использовании неинициализированной переменной (спасает от `rm -rf "$DIR/"` с пустым `DIR`);
  - `-o pipefail` — ошибка в любой команде пайпа считается ошибкой всего пайпа.
- `trap 'rm -f "$TMP"' EXIT` — выполнить уборку при выходе из скрипта (подробнее — в теме «Сигналы»).

## Отладка и проверка

```bash
bash -x script.sh       # печатает каждую команду перед выполнением
bash -n script.sh       # проверить синтаксис без запуска
shellcheck script.sh    # линтер: находит забытые кавычки и типичные ошибки
```

## Тест

### Зачем нужна первая строка #!/usr/bin/env bash?
- [ ] Это комментарий для читателя
- [x] Shebang указывает, каким интерпретатором выполнить файл при запуске ./script.sh
- [ ] Она включает строгий режим
- [ ] Она нужна только для запуска через bash script.sh
> При `bash script.sh` интерпретатор задан явно, и shebang не используется.

### Что нужно сделать, чтобы запускать скрипт как ./deploy.sh?
= chmod +x deploy.sh
= chmod u+x deploy.sh
> Плюс в файле должен быть shebang.

### Чем отличаются "$name" и '$name' в bash?
- [ ] Ничем
- [x] В двойных кавычках переменная подставляется, в одинарных остаётся как текст $name
- [ ] Одинарные кавычки быстрее
- [ ] Двойные кавычки запрещают пробелы
> Одинарные кавычки — для текста, который нельзя трогать: регулярных выражений, awk-программ.

### Что хранится в $#?
- [ ] Имя скрипта
- [x] Количество переданных аргументов
- [ ] Код возврата
- [ ] PID процесса
> `$0` — имя скрипта, `$?` — код возврата, `$$` — PID.

### Как правильно передать все аргументы скрипта другой команде, сохранив аргументы с пробелами?
- [ ] $*
- [ ] $@
- [x] "$@"
- [ ] $#
> Без кавычек аргумент «my file» распадётся на два слова.

### Как проверить в bash, что файл /etc/app.conf существует?
- [ ] if [[ -d /etc/app.conf ]]
- [x] if [[ -f /etc/app.conf ]]
- [ ] if [[ -z /etc/app.conf ]]
- [ ] if exists /etc/app.conf
> `-d` проверяет каталог, `-z` — пустую строку.

### Как сравнить числа в [[ ]]: «переменная count больше 10»?
- [ ] [[ $count > 10 ]]
- [x] [[ $count -gt 10 ]]
- [ ] [[ $count => 10 ]]
- [ ] [[ count -more 10 ]]
> Внутри `[[ ]]` знак `>` сравнивает строки по алфавиту. Для чисел — `-gt` или `(( count > 10 ))`.

### Что делает set -e?
- [ ] Включает подробный вывод
- [x] Завершает скрипт, если какая-либо команда вернула ошибку
- [ ] Запрещает использование переменных
- [ ] Экспортирует все переменные
> Обычно используют вместе: `set -euo pipefail`.

### Зачем в скриптах нужен set -u?
- [ ] Чтобы запускать скрипт только от пользователя
- [x] Чтобы использование неинициализированной переменной вызывало ошибку, а не подставляло пустую строку
- [ ] Чтобы включить Unicode
- [ ] Чтобы обновлять пакеты
> Защищает от катастроф вроде `rm -rf "$DIR/"`, когда DIR пустая.

### Что вернёт функция в bash командой return 1?
- [ ] Строку «1»
- [x] Код возврата 1, который можно проверить через $? или if
- [ ] Значение 1 в переменную result
- [ ] Ничего, return в bash не работает
> Чтобы «вернуть» данные, функция печатает их, а вызывающий код забирает вывод через `$(func)`.

### Как прочитать файл hosts.txt построчно?
- [x] while read -r line; do ...; done < hosts.txt
- [ ] for line in hosts.txt; do ...; done
- [ ] read hosts.txt
- [ ] cat hosts.txt | for line
> `for line in hosts.txt` переберёт одно слово — само имя файла.

### Как посмотреть, какие команды выполняет скрипт, с подставленными значениями переменных?
= bash -x script.sh
> Внутри скрипта можно включить отладку на участке через `set -x` и выключить через `set +x`.

### Какой код возврата должен вернуть скрипт проверки, если он нашёл проблему, чтобы CI-пайплайн упал?
- [ ] 0
- [x] Любой ненулевой, например 1
- [ ] Строку «error»
- [ ] Код не важен, CI смотрит на вывод
> CI/CD, cron и systemd ориентируются на код возврата, а не на текст.

### Какой инструмент находит типичные ошибки в bash-скриптах, например забытые кавычки?
= shellcheck
> Подключите его в CI, чтобы ошибки ловились до выкатки.
