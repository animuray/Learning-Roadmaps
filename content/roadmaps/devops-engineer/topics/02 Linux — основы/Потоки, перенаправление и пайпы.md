# Потоки, перенаправление и пайпы

У каждого процесса есть три стандартных потока — **файловых дескриптора**:

| Номер | Имя | По умолчанию |
| --- | --- | --- |
| 0 | **stdin** — стандартный ввод | Клавиатура |
| 1 | **stdout** — стандартный вывод | Экран |
| 2 | **stderr** — поток ошибок | Экран |

Ошибки идут отдельным потоком, поэтому их можно отделить от полезного вывода. Без этого невозможно писать скрипты, однострочники и разбирать логи.

## Перенаправление вывода

```bash
ls -l > files.txt          # stdout в файл (файл перезаписывается!)
echo "line" >> log.txt     # дописать в конец файла
find / -name x 2> errors.txt   # stderr в файл
find / -name x 2>/dev/null     # выбросить ошибки
command > out.log 2>&1     # и stdout, и stderr в один файл
command &> out.log         # то же короче (только bash)
command > /dev/null 2>&1   # полностью «тихий» запуск, например в cron
```

`/dev/null` — «чёрная дыра»: всё, что туда записано, исчезает.

### Порядок важен

Перенаправления обрабатываются **слева направо**. `2>&1` значит «направь stderr туда же, куда **сейчас** указывает stdout».

```bash
cmd > file 2>&1   # stdout → file, затем stderr → туда же (file). Оба в файле
cmd 2>&1 > file   # stderr → экран (куда тогда указывал stdout), stdout → file
```

## Ввод из файла

```bash
wc -l < access.log        # stdin из файла
mysql db < dump.sql
```

**Here-document** — многострочный ввод прямо в скрипте, удобно для создания конфигов:

```bash
cat > /etc/app.conf <<EOF
port=8080
host=$HOSTNAME
EOF
```

С `<<'EOF'` (кавычки вокруг метки) переменные внутри **не** подставляются.

**Here-string:** `grep error <<< "$OUTPUT"`.

## Пайпы

`|` передаёт stdout одной команды на stdin следующей. Так из маленьких утилит собирают мощные цепочки:

```bash
ps aux | grep nginx
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
journalctl -u app | grep -i error | tail -20
```

- Через пайп идёт **только stdout**. Чтобы пустить и ошибки: `cmd 2>&1 | grep x` или в bash — `cmd |& grep x`.
- `tee` — «тройник»: пишет и в файл, и дальше на экран или в пайп:
  ```bash
  ./build.sh 2>&1 | tee build.log
  echo "127.0.0.1 app.local" | sudo tee -a /etc/hosts
  ```
  Почему не `sudo echo ... >> /etc/hosts`? Перенаправление выполняет **ваша** оболочка без root, и вы получите Permission denied. `sudo tee` открывает файл уже с правами root.

## Код возврата и цепочки команд

Каждая команда завершается с **кодом возврата**: `0` — успех, всё остальное — ошибка. Код последней команды хранится в `$?`.

```bash
ls /nope; echo $?          # 2
mkdir app && cd app        # cd выполнится, только если mkdir успешен
ping -c1 host || echo "недоступен"   # выполнить, если первая команда упала
cmd1; cmd2                 # просто по очереди, независимо от результата
```

У пайплайна код возврата по умолчанию берётся у **последней** команды. В скриптах включают `set -o pipefail`, чтобы ошибка в середине цепочки не терялась.

## Подстановка команды

```bash
echo "Сегодня $(date +%F)"
tar czf backup-$(date +%F).tar.gz /etc
kill $(pgrep -f old-app)
```

## Лаборатория

### Результаты отдельно, ошибки отдельно

Найдите от имени **обычного пользователя** (без sudo) все файлы с именем, оканчивающимся на `.conf`, во всей системе. Найденные пути сохраните в `~/found.txt`, а сообщения об ошибках — в `~/errors.txt`.

```bash setup
rm -f /home/student/found.txt /home/student/errors.txt
```

```bash check
h=/home/student
[ -s $h/found.txt ] || fail "~/found.txt пуст или не создан"
[ -s $h/errors.txt ] || fail "~/errors.txt пуст или не создан"
grep -q '^/etc/ld.so.conf$' $h/found.txt || fail "В ~/found.txt нет /etc/ld.so.conf — он точно существует"
grep -qi 'denied\|отказано' $h/found.txt && fail "В ~/found.txt попали сообщения об ошибках"
grep -qi 'denied\|отказано' $h/errors.txt || fail "В ~/errors.txt нет сообщений об ошибках доступа"
grep -q '^/' $h/errors.txt && fail "В ~/errors.txt попали найденные пути"
ok "найдено: $(wc -l < $h/found.txt), ошибок: $(wc -l < $h/errors.txt)"
```

```text hint
У каждой программы два выходных потока: обычный вывод (номер 1) и ошибки (номер 2). Каждый можно перенаправить в свой файл, указав номер потока перед знаком перенаправления.
```

```bash solution
find / -name "*.conf" > ~/found.txt 2> ~/errors.txt
```

```text review
Эталон: `find / -name "*.conf" > ~/found.txt 2> ~/errors.txt`.

- `>` — то же, что `1>`: стандартный вывод. `2>` — поток ошибок.
- `2>/dev/null` — выбросить ошибки, `&> file` — оба потока в один файл (то же, что `> file 2>&1`).
- Порядок важен: `cmd > f 2>&1` пишет оба потока в f, а `cmd 2>&1 > f` — ошибки на экран: `2>&1` копирует **текущее** назначение потока 1, а это ещё был терминал.
- Кавычки вокруг `"*.conf"` нужны: без них оболочка подставит `.conf`-файлы текущего каталога, и find получит совсем другое условие.
```

```text notes
sudo\s+find => Через sudo ошибок доступа нет совсем — а задача была как раз разделить два потока. Права root без нужды — плохая привычка.
-name\s+\*\.conf => Шаблон *.conf без кавычек раскроет оболочка, если в текущем каталоге есть .conf-файлы, и find получит не тот аргумент. Берите шаблоны find в кавычки.
```

### Конфиг через here-document

Создайте файл `~/app.env` ровно из двух строк, подставив значения переменных окружения (не печатайте их вручную):

```
APP_USER=<ваш пользователь из $USER>
APP_HOME=<ваш домашний каталог из $HOME>
```

```bash setup
rm -f /home/student/app.env
```

```bash check
f=/home/student/app.env
[ -f $f ] || fail "Нет ~/app.env"
want=$(printf 'APP_USER=student\nAPP_HOME=/home/student')
got=$(sed 's/[[:space:]]*$//' $f)
[ "$got" = "$want" ] || fail "Содержимое не совпало. Сейчас в файле:
$(cat $f)"
ok "$(tr '\n' ' ' < $f)"
```

```text hint
Многострочный текст можно подать команде прямо из оболочки «до метки конца». Если метку не брать в кавычки, переменные внутри текста подставятся. Результат перенаправьте в файл.
```

```bash solution
cat > ~/app.env <<EOF
APP_USER=$USER
APP_HOME=$HOME
EOF
```

```text review
Эталон: `cat > ~/app.env <<EOF ... EOF`.

- `<<EOF` — here-document: всё до строки `EOF` идёт команде на вход. Переменные и `$(команды)` внутри подставляются.
- `<<'EOF'` (метка в кавычках) — текст попадает **как есть**, без подстановок. Так пишут скрипты и конфиги, где `$` должен остаться в файле.
- `<<-EOF` разрешает отступы табуляцией внутри — удобно в функциях скриптов.
- Для записи в системный файл: `sudo tee /etc/app.conf > /dev/null <<EOF ... EOF`.
```

### Строка в системный файл

Добавьте в конец `/etc/hosts` строку:

```
10.0.0.5 db.local
```

Остальное содержимое файла должно сохраниться.

```bash setup
sed -i '/db\.local/d' /etc/hosts
cp /etc/hosts /var/lib/lab/hosts.orig
```

```bash check
grep -Eq '^10\.0\.0\.5[[:space:]]+db\.local[[:space:]]*$' /etc/hosts || fail "В /etc/hosts нет строки «10.0.0.5 db.local»"
[ "$(grep -c 'db\.local' /etc/hosts)" = 1 ] || fail "Строка db.local встречается $(grep -c 'db\.local' /etc/hosts) раз — должна один"
grep -v 'db\.local' /etc/hosts | diff -q - /var/lib/lab/hosts.orig >/dev/null || fail "Изменилось прежнее содержимое /etc/hosts"
getent hosts db.local | grep -q 10.0.0.5 || fail "Система не видит db.local"
ok "$(getent hosts db.local)"
```

```text hint
Перенаправление в файл делает ваша оболочка, а она работает без прав root — даже если перед командой стоит sudo. Нужна команда, которая сама пишет в файл (и ещё печатает на экран), — её и запускают через sudo, в режиме дописывания.
```

```bash solution
echo "10.0.0.5 db.local" | sudo tee -a /etc/hosts > /dev/null
```

```text review
Эталон: `echo "10.0.0.5 db.local" | sudo tee -a /etc/hosts > /dev/null`.

- `sudo echo ... >> /etc/hosts` не работает: `>>` выполняет ваша оболочка без root, а под sudo запускается только echo.
- `tee -a` дописывает, `tee` без `-a` **перезапишет** файл целиком — так однажды теряли /etc/hosts на продакшене.
- `> /dev/null` убирает дубль строки на экране.
- Вариант `sudo sh -c 'echo ... >> /etc/hosts'` тоже рабочий, но с кавычками в нём легко ошибиться.
- Проверять результат удобно через `getent hosts db.local`: он идёт тем же путём, что и программы.
```

```text notes
sudo\s+echo[^|\n]*>> => sudo echo ... >> файл даёт Permission denied: перенаправление выполняет ваша оболочка без прав root.
tee\s+(?!-a)[^\n]*/etc/hosts => tee без -a перезаписывает файл целиком. Для добавления строки нужен tee -a.
(nano|vim?)\s+/etc/hosts => Через редактор задача тоже решается, но в скриптах и автоматизации пишут через tee -a — это одна воспроизводимая команда.
```

### Сколько bash-пользователей

Посчитайте, у скольких пользователей в `/etc/passwd` оболочка — `/bin/bash`. Запишите одно число в `~/bash-users.txt`. Решите одной строкой с пайпом или одной командой поиска.

```bash setup
rm -f /home/student/bash-users.txt
```

```bash check
[ -f /home/student/bash-users.txt ] || fail "Нет ~/bash-users.txt"
want=$(grep -c ':/bin/bash$' /etc/passwd)
got=$(tr -d '[:space:]' < /home/student/bash-users.txt)
[ "$got" = "$want" ] || fail "В файле «$got», а пользователей с /bin/bash — другое число"
ok "пользователей с bash: $want"
```

```text hint
Отобрать строки /etc/passwd, которые заканчиваются на /bin/bash, и посчитать их. Это либо поиск, передающий результат в подсчёт строк, либо поиск с ключом «только количество».
```

```bash solution
grep -c '/bin/bash$' /etc/passwd > ~/bash-users.txt
```

```text review
Эталон: `grep -c '/bin/bash$' /etc/passwd`.

- `$` — конец строки: без него нашлись бы и строки, где `/bin/bash` встречается в середине (например, в описании пользователя).
- `grep ... | wc -l` даёт то же самое, но `grep -c` — один процесс вместо двух.
- Правильнее искать по полю, а не по строке: `awk -F: '$7 == "/bin/bash"' /etc/passwd | wc -l` — не ошибётся даже на хитрых данных. Об awk — в теме [[Работа с текстом]].
- `getent passwd` вместо `/etc/passwd` учтёт и пользователей из LDAP.
```

## Тест

### Какой номер файлового дескриптора у stderr?
= 2
> 0 — stdin, 1 — stdout, 2 — stderr.

### Чем > отличается от >>?
- [ ] `>` дописывает в конец, `>>` перезаписывает
- [x] `>` перезаписывает файл, `>>` дописывает в конец
- [ ] `>>` перенаправляет ошибки
- [ ] Ничем
> Одна лишняя стрелка или её отсутствие может стереть важный лог.

### Как отправить и stdout, и stderr команды в файл out.log?
- [x] cmd > out.log 2>&1
- [x] cmd &> out.log
- [ ] cmd 2>&1 > out.log
- [ ] cmd | out.log
> В третьем варианте stderr уйдёт на экран: перенаправления обрабатываются слева направо.

### Что делает 2>/dev/null?
- [ ] Удаляет файл с ошибками
- [x] Выбрасывает сообщения об ошибках, не показывая их
- [ ] Перенаправляет вывод на второй терминал
- [ ] Отключает команду при ошибке
> Удобно для `find /`, где много «Permission denied».

### Что передаёт пайп | следующей команде?
- [ ] stdout и stderr
- [x] Только stdout
- [ ] Только stderr
- [ ] Код возврата
> Чтобы через пайп пошли и ошибки, добавьте `2>&1` или используйте `|&`.

### Почему sudo echo "x" >> /etc/hosts выдаёт Permission denied?
- [ ] echo нельзя запускать через sudo
- [x] Перенаправление выполняет текущая оболочка без прав root; sudo получает только echo
- [ ] Файл /etc/hosts защищён от записи даже для root
- [ ] Нужно использовать >, а не >>
> Правильно: `echo "x" | sudo tee -a /etc/hosts`.

### Что делает команда tee?
- [ ] Сортирует строки
- [x] Пишет входные данные одновременно в файл и на stdout
- [ ] Удаляет дубликаты
- [ ] Создаёт пайп между двумя терминалами
> Название — от T-образного соединения труб.

### Какой код возврата означает успешное завершение команды?
= 0
> Любое ненулевое значение — ошибка; конкретное число зависит от программы.

### В какой переменной хранится код возврата последней команды?
= $?
> Сразу после проверки значение перезапишется кодом самой проверки.

### Когда выполнится вторая команда в mkdir app && cd app?
- [ ] Всегда
- [x] Только если mkdir завершился успешно
- [ ] Только если mkdir завершился с ошибкой
- [ ] Параллельно с первой
> `||` — наоборот, при ошибке первой команды.

### Как сохранить в имя архива текущую дату через подстановку команды?
- [ ] tar czf backup-{date}.tar.gz /etc
- [x] tar czf backup-$(date +%F).tar.gz /etc
- [ ] tar czf backup-date.tar.gz /etc | date
- [ ] tar czf backup-${date}.tar.gz /etc
> `$(...)` подставляет вывод команды. `${date}` — это переменная date, а не команда.

### Чем cat <<'EOF' отличается от cat <<EOF в here-document?
- [ ] Ничем
- [x] С кавычками переменные и подстановки внутри не раскрываются, текст вставляется как есть
- [ ] С кавычками текст пишется в файл EOF
- [ ] Без кавычек here-document не работает
> Удобно, когда в шаблоне нужен буквальный `$` — например, для конфигов nginx.

### Зачем в скриптах включают set -o pipefail?
- [ ] Чтобы пайпы работали быстрее
- [x] Чтобы пайплайн возвращал ошибку, если упала любая команда в цепочке, а не только последняя
- [ ] Чтобы запретить пайпы
- [ ] Чтобы ошибки шли в stdout
> Без pipefail `false | true` считается успешным.
