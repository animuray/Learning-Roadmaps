# Файловая система и поиск файлов

В Linux одно общее дерево каталогов с корнем `/`. Нет дисков C: и D: — другие диски **монтируются** в каталоги этого дерева. Принцип «всё есть файл»: устройства, процессы и сокеты тоже видны как файлы.

## Структура каталогов (FHS)

| Каталог | Что там |
| --- | --- |
| `/` | Корень |
| `/etc` | Конфигурация системы и служб: `/etc/nginx`, `/etc/ssh`, `/etc/fstab` |
| `/var` | Изменяемые данные: `/var/log` — логи, `/var/lib` — данные служб (базы, Docker) |
| `/home` | Домашние каталоги пользователей |
| `/root` | Домашний каталог root |
| `/usr` | Программы и библиотеки из пакетов: `/usr/bin`, `/usr/lib`, `/usr/share` |
| `/usr/local` | Программы, установленные вручную, не из пакетов |
| `/bin`, `/sbin`, `/lib` | Базовые команды и библиотеки; в современных дистрибутивах — ссылки на каталоги в `/usr` |
| `/opt` | Сторонние приложения целиком в одном каталоге |
| `/tmp` | Временные файлы, очищаются (часто при перезагрузке) |
| `/boot` | Ядро, initramfs, загрузчик |
| `/dev` | Файлы устройств: `/dev/sda`, `/dev/null` |
| `/proc`, `/sys` | Виртуальные ФС с информацией о процессах и ядре |
| `/run` | Данные работающих служб: PID-файлы, сокеты |
| `/mnt`, `/media` | Точки монтирования: временно вручную / съёмные носители |
| `/srv` | Данные, которые отдают службы (сайты, FTP) |

## Типы файлов

Первый символ в `ls -l` показывает тип:

| Символ | Тип |
| --- | --- |
| `-` | Обычный файл |
| `d` | Каталог |
| `l` | Символическая ссылка |
| `c` / `b` | Символьное / блочное устройство (`/dev/tty`, `/dev/sda`) |
| `s` | Сокет |
| `p` | Именованный канал (FIFO) |

Команда `file` определяет тип по **содержимому**, а не по расширению: `file /bin/ls`, `file image.png`.

## stat — всё о файле

```bash
stat /etc/hosts
```

Покажет размер, номер **inode**, права, владельца, число жёстких ссылок и три времени:

- **atime** — последнее чтение;
- **mtime** — последнее изменение содержимого;
- **ctime** — последнее изменение метаданных (права, владелец, переименование).

## Ссылки: ln

```bash
ln -s /opt/app/current/bin/app /usr/local/bin/app   # символическая ссылка
ln file.txt hardlink.txt                            # жёсткая ссылка
```

| | Символическая (`ln -s`) | Жёсткая (`ln`) |
| --- | --- | --- |
| Что это | Отдельный файл, хранящий **путь** к цели | Ещё одно **имя** для того же inode |
| Если удалить оригинал | Ссылка «битая» (dangling) | Данные живы, пока есть хоть одно имя |
| Между файловыми системами | Можно | Нельзя |
| На каталоги | Можно | Нельзя |

Символические ссылки повсюду: так переключают версии (`current → releases/2024-06-01`), так устроены `/etc/nginx/sites-enabled` и `/etc/systemd/system/*.wants`.

## Поиск файлов

### find — ищет по диску прямо сейчас

```bash
find /etc -name "*.conf"               # по имени (с учётом регистра)
find / -iname "nginx*" 2>/dev/null     # без учёта регистра, ошибки доступа скрыты
find /var/log -type f -size +100M      # файлы больше 100 МБ
find /tmp -type f -mtime +7            # изменены больше 7 дней назад
find . -type d -name node_modules      # только каталоги
find /home -user alice                 # по владельцу
find /var/log -name "*.gz" -mtime +30 -delete            # удалить старые архивы логов
find . -name "*.sh" -exec chmod +x {} \;                  # выполнить команду для каждого
find / -xdev -size +1G                 # не уходить в другие файловые системы
```

### locate — быстро, но по базе

```bash
sudo updatedb       # обновить базу (обычно делается по расписанию)
locate nginx.conf
```

`locate` ищет мгновенно, но не видит файлы, созданные после последнего `updatedb`. В современных дистрибутивах это пакет `plocate`.

### Где программа

```bash
which python3       # какой файл запустится (по PATH)
type ls             # что это: алиас, встроенная команда или файл
whereis nginx       # бинарник, man-страницы, исходники
```

### tree — дерево каталогов

```bash
tree -L 2 /etc/nginx   # два уровня вложенности
tree -a -I node_modules
```

## Практика

- [ ] Найти через `find` все файлы больше 50 МБ в своей системе
- [ ] Найти конфиги, изменённые за последние сутки: `find /etc -mtime -1`
- [ ] Создать символическую и жёсткую ссылку на файл, удалить оригинал и посмотреть, что стало с каждой ссылкой (`ls -li`, `stat`)
- [ ] Выполнить `file` для бинарника, скрипта, картинки и текстового файла
- [ ] Установить `tree` и посмотреть структуру своего репозитория-конспекта

## Тест

### В каком каталоге хранятся конфигурационные файлы системы и служб?
= /etc
> Например, `/etc/nginx/nginx.conf` или `/etc/ssh/sshd_config`.

### Где обычно лежат логи служб?
- [ ] /etc/log
- [x] /var/log
- [ ] /usr/log
- [ ] /tmp/log
> `/var` — изменяемые данные: логи, кэши, данные баз и Docker.

### Что находится в /proc?
- [ ] Исполняемые файлы процессора
- [x] Виртуальная файловая система с информацией о процессах и ядре
- [ ] Резервные копии
- [ ] Программы, установленные вручную
> Файлов в `/proc` нет на диске — ядро формирует их на лету.

### Как найти все файлы больше 100 МБ в /var?
- [ ] find /var -size 100M
- [x] find /var -type f -size +100M
- [ ] locate /var +100M
- [ ] ls -size /var
> `+` — больше, `-` — меньше, без знака — ровно столько.

### Чем locate отличается от find?
- [ ] locate ищет только по содержимому файлов
- [x] locate ищет мгновенно по заранее созданной базе и может не видеть свежие файлы; find обходит диск в момент запуска
- [ ] find работает только в домашнем каталоге
- [ ] Ничем
> Базу обновляет `updatedb`.

### Что произойдёт с символической ссылкой, если удалить файл, на который она указывает?
- [ ] Ссылка продолжит показывать содержимое файла
- [x] Ссылка станет «битой» — указывает на несуществующий путь
- [ ] Ссылка удалится автоматически
- [ ] Файл восстановится
> С жёсткой ссылкой иначе: данные остаются, пока существует хотя бы одно имя.

### Что верно для жёстких ссылок?
- [x] Это ещё одно имя для того же inode
- [x] Нельзя создать жёсткую ссылку на файл в другой файловой системе
- [ ] Можно создать жёсткую ссылку на каталог
- [ ] Хранит путь к оригинальному файлу
> Путь хранит символическая ссылка.

### Как создать символическую ссылку /usr/local/bin/app на файл /opt/app/bin/app?
= ln -s /opt/app/bin/app /usr/local/bin/app
> Порядок: сначала цель, потом имя ссылки — как у `cp`.

### Какой символ в начале строки ls -l означает каталог?
- [ ] -
- [x] d
- [ ] l
- [ ] c
> `l` — символическая ссылка, `-` — обычный файл.

### Какая команда определяет тип файла по его содержимому?
= file
> Расширение в Linux ничего не гарантирует: `file` смотрит на сигнатуру внутри файла.

### Что показывает mtime в выводе stat?
- [ ] Время последнего чтения
- [x] Время последнего изменения содержимого
- [ ] Время изменения прав и владельца
- [ ] Время создания каталога
> atime — чтение, ctime — изменение метаданных. `find -mtime` ищет как раз по mtime.

### Как выполнить команду chmod +x для каждого найденного .sh-файла?
- [ ] find . -name "*.sh" | chmod +x
- [x] find . -name "*.sh" -exec chmod +x {} \;
- [ ] chmod +x find . -name "*.sh"
- [ ] find . -name "*.sh" -chmod +x
> `{}` подставляется именем файла, `\;` завершает команду. Альтернатива — `xargs`.

### Как узнать, какой именно файл запустится при вводе python3?
- [ ] find python3
- [x] which python3
- [ ] stat python3
- [ ] file python3
> `which` ищет команду по каталогам из PATH — подробнее в теме «Переменные окружения».

### Зачем в команде find / -name "x" добавляют 2>/dev/null?
- [ ] Чтобы ускорить поиск
- [x] Чтобы скрыть сообщения об ошибках доступа (Permission denied), которые идут в поток ошибок
- [ ] Чтобы сохранить результат в файл
- [ ] Чтобы искать только в /dev
> Потоки и перенаправления разбираются в отдельной теме.
