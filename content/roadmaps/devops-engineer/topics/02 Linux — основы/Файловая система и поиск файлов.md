# Файловая система и поиск файлов

В Linux одно общее дерево каталогов с корнем `/`. Нет дисков C: и D: — другие диски **монтируются** в каталоги этого дерева. Принцип «всё есть файл»: устройства, процессы и сокеты тоже видны как файлы.

## Структура каталогов (FHS)

| Каталог | Что там |
| --- | --- |
| `/` | Корень |
| `/etc` | Конфигурация системы и служб: `/etc/nginx`, `/etc/ssh`, `/etc/fstab` |
| `/var` | Изменяемые данные: `/var/log` — логи, `/var/lib` — данные служб (базы, Docker) |
| `/home` | Домашние каталоги пользователей |
| `/root` | Домашний каталог root |
| `/usr` | Программы и библиотеки из пакетов: `/usr/bin`, `/usr/lib`, `/usr/share` |
| `/usr/local` | Программы, установленные вручную, не из пакетов |
| `/bin`, `/sbin`, `/lib` | Базовые команды и библиотеки; в современных дистрибутивах — ссылки на каталоги в `/usr` |
| `/opt` | Сторонние приложения целиком в одном каталоге |
| `/tmp` | Временные файлы, очищаются (часто при перезагрузке) |
| `/boot` | Ядро, initramfs, загрузчик |
| `/dev` | Файлы устройств: `/dev/sda`, `/dev/null` |
| `/proc`, `/sys` | Виртуальные ФС с информацией о процессах и ядре |
| `/run` | Данные работающих служб: PID-файлы, сокеты |
| `/mnt`, `/media` | Точки монтирования: временно вручную / съёмные носители |
| `/srv` | Данные, которые отдают службы (сайты, FTP) |

## Типы файлов

Первый символ в `ls -l` показывает тип:

| Символ | Тип |
| --- | --- |
| `-` | Обычный файл |
| `d` | Каталог |
| `l` | Символическая ссылка |
| `c` / `b` | Символьное / блочное устройство (`/dev/tty`, `/dev/sda`) |
| `s` | Сокет |
| `p` | Именованный канал (FIFO) |

Команда `file` определяет тип по **содержимому**, а не по расширению: `file /bin/ls`, `file image.png`.

## stat — всё о файле

```bash
stat /etc/hosts
```

Покажет размер, номер **inode**, права, владельца, число жёстких ссылок и три времени:

- **atime** — последнее чтение;
- **mtime** — последнее изменение содержимого;
- **ctime** — последнее изменение метаданных (права, владелец, переименование).

## Ссылки: ln

```bash
ln -s /opt/app/current/bin/app /usr/local/bin/app   # символическая ссылка
ln file.txt hardlink.txt                            # жёсткая ссылка
```

| | Символическая (`ln -s`) | Жёсткая (`ln`) |
| --- | --- | --- |
| Что это | Отдельный файл, хранящий **путь** к цели | Ещё одно **имя** для того же inode |
| Если удалить оригинал | Ссылка «битая» (dangling) | Данные живы, пока есть хоть одно имя |
| Между файловыми системами | Можно | Нельзя |
| На каталоги | Можно | Нельзя |

Символические ссылки повсюду: так переключают версии (`current → releases/2024-06-01`), так устроены `/etc/nginx/sites-enabled` и `/etc/systemd/system/*.wants`.

## Поиск файлов

### find — ищет по диску прямо сейчас

```bash
find /etc -name "*.conf"               # по имени (с учётом регистра)
find / -iname "nginx*" 2>/dev/null     # без учёта регистра, ошибки доступа скрыты
find /var/log -type f -size +100M      # файлы больше 100 МБ
find /tmp -type f -mtime +7            # изменены больше 7 дней назад
find . -type d -name node_modules      # только каталоги
find /home -user alice                 # по владельцу
find /var/log -name "*.gz" -mtime +30 -delete            # удалить старые архивы логов
find . -name "*.sh" -exec chmod +x {} \;                  # выполнить команду для каждого
find / -xdev -size +1G                 # не уходить в другие файловые системы
```

### locate — быстро, но по базе

```bash
sudo updatedb       # обновить базу (обычно делается по расписанию)
locate nginx.conf
```

`locate` ищет мгновенно, но не видит файлы, созданные после последнего `updatedb`. В современных дистрибутивах это пакет `plocate`.

### Где программа

```bash
which python3       # какой файл запустится (по PATH)
type ls             # что это: алиас, встроенная команда или файл
whereis nginx       # бинарник, man-страницы, исходники
```

### tree — дерево каталогов

```bash
tree -L 2 /etc/nginx   # два уровня вложенности
tree -a -I node_modules
```

## Лаборатория

```bash setup
# Тестовое дерево для поиска: большие, свежие, старые и пустые файлы.
rm -rf /srv/data /home/student/big.txt /home/student/recent.txt
mkdir -p /srv/data/{app,cache,backup/old}
head -c 12M /dev/zero > /srv/data/backup/db-2025.dump
head -c 7M /dev/zero > /srv/data/cache/blob.bin
head -c 2M /dev/zero > /srv/data/app/app.jar
echo "level=info" > /srv/data/app/app.conf
echo "old" > /srv/data/backup/old/notes.txt
: > /srv/data/cache/empty.lock
touch -d '40 days ago' /srv/data/backup/db-2025.dump /srv/data/backup/old/notes.txt /srv/data/cache/blob.bin
touch -d '2 hours ago' /srv/data/app/app.conf /srv/data/app/app.jar /srv/data/cache/empty.lock
```

### Большие файлы

Найдите в `/srv/data` все файлы **больше 5 МБ** и сохраните их полные пути (по одному на строку) в `~/big.txt`.

```bash check
f=/home/student/big.txt
[ -s $f ] || fail "Файл ~/big.txt пуст или не создан"
want=$(printf '%s\n' /srv/data/backup/db-2025.dump /srv/data/cache/blob.bin)
got=$(sort -u $f | sed 's/[[:space:]]*$//')
[ "$got" = "$want" ] || fail "В списке лишние файлы или не хватает нужных. Сейчас в ~/big.txt:
$(cat $f)"
ok "найдены оба больших файла"
```

```text hint
Искать начиная с /srv/data, только обычные файлы, с условием на размер «больше 5 мегабайт». У команды поиска размер задаётся числом с суффиксом и знаком «+» для «больше». Результат — в файл.
```

```bash solution
find /srv/data -type f -size +5M > ~/big.txt
```

```text review
Эталон: `find /srv/data -type f -size +5M > ~/big.txt`.

- `+5M` — больше 5 МБ, `-5M` — меньше, `5M` — ровно (с округлением вверх до мегабайт — поэтому «ровно» почти не используют).
- На сервере такой поиск обычно ограничивают одной файловой системой: `find / -xdev -type f -size +500M` — без `-xdev` find пойдёт в `/proc` и смонтированные сетевые диски.
- Для «что съело место» чаще начинают с `du -sh /* | sort -h` — см. тему [[Место на диске — df и du]].
```

### Свежие изменения

Найдите в `/srv/data` файлы, изменённые **за последние сутки**, и сохраните полные пути в `~/recent.txt`.

```bash check
f=/home/student/recent.txt
[ -s $f ] || fail "Файл ~/recent.txt пуст или не создан"
want=$(printf '%s\n' /srv/data/app/app.conf /srv/data/app/app.jar /srv/data/cache/empty.lock)
got=$(sort -u $f | sed 's/[[:space:]]*$//')
[ "$got" = "$want" ] || fail "В списке лишние файлы или не хватает нужных. Сейчас в ~/recent.txt:
$(cat $f)"
ok "найдены 3 свежих файла"
```

```text hint
Условие поиска по времени изменения содержимого, в сутках: «меньше одних суток назад» записывается со знаком минус. Только обычные файлы, без каталогов.
```

```bash solution
find /srv/data -type f -mtime -1 > ~/recent.txt
```

```text review
Эталон: `find /srv/data -type f -mtime -1`.

- `-mtime` — изменение содержимого, `-ctime` — изменение метаданных (права, владелец), `-atime` — последнее чтение (часто отключено опцией монтирования `noatime`).
- `-mmin -60` — то же в минутах: «что поменялось за последний час» после неудачного деплоя.
- Без `-type f` в список попали бы и каталоги — их mtime меняется, когда внутри создают или удаляют файлы.
```

### Удалить пустые

Удалите все **пустые файлы** внутри `/srv/data`. Остальные файлы трогать нельзя.

```bash check
[ -e /srv/data/cache/empty.lock ] && fail "Пустой файл /srv/data/cache/empty.lock ещё на месте"
for f in backup/db-2025.dump cache/blob.bin app/app.jar app/app.conf backup/old/notes.txt; do
  [ -f /srv/data/$f ] || fail "Пропал непустой файл /srv/data/$f — удалять нужно только пустые"
done
ok "пустые файлы удалены, остальные на месте"
```

```text hint
1. Найти в /srv/data обычные файлы с условием «пустой».
2. Сначала просто посмотрите список — убедитесь, что там только то, что нужно удалить.
3. Затем добавьте к той же команде действие удаления. Каталог принадлежит root.
```

```bash solution
sudo find /srv/data -type f -empty -delete
```

```text review
Эталон: сначала `find /srv/data -type f -empty` — посмотреть, затем то же с `-delete`.

- Привычка «сначала вывести, потом удалять» спасает от ошибок в условиях: `-delete` не спрашивает подтверждения.
- `-delete` должен стоять **последним**: find выполняет выражение слева направо, и `find -delete -type f` удалит всё подряд.
- Альтернатива для старых систем — `-exec rm {} +`; `xargs rm` без `-print0 | xargs -0` ломается на именах с пробелами.
```

```text notes
-delete\s+.*-(type|empty|name) => -delete стоит раньше условий: find выполняет выражение слева направо и удаляет файлы ещё до проверки условий. -delete всегда пишут последним.
rm\s+-[a-z]*r[a-z]*\s+/srv/data => Каталог /srv/data удалялся целиком — задача была удалить только пустые файлы.
```

### Ссылки

Создайте в домашнем каталоге:

- **символическую** ссылку `~/app.conf`, указывающую на `/srv/data/app/app.conf`;
- **жёсткую** ссылку `~/notes-copy.txt` на файл `~/notes.txt` (он уже создан).

```bash setup
rm -f /home/student/app.conf /home/student/notes-copy.txt
echo "мои заметки" > /home/student/notes.txt
chown student:student /home/student/notes.txt
mkdir -p /srv/data/app && echo "level=info" > /srv/data/app/app.conf
```

```bash check
h=/home/student
[ -L $h/app.conf ] || fail "~/app.conf — не символическая ссылка"
[ "$(readlink -f $h/app.conf)" = /srv/data/app/app.conf ] || fail "~/app.conf указывает на $(readlink $h/app.conf), а не на /srv/data/app/app.conf"
[ -f $h/notes-copy.txt ] && [ ! -L $h/notes-copy.txt ] || fail "~/notes-copy.txt нет или это символическая ссылка"
[ "$(stat -c %i $h/notes.txt)" = "$(stat -c %i $h/notes-copy.txt)" ] || fail "У notes.txt и notes-copy.txt разные inode — это копия, а не жёсткая ссылка"
ok "symlink → $(readlink $h/app.conf); hardlink: inode $(stat -c %i $h/notes.txt), ссылок: $(stat -c %h $h/notes.txt)"
```

```text hint
Обе ссылки создаёт одна и та же команда; символическую — с ключом. Порядок аргументов как у копирования: сначала на что ссылаемся, потом имя ссылки.
```

```bash solution
ln -s /srv/data/app/app.conf ~/app.conf
ln ~/notes.txt ~/notes-copy.txt
```

```text review
Эталон: `ln -s /srv/data/app/app.conf ~/app.conf` и `ln ~/notes.txt ~/notes-copy.txt`.

- Символическая ссылка хранит **путь**. Удалите оригинал — ссылка станет «битой». Может указывать на каталог и на другой диск.
- Жёсткая ссылка — второе **имя** того же inode. Удаление одного имени не трогает данные, пока есть другие (счётчик ссылок в `ls -l` / `stat -c %h`). Не работает для каталогов и между файловыми системами.
- На практике симлинки повсюду: `/etc/nginx/sites-enabled/`, переключение версий релиза (`current → releases/2026-03-15`), `/usr/bin/python3 → python3.12`.
- Частая ошибка — перепутать порядок аргументов: `ln -s ЦЕЛЬ ИМЯ_ССЫЛКИ`, как `cp ОТКУДА КУДА`.
```

```text notes
cp\s+[^\n]*notes => notes-copy.txt создавался через cp — это копия с отдельным inode, а не жёсткая ссылка. Изменение одного файла не отразится на другом.
```

## Тест

### В каком каталоге хранятся конфигурационные файлы системы и служб?
= /etc
> Например, `/etc/nginx/nginx.conf` или `/etc/ssh/sshd_config`.

### Где обычно лежат логи служб?
- [ ] /etc/log
- [x] /var/log
- [ ] /usr/log
- [ ] /tmp/log
> `/var` — изменяемые данные: логи, кэши, данные баз и Docker.

### Что находится в /proc?
- [ ] Исполняемые файлы процессора
- [x] Виртуальная файловая система с информацией о процессах и ядре
- [ ] Резервные копии
- [ ] Программы, установленные вручную
> Файлов в `/proc` нет на диске — ядро формирует их на лету.

### Как найти все файлы больше 100 МБ в /var?
- [ ] find /var -size 100M
- [x] find /var -type f -size +100M
- [ ] locate /var +100M
- [ ] ls -size /var
> `+` — больше, `-` — меньше, без знака — ровно столько.

### Чем locate отличается от find?
- [ ] locate ищет только по содержимому файлов
- [x] locate ищет мгновенно по заранее созданной базе и может не видеть свежие файлы; find обходит диск в момент запуска
- [ ] find работает только в домашнем каталоге
- [ ] Ничем
> Базу обновляет `updatedb`.

### Что произойдёт с символической ссылкой, если удалить файл, на который она указывает?
- [ ] Ссылка продолжит показывать содержимое файла
- [x] Ссылка станет «битой» — указывает на несуществующий путь
- [ ] Ссылка удалится автоматически
- [ ] Файл восстановится
> С жёсткой ссылкой иначе: данные остаются, пока существует хотя бы одно имя.

### Что верно для жёстких ссылок?
- [x] Это ещё одно имя для того же inode
- [x] Нельзя создать жёсткую ссылку на файл в другой файловой системе
- [ ] Можно создать жёсткую ссылку на каталог
- [ ] Хранит путь к оригинальному файлу
> Путь хранит символическая ссылка.

### Как создать символическую ссылку /usr/local/bin/app на файл /opt/app/bin/app?
= ln -s /opt/app/bin/app /usr/local/bin/app
> Порядок: сначала цель, потом имя ссылки — как у `cp`.

### Какой символ в начале строки ls -l означает каталог?
- [ ] -
- [x] d
- [ ] l
- [ ] c
> `l` — символическая ссылка, `-` — обычный файл.

### Какая команда определяет тип файла по его содержимому?
= file
> Расширение в Linux ничего не гарантирует: `file` смотрит на сигнатуру внутри файла.

### Что показывает mtime в выводе stat?
- [ ] Время последнего чтения
- [x] Время последнего изменения содержимого
- [ ] Время изменения прав и владельца
- [ ] Время создания каталога
> atime — чтение, ctime — изменение метаданных. `find -mtime` ищет как раз по mtime.

### Как выполнить команду chmod +x для каждого найденного .sh-файла?
- [ ] find . -name "*.sh" | chmod +x
- [x] find . -name "*.sh" -exec chmod +x {} \;
- [ ] chmod +x find . -name "*.sh"
- [ ] find . -name "*.sh" -chmod +x
> `{}` подставляется именем файла, `\;` завершает команду. Альтернатива — `xargs`.

### Как узнать, какой именно файл запустится при вводе python3?
- [ ] find python3
- [x] which python3
- [ ] stat python3
- [ ] file python3
> `which` ищет команду по каталогам из PATH — подробнее в теме «Переменные окружения».

### Зачем в команде find / -name "x" добавляют 2>/dev/null?
- [ ] Чтобы ускорить поиск
- [x] Чтобы скрыть сообщения об ошибках доступа (Permission denied), которые идут в поток ошибок
- [ ] Чтобы сохранить результат в файл
- [ ] Чтобы искать только в /dev
> Потоки и перенаправления разбираются в отдельной теме.
