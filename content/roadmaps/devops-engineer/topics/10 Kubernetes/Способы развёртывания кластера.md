# Способы развёртывания кластера

| Способ | Кто управляет control plane | Когда |
| --- | --- | --- |
| **Managed Kubernetes** (EKS, GKE, AKS, Yandex Managed Kubernetes, VK Cloud, Selectel и др.) | Провайдер | Облако, хочется меньше эксплуатации |
| **kubeadm** | Вы | Свои серверы, понимание «как устроено», основа многих инструментов |
| **kubespray** (Ansible) | Вы | Своё железо/ВМ, много нод, повторяемая установка с HA |
| **k3s**, **RKE2**, **k0s** | Вы | Лёгкие дистрибутивы: edge, небольшие кластеры, быстрая установка |
| **Talos Linux** | Вы | Неизменяемая ОС только для Kubernetes, управление через API |
| kind, Minikube, k3d | — | Только локально, для учёбы и тестов |

## kubeadm — официальный инструмент

kubeadm создаёт минимальный кластер по лучшим практикам: сертификаты, static pods control plane, kubeconfig, bootstrap-токены.

Подготовка **каждой** ноды:

1. Linux, минимум 2 CPU и 2 ГБ RAM, уникальные hostname, MAC и product_uuid, связность между нодами.
2. Swap: исторически требовалось выключить (`swapoff -a`); современные версии умеют работать со swap при настройке kubelet, но для начала проще выключить.
3. Модули ядра и sysctl: `overlay`, `br_netfilter`, `net.ipv4.ip_forward = 1`.
4. Container runtime: **containerd** с `SystemdCgroup = true`.
5. Пакеты `kubeadm`, `kubelet`, `kubectl` из репозитория **pkgs.k8s.io** (отдельный репозиторий на каждую минорную версию; старые apt.kubernetes.io заморожены), зафиксировать версии (`apt-mark hold`).

```bash
sudo kubeadm init --pod-network-cidr=10.244.0.0/16 --control-plane-endpoint=k8s-api.example.com
mkdir -p ~/.kube && sudo cp /etc/kubernetes/admin.conf ~/.kube/config && sudo chown $(id -u):$(id -g) ~/.kube/config
kubectl apply -f calico.yaml                      # CNI — без него ноды NotReady, CoreDNS в Pending
sudo kubeadm join k8s-api.example.com:6443 --token ... --discovery-token-ca-cert-hash sha256:...
kubeadm token create --print-join-command
```

Что лежит на control-plane ноде: `/etc/kubernetes/manifests/` (static pods: apiserver, etcd, scheduler, controller-manager), `/etc/kubernetes/pki/` (сертификаты), `/etc/kubernetes/admin.conf`.

## Высокая доступность

- **3 control-plane ноды** (etcd с кворумом), API за балансировщиком (HAProxy+keepalived, kube-vip или облачный LB) — адрес задаётся `--control-plane-endpoint` **с самого начала**.
- etcd: **stacked** (на тех же нодах — проще) или **внешний** кластер etcd (надёжнее, больше серверов).
- Worker-нод — столько, чтобы падение одной не перегружало остальные.

## kubespray

Набор плейбуков Ansible, который устанавливает production-кластер на ваши ноды: HA control plane, выбор CNI, аддоны, обновления.

```bash
git clone https://github.com/kubernetes-sigs/kubespray && cd kubespray
pip install -r requirements.txt
cp -r inventory/sample inventory/mycluster
ansible-playbook -i inventory/mycluster/hosts.yaml --become cluster.yml
```

Настройки — в `inventory/mycluster/group_vars/`. Обновление кластера — `upgrade-cluster.yml`, добавление нод — `scale.yml`. Под капотом kubespray использует kubeadm.

## Managed Kubernetes

Провайдер запускает и обновляет control plane, etcd, бэкапы; вы управляете группами worker-нод (часто с автомасштабированием) и всем внутри кластера.

Плюсы: быстро, надёжный control plane, интеграция с балансировщиками, дисками, IAM, реестром. Минусы: стоимость, меньше контроля, особенности конкретного облака. Создают обычно через **Terraform** (тема впереди).

## Жизнь кластера

- **Обновления**: Kubernetes выпускает минорные версии примерно три раза в год, каждая поддерживается около года. Обновляться **по одной минорной версии**: сначала control plane (`kubeadm upgrade plan`, `kubeadm upgrade apply`), потом kubelet на нодах (drain → обновить → uncordon). Читайте release notes: удаляются устаревшие API (проверить манифесты: kubent, pluto).
- **Сертификаты** kubeadm живут 1 год; `kubeadm certs check-expiration`, `kubeadm certs renew all`. Обновление кластера через kubeadm продлевает их автоматически.
- **Бэкап etcd**: `etcdctl snapshot save` по расписанию + бэкап `/etc/kubernetes/pki`.
- **Мониторинг** компонентов, ёмкость нод, логи.

## Тест

### Чем managed Kubernetes отличается от самостоятельно развёрнутого кластера?
- [x] Control plane, etcd и их обновления берёт на себя провайдер
- [x] Вы управляете worker-нодами и ресурсами внутри кластера
- [ ] В managed-кластере нельзя использовать kubectl
- [ ] Managed-кластер всегда бесплатный
> Самостоятельный кластер — больше контроля и больше работы.

### Что такое kubeadm?
- [ ] Веб-интерфейс Kubernetes
- [x] Официальный инструмент для инициализации control plane и подключения нод к кластеру
- [ ] Облачный сервис
- [ ] CNI-плагин
> Им пользуется и kubespray.

### Почему после kubeadm init ноды в статусе NotReady, а CoreDNS в Pending?
- [ ] Ошибка установки
- [x] Не установлен CNI-плагин — сеть подов не настроена
- [ ] Не хватает памяти
- [ ] Не выполнен kubeadm join
> После установки Calico, Cilium или Flannel ноды станут Ready.

### Какой container runtime обычно ставят на ноды kubeadm-кластера?
= containerd
> С драйвером cgroup systemd (SystemdCgroup = true), как и у kubelet.

### Что такое kubespray?
- [ ] Облачный провайдер
- [x] Набор плейбуков Ansible для установки и обновления production-кластера Kubernetes на свои серверы
- [ ] Утилита для бэкапа etcd
- [ ] Ingress-контроллер
> Инвентарь и настройки — в inventory/имя/group_vars.

### Сколько control-plane нод рекомендуют для отказоустойчивого кластера?
= 3
= три
> etcd сохраняет кворум при отказе одной из трёх нод.

### Почему адрес --control-plane-endpoint важно задать при первой инициализации?
- [ ] Иначе kubeadm не запустится
- [x] Через него ноды и клиенты обращаются к API; чтобы потом добавить control-plane ноды за балансировщиком, адрес должен быть общим с самого начала
- [ ] Это требование CNI
- [ ] Чтобы ускорить etcd
> Иначе кластер будет привязан к адресу одной ноды.

### Как правильно обновлять кластер Kubernetes?
- [ ] Сразу через несколько минорных версий
- [x] По одной минорной версии: сначала control plane, затем kubelet на нодах с drain и uncordon
- [ ] Сначала все worker-ноды одновременно
- [ ] Переустановить кластер с нуля
> Перед обновлением проверяют удаляемые API в манифестах.

### Сколько по умолчанию живут сертификаты, выпущенные kubeadm?
- [ ] 10 лет
- [x] 1 год — их проверяют командой kubeadm certs check-expiration и продлевают
- [ ] 30 дней
- [ ] Бессрочно
> Обновление кластера через kubeadm продлевает их автоматически.

### Откуда ставить пакеты kubeadm, kubelet и kubectl сейчас?
- [ ] Из apt.kubernetes.io
- [x] Из репозитория pkgs.k8s.io, отдельного для каждой минорной версии
- [ ] Только собирать из исходников
- [ ] Из Docker Hub
> Старые репозитории apt.kubernetes.io и yum.kubernetes.io заморожены.

### Что обязательно бэкапить в самостоятельном кластере?
- [x] etcd (снапшоты etcdctl snapshot save)
- [x] Сертификаты и ключи control plane из /etc/kubernetes/pki
- [ ] Каталог /tmp на нодах
- [ ] Образы CoreDNS
> Манифесты приложений должны храниться в Git.

### Где на control-plane ноде kubeadm лежат манифесты компонентов control plane?
= /etc/kubernetes/manifests
