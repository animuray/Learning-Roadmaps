# Облачные модели

**Облако** — это не «чужой сервер», а модель: ресурсы (вычисления, сеть, хранилище, сервисы) выдаются **по запросу через API**, быстро масштабируются и оплачиваются **по факту потребления**.

## Пять признаков облака (NIST SP 800-145)

1. **Самообслуживание по запросу** — создать ВМ можно самому за минуту, без звонков и заявок.
2. **Широкий сетевой доступ** — через консоль, CLI, API отовсюду.
3. **Пул ресурсов** — провайдер обслуживает множество клиентов на общем оборудовании (multi-tenancy).
4. **Быстрая эластичность** — масштабирование вверх и вниз, в том числе автоматически.
5. **Измеряемость** — учёт потребления и оплата за него (поминутно, посекундно, за гигабайты и запросы).

## Модели обслуживания

```
                  On-premise   IaaS        PaaS         SaaS
 Приложение        вы          вы          вы           провайдер
 Данные            вы          вы          вы           провайдер*
 Runtime, ОС       вы          вы          провайдер    провайдер
 Виртуализация     вы          провайдер   провайдер    провайдер
 Серверы, сеть, ЦОД вы         провайдер   провайдер    провайдер
                                    * но ответственность за доступ к данным — всегда ваша
```

| Модель | Что даёт провайдер | Примеры | Что делаете вы |
| --- | --- | --- | --- |
| **IaaS** (инфраструктура) | ВМ, диски, сети, балансировщики | Compute Cloud, Selectel Cloud Servers, AWS EC2 | ОС, обновления, ПО, файрвол внутри ВМ, бэкапы |
| **PaaS** (платформа) | Готовую платформу: managed-базы, Kubernetes, очереди, App Engine | Managed PostgreSQL, Managed Kubernetes | Схему БД, приложения, настройки, доступы |
| **SaaS** (приложение) | Готовое приложение | Яндекс 360, GitLab.com, Gmail | Пользователей, данные, права |
| **Serverless / FaaS** | Запуск кода по событию, без серверов | Cloud Functions, Serverless Containers, AWS Lambda | Код функции; платите за вызовы и время |

Чем выше по модели, тем меньше работы по администрированию, но меньше контроля и выше зависимость от провайдера (**vendor lock-in**).

## Разделённая ответственность

Провайдер отвечает за безопасность **облака** (ЦОД, железо, гипервизор, сеть провайдера), клиент — за безопасность **в облаке**: ОС ВМ и её обновления, правила групп безопасности, права IAM, шифрование и доступ к данным. Открытый всему миру бакет или SSH с паролем — ответственность клиента, а не облака.

## Модели развёртывания

- **Публичное облако** — общая инфраструктура провайдера для многих клиентов.
- **Частное облако** — облачная платформа для одной организации (OpenStack, VMware, «частные» инсталляции провайдеров).
- **Гибридное** — часть в своём ЦОД, часть в публичном облаке, связанные сетью (VPN, выделенный канал).
- **Мультиоблако** — несколько провайдеров (для отказоустойчивости или из-за разных сервисов); дорого в поддержке.

## Регионы и зоны доступности

- **Регион** — географическая площадка (например, Россия, Казахстан у Yandex Cloud).
- **Зона доступности (AZ)** — отдельный дата-центр (или группа) с независимым питанием и сетью внутри региона. У Yandex Cloud в России — `ru-central1-a`, `ru-central1-b`, `ru-central1-d` (рекомендуемая для новых проектов), `ru-central1-e`; бывшая `ru-central1-c` выведена из эксплуатации.
- Для отказоустойчивости ресурсы распределяют **минимум по двум-трём зонам**: авария одного ЦОД не останавливает сервис.
- Некоторые ресурсы **зональные** (ВМ, диски, подсети), другие — **региональные** или глобальные (облачная сеть, бакеты, managed-кластеры с хостами в нескольких зонах).

## Как платят за облако

- Поминутно/посекундно за ВМ, за гигабайты дисков и хранилища, за запросы, за **исходящий трафик**.
- **Прерываемые ВМ** (preemptible/spot) — в разы дешевле, но облако может остановить их в любой момент и не дольше чем через 24 часа (у Selectel скидка до 75%). Для CI-раннеров, батчей, тестов.
- Резервирование ресурсов и скидки за обязательства.
- Частые «сюрпризы» в счёте: забытые ВМ и диски, снапшоты, публичные IP, трафик, логи, managed-сервисы, оставленные после тестов. **Метки** (labels) на ресурсах, бюджеты и алерты по расходам — обязательны.

## Российские облака

| Провайдер | Особенности |
| --- | --- |
| **Yandex Cloud** | Самая широкая линейка сервисов: ВМ, VPC, Object Storage, Managed PostgreSQL/ClickHouse/Kafka/Valkey/OpenSearch, Managed Kubernetes, serverless; CLI `yc`, Terraform-провайдер |
| **Selectel** | Облачные серверы на OpenStack (KVM), выделенные серверы, Managed Kubernetes и базы, S3; работает с OpenStack CLI и Terraform |
| **Cloud.ru (Evolution)** | Публичное облако с IaaS и PaaS: ВМ, Managed Kubernetes, Managed PostgreSQL, GPU |
| **VK Cloud, Timeweb Cloud, MWS** и другие | IaaS, Kubernetes, базы, S3 |

Зачем свои облака: **152-ФЗ** о персональных данных (данные россиян хранятся в России), доступность и оплата, аттестация для госсистем. Концепции у всех одинаковые — ВМ, сети, группы безопасности, S3, managed-сервисы, Terraform, — поэтому опыт переносится между провайдерами (в том числе на AWS, GCP, Azure).

## Когда облако выгодно

- Быстрый старт, эксперименты, переменная нагрузка, нужна эластичность.
- Нужны managed-сервисы, а своей команды DBA/инфраструктуры нет.
- География и отказоустойчивость без постройки своих ЦОД.

Когда стоит считать: стабильная высокая нагрузка 24/7 (свои или арендованные выделенные серверы бывают дешевле), огромный исходящий трафик, особые требования к железу или изоляции.

## Практика

- [ ] Зарегистрироваться в одном из российских облаков, активировать пробный период и настроить бюджет с уведомлением о расходах
- [ ] Разобраться в иерархии ресурсов провайдера (у Yandex Cloud: организация, облако, каталог) и создать отдельный каталог или проект для учёбы
- [ ] Для своего проекта расписать, что делать в модели IaaS, а что — в PaaS, и где проходит граница ответственности
- [ ] Найти в документации провайдера список зон доступности и определить, какие ресурсы зональные, а какие региональные
- [ ] Посчитать на калькуляторе стоимость: две ВМ, managed PostgreSQL, 100 ГБ в S3 и сравнить с прерываемыми ВМ
- [ ] Повесить метки (labels) на все ресурсы учебного проекта и научиться находить их по меткам

### Чем PaaS отличается от SaaS?
- [ ] Ничем
- [x] PaaS — платформа для запуска и хранения вашего (базы, Kubernetes), SaaS — готовое приложение для конечных пользователей

- [ ] PaaS — это физические серверы
> Примеры SaaS — почта, GitLab.com, офисные пакеты.

### Что такое vendor lock-in?
- [ ] Блокировка аккаунта
- [x] Сильная зависимость от конкретного провайдера: его уникальные сервисы и API затрудняют переезд

- [ ] Ограничение по числу ВМ
> Чем выше по модели (PaaS, serverless), тем сильнее привязка.

### Что такое гибридное облако?
- [ ] Облако с ВМ и контейнерами
- [x] Сочетание своей инфраструктуры и публичного облака, связанных сетью
