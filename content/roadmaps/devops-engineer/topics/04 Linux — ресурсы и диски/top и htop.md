# top и htop

`top` есть на любом сервере, `htop` — его удобная цветная версия (обычно её нужно доустановить). Это первое, что открывают, когда «сервер тормозит». Важно не просто запустить их, а понимать каждую цифру в шапке.

## Шапка top

```
top - 14:02:11 up 12 days,  3:41,  2 users,  load average: 3.15, 2.80, 1.95
Tasks: 213 total,   2 running, 211 sleeping,   0 stopped,   0 zombie
%Cpu(s): 35.2 us,  6.1 sy,  0.0 ni, 40.3 id, 17.9 wa,  0.0 hi,  0.5 si,  0.0 st
MiB Mem :   7951.2 total,    312.4 free,   4120.8 used,   3518.0 buff/cache
MiB Swap:   2048.0 total,   1980.1 free,     67.9 used.   3512.6 avail Mem
```

### Load Average

Три числа — средняя нагрузка за **1, 5 и 15 минут**. Нагрузка — это среднее число процессов, которые **выполняются или ждут CPU** (состояние R), плюс процессы в **непрерываемом ожидании ввода-вывода** (состояние D).

- Сравнивайте с числом ядер (`nproc`): на 4 ядрах LA = 4 — процессор занят полностью, LA = 8 — процессы стоят в очереди.
- Смотрите на тренд: `1.0, 3.0, 6.0` — нагрузка спадает, `6.0, 3.0, 1.0` — растёт.
- Высокий LA при большом `id` (простое CPU) и высоком `wa` — проблема с диском или сетевым хранилищем, а не с процессором.

### Строка %Cpu(s)

| Поле | Что значит | Когда тревожно |
| --- | --- | --- |
| **us** | Пользовательский код (приложения) | Приложение упирается в CPU |
| **sy** | Код ядра (системные вызовы, драйверы) | Много переключений контекста, сетевая нагрузка, проблемы драйверов |
| ni | Процессы с повышенным nice | — |
| **id** | Простой | Низкий id — CPU загружен |
| **wa** | Ожидание ввода-вывода (I/O wait) | Высокий — медленный или перегруженный диск |
| hi | Аппаратные прерывания | — |
| **si** | Программные прерывания (softirq): обработка сетевых пакетов | Высокий — очень много сетевого трафика |
| **st** | Steal — время, которое гипервизор отдал другим ВМ | Высокий — «соседи» по облаку забирают ваш CPU |

### Память

`free` — совсем свободная память, `buff/cache` — кэш файлов (его можно освободить), `avail Mem` — сколько реально доступно приложениям. Подробно — в следующей теме.

## Колонки процессов

| Колонка | Значение |
| --- | --- |
| PR / NI | Приоритет / nice |
| VIRT | Виртуальная память процесса |
| **RES** | Резидентная память — реально занятая в ОЗУ |
| SHR | Разделяемая память (библиотеки и т. п.) |
| S | Состояние: R, S, D, Z, T |
| **%CPU** | Доля CPU; на многоядерной машине может быть больше 100% (200% — два ядра заняты полностью) |
| %MEM | Доля RES от всей ОЗУ |
| TIME+ | Сколько процессорного времени израсходовано |

## Клавиши top

| Клавиша | Действие |
| --- | --- |
| `P` | Сортировка по CPU |
| `M` | Сортировка по памяти |
| `1` | Показать каждое ядро отдельно |
| `c` | Полная командная строка |
| `k` | Отправить сигнал процессу (kill) |
| `r` | Изменить nice (renice) |
| `u` | Процессы одного пользователя |
| `q` | Выход |

```bash
top -o %MEM          # сразу сортировать по памяти
top -b -n 1 | head -20   # один снимок в текстовом виде — для скриптов и отчётов
top -p 1234          # следить за одним процессом
```

## htop

Всё то же, но удобнее: цветные полосы загрузки каждого ядра, прокрутка, мышь.

| Клавиша | Действие |
| --- | --- |
| F6 или `<` `>` | Выбрать колонку сортировки |
| F5 | Дерево процессов |
| F4 | Фильтр по имени |
| F3 или `/` | Поиск |
| F9 | Отправить сигнал |
| F7 / F8 | Изменить nice |
| `u` | Процессы пользователя |
| Space | Отметить несколько процессов |
| `H` | Показать или скрыть потоки |

## Алгоритм «сервер тормозит»

1. `uptime` или шапка top — какой Load Average и как он меняется.
2. Строка CPU: что занято — **us** (приложение), **sy** (ядро), **wa** (диск), **st** (соседи по облаку)?
3. Память: сколько **available**, используется ли swap?
4. Сортировка по CPU (`P`), затем по памяти (`M`) — кто «виновник»?
5. Что это за процесс: `ps -fp PID`, `systemctl status PID`. Можно ли его остановить?
6. Если можно — `kill PID` (SIGTERM), если не помогло — `kill -9`. Если это важная служба — разбираться с причиной: логи, `strace`, диск.

## Практика

- [ ] Запустить `top`, расшифровать каждую цифру в шапке и записать в конспект
- [ ] Создать нагрузку на CPU (`yes > /dev/null &` или `stress-ng --cpu 2`) и посмотреть, как меняются us и Load Average; затем найти и завершить процесс прямо из top клавишей `k`
- [ ] Создать нагрузку на диск (`dd if=/dev/zero of=/tmp/big bs=1M count=3000 oflag=direct`) и найти рост `wa`
- [ ] Выполнить `top -o %MEM` и найти три самых «прожорливых» по памяти процесса
- [ ] В htop включить дерево процессов (F5) и найти родителя своего терминала

## Лаборатория

```bash setup
lab_unit() { systemctl stop "$1" 2>/dev/null; systemctl reset-failed "$1" 2>/dev/null; true; }
mkdir -p /opt/lab
cat > /opt/lab/worker <<'EOF'
#!/usr/bin/env python3
# Обработчик задач. Режим busy — грузит процессор (не дольше 10 минут), иначе спит.
import sys, time
if len(sys.argv) > 2 and sys.argv[2] == "busy":
    end = time.time() + 600
    while time.time() < end:
        pass
else:
    time.sleep(10**6)
EOF
chmod 755 /opt/lab/worker
```

### Кто грузит процессор

На сервере работают шесть одинаковых обработчиков `worker` (в списке процессов они видны как `python3`). Один из них ушёл в бесконечный цикл и съедает целое ядро процессора. Найдите **именно его** и завершите. Остальные обработчики должны продолжать работать.

```bash setup
for i in 1 2 3 4 5 6; do lab_unit lab-worker$i; done
hot=$(( RANDOM % 6 + 1 ))
echo $hot > /var/lib/lab/hot-worker
for i in 1 2 3 4 5 6; do
  mode=idle; [ $i = $hot ] && mode=busy
  systemd-run -q --unit=lab-worker$i -p User=student /opt/lab/worker $i $mode
done
sleep 2
```

```bash check
hot=$(cat /var/lib/lab/hot-worker)
[ "$(systemctl is-active lab-worker$hot)" = active ] && fail "Процесс, который грузит процессор, всё ещё работает"
for i in 1 2 3 4 5 6; do
  [ $i = $hot ] && continue
  [ "$(systemctl is-active lab-worker$i)" = active ] || fail "Остановлен лишний обработчик — worker $i работал нормально"
done
ok "остановлен worker $hot, остальные пять работают"
```

```text hint
1. Открыть интерактивный монитор процессов: по умолчанию он сортирует по загрузке процессора — виновник будет наверху.
2. Все процессы называются одинаково: включите показ полной командной строки (одна клавиша), чтобы различать их.
3. Завершить процесс можно прямо из монитора (клавиша «убить», затем PID и сигнал) или отдельной командой по PID.
```

```bash solution
top -b -n 2 -d 1 -o %CPU -c | grep -A 3 '^ *PID' | tail -3
pid=$(ps -eo pid=,pcpu=,args= --sort=-pcpu | grep '/opt/lab/worker' | head -1 | awk '{print $1}')
kill "$pid"
```

```text review
Эталон: `top` (сортировка по %CPU по умолчанию) → `c` (полная команда) → `k` → PID → Enter (SIGTERM).

- В шапке top: `load average` за 1/5/15 минут, строка `%Cpu(s)` — `us` (программы), `sy` (ядро), `wa` (ожидание диска), `st` (у вас отняла гипервизор-соседка), `id` — простой.
- Полезные клавиши: `P`/`M` — сортировка по CPU/памяти, `1` — по ядрам, `H` — потоки, `u` — процессы пользователя, `c` — полная команда.
- 100% у процесса в top — это **одно ядро**. На 4-ядерной машине процесс может показать и 400%.
- htop удобнее: дерево (`F5`), поиск (`F3`), фильтр (`F4`), сигнал выбранному процессу (`F9`).
```

### Отчёт для скрипта

Интерактивный top не годится для cron и отчётов. Сохраните в `~/top-report.txt` снимок top в **пакетном режиме**: шапку и процессы, **отсортированные по загрузке CPU**, — первые 20 строк вывода. Сейчас на сервере работает тяжёлый процесс `encoder` — в отчёте он должен оказаться вверху списка.

```bash setup
lab_unit lab-encoder-cpu
rm -f /home/student/top-report.txt
systemd-run -q --unit=lab-encoder-cpu -p User=student /opt/lab/worker encoder busy
sleep 2
```

```bash check
f=/home/student/top-report.txt
[ -s $f ] || fail "~/top-report.txt пуст или не создан"
grep -q 'load average' $f || fail "В отчёте нет шапки top (строки с load average)"
grep -qE '^\s*PID ' $f || fail "В отчёте нет списка процессов"
pid=$(systemctl show -p MainPID --value lab-encoder-cpu)
grep -A3 -E '^\s*PID ' $f | awk 'NR>1 {print $1}' | grep -qx "$pid" || fail "encoder (PID $pid) не среди первых процессов отчёта — список отсортирован не по CPU"
[ "$(wc -l < $f)" -le 25 ] || fail "В отчёте $(wc -l < $f) строк, нужны первые 20"
ok "отчёт: $(wc -l < $f) строк, encoder вверху"
```

```text hint
1. У top есть ключи: «пакетный режим» (вывод текстом, без управления клавишами), «число обновлений» и «поле для сортировки».
2. Первое обновление считает загрузку от старта процесса — надёжнее взять второе с интервалом в секунду.
3. Обрезать вывод до первых строк и сохранить в файл.
```

```bash solution
top -b -n 1 -o %CPU | head -20 > ~/top-report.txt
cat ~/top-report.txt
```

```text review
Эталон: `top -b -n 1 -o %CPU | head -20 > ~/top-report.txt`.

- `-b` — пакетный режим (без экрана и клавиш), `-n` — сколько снимков, `-d` — интервал, `-o` — поле сортировки, `-u` — пользователь, `-p` — конкретные PID.
- Так собирают «снимок при инциденте»: cron или алерт запускает `top -b -n 1`, `ps aux --sort=-%cpu`, `free -m`, `df -h` и сохраняет в файл — потом видно, что происходило в момент проблемы.
- Для истории нагрузки за сутки лучше `sar` (пакет sysstat) или мониторинг — Prometheus и node_exporter.
```

## Тест

### Что показывают три числа load average?
- [ ] Загрузку трёх процессоров
- [x] Среднюю нагрузку за 1, 5 и 15 минут: число процессов, которые выполняются или ждут CPU, плюс процессы в ожидании ввода-вывода (D)
- [ ] Процент загрузки CPU, памяти и диска
- [ ] Число пользователей, процессов и потоков
> Сравнивайте LA с числом ядер и смотрите на тренд.

### На сервере 4 ядра, load average 8.0, 7.5, 7.0. Что это значит?
- [ ] Сервер почти простаивает
- [x] Нагрузка примерно вдвое выше, чем могут обработать ядра: процессы стоят в очереди (или ждут ввод-вывод)
- [ ] Используется 8% процессора
- [ ] Нагрузка быстро снижается
> LA, равная числу ядер, — полная загрузка. Всё, что выше, — очередь.

### Что означает высокий wa в строке %Cpu(s)?
- [ ] Процессор занят приложениями
- [x] Процессор простаивает, ожидая завершения операций ввода-вывода: диск не успевает
- [ ] Высокая сетевая нагрузка
- [ ] Гипервизор забирает CPU
> Дальше смотрят `iostat -xz 1` и ищут процессы в состоянии D.

### Что показывает поле st (steal)?
- [ ] Время, украденное вирусами
- [x] Время, которое гипервизор отдал другим виртуальным машинам вместо вашей
- [ ] Время ожидания диска
- [ ] Время обработки прерываний
> Высокий steal в облаке — повод сменить тип инстанса или хост.

### Что означает si в строке CPU?
- [ ] Swap in
- [x] Время обработки программных прерываний (softirq), чаще всего — обработка сетевых пакетов
- [ ] Время в спящем режиме
- [ ] Системные вызовы
> Не путайте с колонкой si у vmstat — там это swap in.

### Какая колонка top показывает, сколько физической памяти реально занимает процесс?
= RES
> VIRT — виртуальная память, она почти всегда намного больше.

### Почему у процесса в top может быть %CPU = 250%?
- [ ] Это ошибка top
- [x] Процесс многопоточный и загружает сразу несколько ядер; 100% — одно ядро целиком
- [ ] Процесс разогнал процессор
- [ ] Процесс в состоянии зомби
> Клавиша `1` покажет загрузку каждого ядра отдельно.

### Какой клавишей в top отсортировать процессы по памяти?
- [ ] P
- [x] M
- [ ] S
- [ ] F
> `P` — по CPU, `M` — по памяти.

### Load average 12 на 8 ядрах, при этом id = 70% и wa = 25%. Где искать проблему?
- [ ] В приложении, которое нагружает CPU
- [x] В дисковой подсистеме или сетевом хранилище: процессы ждут ввод-вывод (состояние D), а процессор свободен
- [ ] В сети
- [ ] Это нормальная картина
> В Linux load average учитывает процессы в состоянии D.

### Как получить один снимок top в текстовом виде, например для отчёта или скрипта?
= top -b -n 1
= top -bn1
> `-b` — пакетный режим, `-n 1` — одна итерация.

### Как в htop показать процессы деревом?
- [ ] F2
- [x] F5
- [ ] F9
- [ ] F10
> F9 — отправить сигнал, F10 — выход, F2 — настройки.

### В top высокий us у одного процесса java. С чего начать?
- [x] Посмотреть, что это за процесс и его командную строку (c в top, ps -fp PID)
- [x] Проверить логи приложения и понять, нормальна ли нагрузка
- [ ] Сразу выполнить kill -9
- [ ] Перезагрузить сервер
> Сначала понять, затем действовать. Если остановить можно — сначала SIGTERM.

### Что показывает строка Tasks в top?
- [ ] Задачи cron
- [x] Сколько всего процессов и сколько из них выполняется, спит, остановлено и в состоянии зомби
- [ ] Число открытых файлов
- [ ] Число пользователей
> Ненулевое число зомби — повод посмотреть на родительские процессы.
