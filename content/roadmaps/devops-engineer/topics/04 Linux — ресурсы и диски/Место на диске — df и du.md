# Место на диске — df и du

Закончившееся место — одна из самых частых аварий: перестают писаться логи, база данных падает, деплой не может распаковать архив, Docker не может скачать образ. Алгоритм поиска виновника простой, его нужно довести до автоматизма.

## Шаг 1. df — общая картина по разделам

```bash
df -h          # размер, занято, свободно, % — по каждой смонтированной ФС
df -hT         # плюс тип файловой системы
df -h /var     # на каком разделе лежит каталог и сколько там места
```

Ищите раздел, где `Use%` близок к 100%. Обратите внимание на колонку `Mounted on`: `/var` или `/home` могут быть отдельными разделами со своим местом.

## Шаг 2. du — что именно съело место

```bash
cd /var
sudo du -sh * | sort -h                    # размер каждого элемента в текущем каталоге
sudo du -h --max-depth=1 /var | sort -h    # то же для заданного каталога
sudo du -xh --max-depth=1 / | sort -h      # -x: не уходить на другие ФС
sudo find / -xdev -type f -size +500M -exec ls -lh {} \; 2>/dev/null   # большие файлы
```

Спускайтесь в самый большой каталог и повторяйте, пока не найдёте виновника. Интерактивная альтернатива — **ncdu** (`sudo ncdu -x /`): сортировка, навигация стрелками, удаление клавишей `d`.

## Типичные виновники

| Где | Что | Как чистить |
| --- | --- | --- |
| `/var/log` | Разросшиеся логи, нет ротации | logrotate, `truncate -s 0`, удалить старые `.gz` |
| `/var/log/journal` | Журнал systemd | `journalctl --vacuum-size=500M` |
| `/var/lib/docker` | Образы, остановленные контейнеры, тома, кэш сборки | `docker system df`, `docker system prune` (осторожно с `-a` и `--volumes`) |
| `/var/cache/apt`, `/var/cache/dnf` | Кэш пакетов | `apt clean`, `dnf clean all` |
| `/boot` | Старые ядра | `apt autoremove --purge` |
| `/tmp`, домашние каталоги | Забытые дампы, архивы, бэкапы | Удалить ненужное |
| Каталог приложения | Core dumps, загрузки пользователей, кэш | Настроить очистку |

## No space left on device — чек-лист

1. **`df -h`** — действительно ли кончилось место? Если да — ищем виновника через `du`.
2. **`df -i`** — место есть, но кончились **inode** (миллионы мелких файлов). Это следующая тема.
3. **Удалённые, но открытые файлы.** `du` их уже не видит, а `df` всё ещё считает место занятым: `sudo lsof +L1`. Решение — перезапустить процесс или обрезать файл через `/proc/PID/fd/N`.
4. **Зарезервированные блоки.** ext4 по умолчанию оставляет 5% места для root. Обычный пользователь видит «нет места», а root ещё может писать. Посмотреть и изменить можно через `tune2fs -l` / `tune2fs -m 1` (на разделах с данными).
5. **Файлы под точкой монтирования.** Если в `/data` записали файлы, а потом смонтировали туда диск, старые файлы скрыты под ним, но занимают место на корневом разделе.

## Почему df и du показывают разное

- `du` считает размер **найденных файлов**, `df` — **занятые блоки** файловой системы.
- Удалённые, но открытые файлы, зарезервированные блоки, метаданные ФС и файлы под точками монтирования видит только `df`.
- Разреженные (sparse) файлы и жёсткие ссылки `du` считает иначе.

> [!tip] Не доводите до 100%
> Настройте мониторинг заполнения дисков с порогами 80% и 90% — к этому вернёмся в разделе «Мониторинг».

## Практика

- [ ] Выполнить `df -hT` и разобраться, какие разделы и файловые системы есть в системе
- [ ] Найти пять самых больших каталогов на корневом разделе через `du -xh --max-depth=1 / | sort -h` и спуститься в самый большой
- [ ] Установить `ncdu` и пройтись по системе
- [ ] Найти файлы больше 100 МБ через `find -size`
- [ ] Воспроизвести «удалённый, но открытый файл»: создать большой файл, открыть его процессом, удалить, сравнить `df` и `du`, найти через `lsof +L1`
- [ ] Посмотреть, сколько места занимают журнал (`journalctl --disk-usage`) и Docker (`docker system df`), если он установлен

## Лаборатория

```bash setup
export LVM_SUPPRESS_FD_WARNINGS=1
DISKS=/var/lib/lab-disks
# Убрать всё, что могли оставить прошлые задачи с дисками: монтирования, массивы, тома, loop-устройства
lab_disks_reset() {
  for m in $(findmnt -rn -o TARGET | grep -E '^/mnt/(data|app|busy|raid|xfs-lab|ramcache|lab-[a-z]+)$|^/srv/overlay/merged$' | sort -r); do umount -l "$m"; done
  mdadm --stop --scan >/dev/null 2>&1
  for vg in data labvg; do vgremove -qq -ff "$vg" >/dev/null 2>&1; done
  for l in $(losetup -nO NAME,BACK-FILE 2>/dev/null | awk -v d="$DISKS" 'index($2, d) == 1 {print $1}'); do
    pvremove -qq -ff "$l" >/dev/null 2>&1; wipefs -qa "$l" >/dev/null 2>&1; losetup -d "$l"
  done
  rm -f /dev/lab-*; rm -rf "$DISKS"; mkdir -p "$DISKS"
  sed -i -E '\#[[:space:]]/mnt/(data|app|raid|xfs-lab|ramcache)[[:space:]]#d' /etc/fstab
  true
}
# lab_disk имя размер → пустой «диск» /dev/lab-имя (ссылка на loop-устройство)
lab_disk() {
  truncate -s "$2" "$DISKS/$1.img"
  ln -sf "$(losetup -f --show "$DISKS/$1.img")" "/dev/lab-$1"
}
```

### Какой каталог съел место

Раздел с данными заполняется. В `/srv/data` четыре каталога: `logs`, `backups`, `cache`, `uploads`. Узнайте, какой из них **занимает больше всего места на диске**, и запишите его имя (только имя каталога) в `~/biggest.txt`.

```bash setup
rm -rf /srv/data /home/student/biggest.txt
sizes=($(shuf -n 4 -e 20 35 50 65 80 95))
i=0
for n in logs backups cache uploads; do
  mkdir -p /srv/data/$n/sub
  s=${sizes[$i]}; i=$((i + 1))
  fallocate -l ${s}M /srv/data/$n/sub/part1.bin
  fallocate -l $(( (RANDOM % 5) + 1 ))M /srv/data/$n/part2.bin
done
# много мелких файлов: по количеству лидер другой, чем по объёму
for i in $(seq 1 300); do echo "$i" > /srv/data/logs/small-$i.log; done
du -s /srv/data/* | sort -n | tail -1 | awk '{print $2}' | xargs basename > /var/lib/lab/biggest
```

```bash check
want=$(cat /var/lib/lab/biggest)
[ -f /home/student/biggest.txt ] || fail "Нет ~/biggest.txt"
got=$(tr -d '[:space:]' < /home/student/biggest.txt); got=${got%/}; got=${got##*/}
[ "$got" = "$want" ] || fail "В ~/biggest.txt «$got» — этот каталог занимает не больше всех"
ok "больше всех занимает /srv/data/$want ($(du -sh /srv/data/$want | cut -f1))"
```

```text hint
1. Посчитать суммарный размер каждого каталога первого уровня (не каждого файла): у du есть ключ «итог по аргументу» и ключ «в удобных единицах».
2. Отсортировать результат по размеру — у sort есть режим, который понимает суффиксы K, M, G.
```

```bash solution
du -sh /srv/data/* | sort -h
du -s /srv/data/* | sort -n | tail -1 | awk '{print $2}' | xargs basename > ~/biggest.txt
```

```text review
Эталон: `du -sh /srv/data/* | sort -h`.

- `df` — сколько занято и свободно на **разделе**, `du` — сколько занимают **файлы и каталоги**. Сначала `df -h` (какой раздел полон), потом `du` (кто его съел).
- По всему разделу: `du -xh --max-depth=1 / | sort -h` (`-x` — не уходить на другие разделы) и спускаться в самый большой каталог. Удобнее — `ncdu -x /`.
- `du` считает занятые блоки, а `ls -l` — длину файла. Разреженный файл (виртуальный диск, `truncate`) по `ls` может весить гигабайты, а по `du` — ничего.
```

### Резерв на диске с данными

На отдельном диске для данных, смонтированном в `/mnt/lab-data`, ext4 по умолчанию держит **5% места в резерве** для root — на системном разделе это спасает, а на диске только с данными просто теряется. Уберите резерв полностью, **не отмонтируя** диск и не теряя данные.

```bash setup
lab_disks_reset
lab_disk data 200M
mkfs.ext4 -q -F /dev/lab-data
mkdir -p /mnt/lab-data
mount /dev/lab-data /mnt/lab-data
echo "важные данные" > /mnt/lab-data/keep.txt
```

```bash check
dev=$(findmnt -no SOURCE /mnt/lab-data) || fail "/mnt/lab-data не смонтирован"
grep -q "важные данные" /mnt/lab-data/keep.txt 2>/dev/null || fail "Пропали данные с диска"
r=$(tune2fs -l "$dev" | awk -F: '/^Reserved block count/ {gsub(/ /, "", $2); print $2}')
[ "$r" = 0 ] || fail "Зарезервировано блоков: $r"
ok "резерв убран: $(df -h --output=size,avail /mnt/lab-data | tail -1)"
```

```text hint
1. Узнать устройство, смонтированное в каталог.
2. У файловых систем ext есть утилита для изменения параметров уже созданной ФС, в том числе процента зарезервированных блоков. Работает на смонтированной ФС.
3. Сравнить «доступно» в df до и после.
```

```bash solution
dev=$(findmnt -no SOURCE /mnt/lab-data)
df -h /mnt/lab-data
sudo tune2fs -m 0 "$dev"
df -h /mnt/lab-data
```

```text review
Эталон: `sudo tune2fs -m 0 <устройство>`.

- Резерв нужен на **корневом** разделе: когда пользователи забили диск, root и системные службы ещё могут писать логи и войти починить. Поэтому в df `Used + Avail` меньше `Size`.
- На диске 2 ТБ 5% — это 100 ГБ. Для дисков с данными, бэкапами, Docker-образами резерв уменьшают до 0–1%.
- `tune2fs -l <устройство>` — все параметры ext4: число inode, резерв, счётчик монтирований, время проверки. Для xfs резерва нет.
```

## Тест

### Какая команда показывает свободное место по всем смонтированным файловым системам в удобном виде?
= df -h
> Добавьте `-T`, чтобы увидеть тип ФС.

### Как узнать размер каждого файла и каталога в текущем каталоге и отсортировать их?
- [ ] df -h | sort
- [x] du -sh * | sort -h
- [ ] ls -lh | sort -n
- [ ] find . -size | sort
> `sort -h` правильно сортирует размеры вида 512K, 3.2M, 1.5G.

### Какой порядок поиска виновника, если кончилось место?
- [x] Сначала df -h, чтобы найти заполненный раздел, затем du по каталогам этого раздела
- [ ] Сначала удалить /tmp
- [ ] Сначала перезагрузить сервер
- [ ] Сразу выполнить rm -rf /var/log/*
> Удаление наугад может уничтожить важные данные и не решить проблему.

### Зачем в du -xh --max-depth=1 / указывают опцию -x?
- [ ] Чтобы показывать скрытые файлы
- [x] Чтобы не переходить на другие файловые системы (смонтированные диски, /proc и т. п.)
- [ ] Чтобы ускорить сортировку
- [ ] Чтобы считать в байтах
> Иначе в результат попадут другие разделы, и картина исказится.

### df показывает 100% заполнения, а du находит файлов на 60%. Какие причины возможны?
- [x] Удалённые файлы, которые всё ещё открыты процессами
- [x] Файлы, скрытые под точкой монтирования
- [x] Зарезервированные блоки и метаданные файловой системы
- [ ] Ошибка в команде df
> Удалённые открытые файлы находит `lsof +L1`.

### При записи файла возникает No space left on device, но df -h показывает 40% свободного места. Что проверить в первую очередь?
- [ ] Права на каталог
- [x] Свободные inode: df -i
- [ ] Свободную память: free -h
- [ ] Нагрузку на CPU
> Если IUse% = 100%, место «съели» миллионы мелких файлов.

### Как найти все файлы больше 500 МБ на корневом разделе?
- [ ] du -s / +500M
- [x] find / -xdev -type f -size +500M
- [ ] df -h --size=500M
- [ ] ls -R / | grep 500M
> `-xdev` не уходит на другие файловые системы.

### Как безопасно посмотреть и почистить место, занятое Docker?
- [ ] rm -rf /var/lib/docker
- [x] Посмотреть docker system df и удалить ненужное через docker system prune, понимая, что именно удаляется
- [ ] Удалить каталог /var/lib/docker/overlay2 вручную
- [ ] Переустановить Docker
> Ручное удаление файлов в /var/lib/docker ломает Docker. Флаги `-a` и `--volumes` удаляют больше — используйте их осознанно.

### Почему обычному пользователю на ext4 пишется «нет места», хотя root ещё может создавать файлы?
- [ ] У root отдельный диск
- [x] ext4 резервирует часть блоков (по умолчанию 5%) для root
- [ ] Пользователь превысил квоту памяти
- [ ] Из-за прав 644
> Резерв помогает системе и root работать при заполненном диске. Изменить: `tune2fs -m`.

### Какая интерактивная утилита удобна для поиска того, что занимает место?
= ncdu
> Работает в терминале и позволяет удалять найденное прямо из интерфейса.

### Как освободить место, занятое журналом systemd, оставив последние 500 МБ?
- [ ] rm -rf /var/log/journal
- [x] journalctl --vacuum-size=500M
- [ ] systemctl clean journal
- [ ] logrotate journal
> Постоянный лимит задаётся `SystemMaxUse=` в journald.conf.

### Как очистить кэш скачанных пакетов в Ubuntu?
= sudo apt clean
= apt clean
> В RHEL-семействе — `dnf clean all`.
