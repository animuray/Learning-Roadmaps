# Экспортеры

Большинство программ не умеют отдавать метрики в формате Prometheus. **Экспортер** — небольшой сервис-посредник: собирает данные системы (из `/proc`, SQL-запросами, через API) и отдаёт их на HTTP `/metrics`. Prometheus опрашивает экспортер как обычную цель.

```
 Linux (/proc, /sys) ──► node_exporter :9100/metrics ◄── Prometheus
 PostgreSQL (SQL)    ──► postgres_exporter :9187     ◄──
 Docker (cgroups)    ──► cAdvisor :8080              ◄──
 https://site.ru     ◄── blackbox_exporter :9115/probe ◄──
```

## node_exporter — метрики сервера

Ставится на **каждый** Linux-сервер, слушает порт **9100**. Отдаёт метрики CPU, памяти, дисков, файловых систем, сети, load average, systemd и многого другого.

```bash
wget https://github.com/prometheus/node_exporter/releases/download/v1.10.2/node_exporter-1.10.2.linux-amd64.tar.gz
tar xzf node_exporter-1.10.2.linux-amd64.tar.gz
sudo mv node_exporter-1.10.2.linux-amd64/node_exporter /usr/local/bin/
sudo useradd --system --no-create-home --shell /usr/sbin/nologin node_exporter
```

`/etc/systemd/system/node_exporter.service`:

```ini
[Unit]
Description=Prometheus Node Exporter
After=network-online.target

[Service]
User=node_exporter
ExecStart=/usr/local/bin/node_exporter --collector.systemd --collector.processes
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now node_exporter
curl -s localhost:9100/metrics | grep node_load
```

Ключевые метрики:

| Метрика | Что | Тип |
| --- | --- | --- |
| `node_cpu_seconds_total{mode="idle"}` | Время CPU по режимам | counter |
| `node_load1`, `node_load5` | Load average | gauge |
| `node_memory_MemAvailable_bytes`, `node_memory_MemTotal_bytes` | Память | gauge |
| `node_filesystem_avail_bytes`, `node_filesystem_size_bytes` | Место на ФС | gauge |
| `node_disk_io_time_seconds_total` | Занятость диска | counter |
| `node_network_receive_bytes_total` | Трафик | counter |
| `node_systemd_unit_state` | Состояние юнитов (с `--collector.systemd`) | gauge |

**Textfile collector** — способ отдать свои метрики через node_exporter: скрипт (например, бэкап по cron) пишет файл `*.prom` в каталог `--collector.textfile.directory`, и node_exporter публикует его:

```
backup_last_success_timestamp_seconds 1764230400
```

Алерт: `time() - backup_last_success_timestamp_seconds > 86400 * 1.5`.

В Docker node_exporter запускают с `--net=host --pid=host` и монтированием `/` хоста в режиме только чтения с `--path.rootfs`.

## postgres_exporter

Порт **9187**. Подключается к базе и отдаёт метрики из `pg_stat_*`:

```bash
docker run -d -p 9187:9187 \
  -e DATA_SOURCE_NAME="postgresql://postgres_exporter:secret@db:5432/postgres?sslmode=disable" \
  quay.io/prometheuscommunity/postgres-exporter
```

- Пользователь с минимальными правами: встроенная роль **`pg_monitor`** (`GRANT pg_monitor TO postgres_exporter;`), не суперпользователь.
- Важные метрики: `pg_up`, число соединений (`pg_stat_activity_count`), транзакции (`pg_stat_database_xact_commit`), размер баз, блокировки, отставание репликации, deadlocks.
- Свои запросы — через файл запросов (`--extend.query-path`) или отдельный sql_exporter.

## Контейнеры: cAdvisor и kube-state-metrics

- **cAdvisor** (Container Advisor, Google) — использование ресурсов **контейнерами**: CPU, память, сеть, диск по каждому контейнеру (`container_cpu_usage_seconds_total`, `container_memory_working_set_bytes`). В Kubernetes cAdvisor встроен в **kubelet** — отдельно ставить не нужно.
- **kube-state-metrics** — **состояние объектов** Kubernetes из API: сколько реплик желаемо и доступно, перезапуски контейнеров, поды в Pending, статусы Job (`kube_deployment_status_replicas_available`, `kube_pod_container_status_restarts_total`).
- Разница: cAdvisor — «сколько ресурсов съел контейнер», kube-state-metrics — «что думает Kubernetes о своих объектах».
- В `kube-prometheus-stack` всё это уже включено вместе с node_exporter (DaemonSet).

## blackbox_exporter — проверки снаружи

Порт **9115**. Сам ничего не мониторит — по запросу Prometheus **проверяет цель** по HTTP(S), TCP, ICMP, DNS, gRPC:

```yaml
scrape_configs:
  - job_name: blackbox-http
    metrics_path: /probe
    params:
      module: [http_2xx]
    static_configs:
      - targets:
          - https://example.com
          - https://api.example.com/health
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: blackbox:9115
```

Метрики: `probe_success` (1/0), `probe_duration_seconds`, `probe_http_status_code`, **`probe_ssl_earliest_cert_expiry`** — для алерта об истечении сертификата.

## Другие экспортеры

| Экспортер | Что мониторит |
| --- | --- |
| nginx-prometheus-exporter | Nginx (stub_status) |
| mysqld_exporter | MySQL/MariaDB |
| redis_exporter | Redis/Valkey |
| kafka_exporter, RabbitMQ (встроенный плагин prometheus) | Очереди |
| windows_exporter | Windows-серверы |
| snmp_exporter | Сетевое оборудование |
| process-exporter | Отдельные процессы |

Многие современные программы (Traefik, Grafana, etcd, CoreDNS, Argo CD, сам Kubernetes) отдают `/metrics` **сами** — экспортер не нужен.

## Безопасность

- Метрики раскрывают много о системе. Не открывайте порты экспортеров в интернет: файрвол только для IP Prometheus, внутренняя сеть.
- Экспортеры поддерживают TLS и basic auth через `--web.config.file`.
- Пароли к базам — в переменных окружения или файлах с ограниченными правами, не в аргументах командной строки (видны в `ps`).

## Лаборатория

node_exporter установлен из пакетов (служба `prometheus-node-exporter`, порт 9100). Его **textfile collector** читает файлы `*.prom` из каталога `/var/lib/prometheus/node-exporter/` — так свои метрики отдают скрипты и cron-задачи.

```bash lib
# Prometheus 2.45 из пакетов Ubuntu: служба prometheus (порт 9090), node-exporter (9100), alertmanager (9093).
# Учебное приложение shop-app отдаёт метрики на 127.0.0.1:8099/metrics: счётчики растут с постоянной скоростью.
lab_shop_exporter() {
  [ "$(systemctl is-active lab-shop-exporter 2>/dev/null)" = active ] && return
  mkdir -p /opt/lab
  cat > /opt/lab/shop-exporter.py <<'EOF'
import math, time
from http.server import BaseHTTPRequestHandler, HTTPServer
START = time.time()
RATES = {('/api', '200'): 10, ('/api', '500'): 1, ('/login', '200'): 2, ('/login', '404'): 0.5}
BUCKETS = [('0.1', 5), ('0.25', 8), ('0.5', 10), ('1', 11.5), ('+Inf', 13.5)]
class H(BaseHTTPRequestHandler):
    def do_GET(self):
        t = time.time() - START
        out = ['# HELP http_requests_total Requests by path and status', '# TYPE http_requests_total counter']
        for (p, s), r in RATES.items():
            out.append(f'http_requests_total{{path="{p}",status="{s}"}} {r * t:.3f}')
        out += ['# HELP request_duration_seconds Request latency', '# TYPE request_duration_seconds histogram']
        for le, r in BUCKETS:
            out.append(f'request_duration_seconds_bucket{{le="{le}"}} {r * t:.3f}')
        out += [f'request_duration_seconds_sum {3 * t:.3f}', f'request_duration_seconds_count {13.5 * t:.3f}',
                '# HELP queue_size Orders waiting in queue', '# TYPE queue_size gauge', f'queue_size {int(50 + 40 * math.sin(t / 60))}']
        body = ("\n".join(out) + "\n").encode()
        self.send_response(200); self.send_header("Content-Type", "text/plain; version=0.0.4"); self.end_headers(); self.wfile.write(body)
    def log_message(self, *a): pass
HTTPServer(("127.0.0.1", 8099), H).serve_forever()
EOF
  systemctl reset-failed lab-shop-exporter 2>/dev/null
  systemd-run -q --unit=lab-shop-exporter python3 /opt/lab/shop-exporter.py
}
# lab_prom_base [с_shop] — исходный prometheus.yml (prometheus + node; с аргументом — и shop-app), правила из /etc/prometheus/rules
lab_prom_base() {
  pkill -u student -f 'ssh .*-L *([^ ]*:)?9090:' 2>/dev/null
  mkdir -p /etc/prometheus/rules
  cat > /etc/prometheus/prometheus.yml <<'EOF'
global:
  scrape_interval: 15s
  evaluation_interval: 15s

alerting:
  alertmanagers:
    - static_configs:
        - targets: ['localhost:9093']

rule_files: []

scrape_configs:
  - job_name: prometheus
    scrape_interval: 5s
    static_configs:
      - targets: ['localhost:9090']
  - job_name: node
    static_configs:
      - targets: ['localhost:9100']
EOF
  if [ -n "$1" ]; then
    printf '  - job_name: shop-app\n    scrape_interval: 5s\n    static_configs:\n      - targets: ["127.0.0.1:8099"]\n' >> /etc/prometheus/prometheus.yml
    sed -i 's#^rule_files: \[\]#rule_files:\n  - /etc/prometheus/rules/*.yml#' /etc/prometheus/prometheus.yml
  fi
  chown root:root /etc/prometheus/prometheus.yml; chmod 644 /etc/prometheus/prometheus.yml
  sed -i 's/^ARGS=.*/ARGS="--web.enable-lifecycle"/' /etc/default/prometheus
  systemctl enable -q prometheus prometheus-node-exporter 2>/dev/null
  systemctl restart prometheus-node-exporter prometheus
  for i in $(seq 40); do curl -s localhost:9090/-/ready | grep -qi ready && break; sleep 0.25; done
}
# lab_promq 'запрос' [время] — значение запроса через HTTP API (JSON)
lab_promq() { curl -s --get localhost:9090/api/v1/query --data-urlencode "query=$1" ${2:+--data-urlencode "time=$2"}; }
# lab_promcmp файл_с_запросом 'эталонный запрос' — сравнить результаты в один момент времени
lab_promcmp() {
  python3 - "$1" "$2" <<'EOF'
import json, sys, time, urllib.parse, urllib.request
path, ref = sys.argv[1], sys.argv[2]
try:
    q = open(path).read().strip()
except OSError:
    print(f"✗ Нет файла {path}"); sys.exit(1)
if not q:
    print(f"✗ Файл {path} пуст"); sys.exit(1)
t = time.time()
def run(query):
    u = "http://localhost:9090/api/v1/query?" + urllib.parse.urlencode({"query": query, "time": t})
    try:
        d = json.load(urllib.request.urlopen(u, timeout=10))
    except urllib.error.HTTPError as e:
        d = json.load(e)
    if d.get("status") != "success":
        return None, d.get("error", "ошибка")
    res = d["data"]["result"]
    if d["data"]["resultType"] == "scalar":
        return {(): float(res[1])}, None
    return {tuple(sorted((k, v) for k, v in r["metric"].items() if k != "__name__")): float(r["value"][1]) for r in res}, None
got, err = run(q)
if got is None:
    print(f"✗ Prometheus не может выполнить запрос: {err}"); sys.exit(1)
want, _ = run(ref)
if not want:
    print("✗ Данных ещё мало — подождите полминуты и проверьте снова"); sys.exit(1)
if set(got) != set(want):
    print(f"✗ Запрос возвращает не тот набор рядов: {len(got)} шт. с метками {sorted(dict(k) for k in got)[:3]}"); sys.exit(1)
for k, v in want.items():
    if abs(got[k] - v) > max(abs(v) * 0.03, 1e-6):
        print(f"✗ Значение {got[k]:.4g} для {dict(k) or 'результата'} неверное"); sys.exit(1)
print("✓ " + "; ".join(f"{dict(k) or 'итог'}: {v:.4g}" for k, v in sorted(got.items())))
EOF
}
```

### Метрика из скрипта бэкапа

Скрипт `~/backup.sh` делает бэкап. Допишите его так, чтобы при **успешном** завершении он через textfile collector публиковал метрики:

- `backup_last_success_timestamp_seconds` — время последнего успешного бэкапа (Unix-время, секунды);
- `backup_size_bytes` — размер архива `/tmp/lab-backup.tar.gz` в байтах.

Файл метрик — `/var/lib/prometheus/node-exporter/backup.prom`, записывать его нужно **атомарно** (через временный файл и переименование), чтобы node_exporter не прочитал его наполовину. Запустите скрипт — метрики должны появиться в `http://localhost:9100/metrics`.

```bash setup
systemctl is-active -q prometheus-node-exporter || systemctl start prometheus-node-exporter
rm -f /var/lib/prometheus/node-exporter/backup.prom /tmp/lab-backup.tar.gz
chmod 1777 /var/lib/prometheus/node-exporter 2>/dev/null || { mkdir -p /var/lib/prometheus/node-exporter; chmod 1777 /var/lib/prometheus/node-exporter; }
cat > /home/student/backup.sh <<'EOF'
#!/bin/bash
set -euo pipefail
# «Бэкап»: архив документации bash
tar -czf /tmp/lab-backup.tar.gz -C /usr/share/doc bash
echo "backup ok"
EOF
chmod 755 /home/student/backup.sh && chown student:student /home/student/backup.sh
```

```bash check
f=/var/lib/prometheus/node-exporter/backup.prom
grep -qE 'mv |rename' /home/student/backup.sh || fail "Скрипт пишет файл метрик не атомарно (нет переименования временного файла)"
rm -f $f /tmp/lab-backup.tar.gz
su - student -c '~/backup.sh' >/dev/null 2>&1 || fail "~/backup.sh завершается с ошибкой"
[ -f $f ] || fail "После запуска скрипта нет $f"
m=$(curl -s localhost:9100/metrics)
ts=$(echo "$m" | awk '/^backup_last_success_timestamp_seconds/ {print $2}')
[ -n "$ts" ] || fail "В метриках node_exporter нет backup_last_success_timestamp_seconds"
now=$(date +%s); ts=$(python3 -c 'import sys; print(int(float(sys.argv[1])))' "$ts")
[ $((now - ts)) -lt 120 ] && [ $((now - ts)) -ge 0 ] || fail "backup_last_success_timestamp_seconds = $ts — это не текущее Unix-время в секундах"
sz=$(echo "$m" | awk '/^backup_size_bytes/ {print $2}'); sz=$(python3 -c 'import sys; print(int(float(sys.argv[1])))' "${sz:-0}")
[ "$sz" = "$(stat -c %s /tmp/lab-backup.tar.gz)" ] || fail "backup_size_bytes = ${sz:-нет}, а архив весит $(stat -c %s /tmp/lab-backup.tar.gz) байт"
ok "метрики бэкапа видны в node_exporter: время $ts, размер $sz"
```

```text hint
1. Формат метрик — текстовый: необязательные строки HELP и TYPE, затем «имя значение» по строке на метрику.
2. Время в секундах Unix — у date есть формат для этого; размер файла — у stat.
3. Записать во временный файл в том же каталоге, затем переименовать в итоговое имя — переименование в пределах одной ФС атомарно.
```

```bash solution
cat >> ~/backup.sh <<'EOF'

# метрики для Prometheus через textfile collector node_exporter
dir=/var/lib/prometheus/node-exporter
tmp=$(mktemp "$dir/backup.prom.XXXXXX")
cat > "$tmp" <<METRICS
# HELP backup_last_success_timestamp_seconds Время последнего успешного бэкапа
# TYPE backup_last_success_timestamp_seconds gauge
backup_last_success_timestamp_seconds $(date +%s)
# HELP backup_size_bytes Размер последнего бэкапа
# TYPE backup_size_bytes gauge
backup_size_bytes $(stat -c %s /tmp/lab-backup.tar.gz)
METRICS
chmod 644 "$tmp"
mv "$tmp" "$dir/backup.prom"
EOF
~/backup.sh
curl -s localhost:9100/metrics | grep '^backup_'
```

```text review
Эталон — в «Решении»: временный файл в том же каталоге + `mv`.

- Textfile collector — самый простой способ мониторить cron-задачи и скрипты, у которых нет своего HTTP-сервера. Алерт: `time() - backup_last_success_timestamp_seconds > 26 * 3600` — «бэкап не делался больше суток».
- Метрику «последний **успех**» пишут только при успехе: при падении скрипта она устареет, и алерт сработает. Метрика «статус = 0/1» хуже — упавший до записи скрипт ничего не обновит.
- Готовые экспортеры для всего популярного: postgres_exporter, redis_exporter, nginx-prometheus-exporter, blackbox_exporter (проверка HTTP/TCP/ICMP снаружи и срока сертификатов).
```

- [x] Метрики раскрывают сведения о системе и могут использоваться для разведки; доступ должен быть только у Prometheus
- [ ] Это увеличит кардинальность
- [ ] Prometheus перестанет их опрашивать
> Файрвол, внутренняя сеть, TLS и basic auth через web.config.file.

### Как node_exporter запускают в Docker для мониторинга хоста?
- [ ] Как обычный контейнер в изолированной сети
- [x] С сетью и PID-пространством хоста и смонтированной корневой ФС хоста только для чтения с флагом --path.rootfs
- [ ] С привилегиями root и записью в /
- [ ] Только внутри Kubernetes
> Иначе он увидит метрики контейнера, а не сервера.
