# Первичная настройка сервера

Новый сервер с белым IP-адресом начинают сканировать и перебирать пароли SSH уже через несколько минут после запуска. Поэтому у каждого сервера есть обязательный минимум настройки. Позже вы будете делать это плейбуком Ansible, но сначала нужно сделать всё руками и понять каждый шаг.

## Шаг 1. Обновить систему

```bash
sudo apt update && sudo apt upgrade -y          # Debian/Ubuntu
sudo dnf upgrade -y                             # RHEL-семейство
sudo apt install -y unattended-upgrades         # автоматические обновления безопасности (Ubuntu)
sudo dpkg-reconfigure -plow unattended-upgrades
```

Заодно задайте имя хоста и часовой пояс:

```bash
sudo hostnamectl set-hostname web1
sudo timedatectl set-timezone Europe/Moscow
timedatectl            # проверить, что синхронизация времени (NTP) включена
```

## Шаг 2. Пользователь с sudo

Работать под root постоянно нельзя: одна опечатка — и система уничтожена, а в журналах не видно, кто что сделал.

```bash
sudo adduser deploy                 # Debian/Ubuntu (интерактивно, с паролем)
sudo usermod -aG sudo deploy        # в RHEL-семействе — группа wheel
```

## Шаг 3. Вход по SSH-ключу

На **своём** компьютере:

```bash
ssh-keygen -t ed25519 -C "deploy@laptop"     # если ключа ещё нет
ssh-copy-id deploy@203.0.113.10
ssh deploy@203.0.113.10                      # должно пустить без пароля
```

## Шаг 4. Запретить вход по паролю и под root

Вместо правки основного файла создайте отдельный drop-in:

```bash
sudo tee /etc/ssh/sshd_config.d/00-hardening.conf <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
EOF
sudo sshd -t                                        # проверить синтаксис
sudo sshd -T | grep -Ei 'passwordauth|permitroot'   # итоговые значения
sudo systemctl reload ssh                           # в RHEL: sshd
```

> [!important] Почему файл начинается с 00
> В sshd_config для каждого параметра действует **первое** найденное значение. Файлы из `sshd_config.d/` подключаются в алфавитном порядке в начале конфига. В облачных образах часто есть `50-cloud-init.conf` с `PasswordAuthentication yes`, и если назвать свой файл `99-…`, значение из cloud-init победит. Поэтому проверяйте итог через `sshd -T`.

> [!warning] Не закройте себе доступ
> Не выходите из текущей SSH-сессии. Откройте **второй терминал** и убедитесь, что вход по ключу работает, а по паролю и под root — нет. Только после этого закрывайте первую сессию.

Дополнительно можно ограничить, кто вообще может входить: `AllowUsers deploy` или `AllowGroups sshusers`.

## Шаг 5. Файрвол

Принцип: **запретить всё входящее**, открыть только нужное.

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH            # или: sudo ufw allow 22/tcp — ДО включения!
sudo ufw allow 80,443/tcp         # если это веб-сервер
sudo ufw enable
sudo ufw status verbose
sudo ufw allow from 10.0.0.0/24 to any port 5432 proto tcp   # доступ к БД только из внутренней сети
```

В RHEL-семействе вместо ufw используется **firewalld**: `firewall-cmd --permanent --add-service=ssh && firewall-cmd --reload`. Под капотом оба работают через netfilter (iptables/nftables) — подробнее в разделе «Сети».

В облаке есть ещё **группы безопасности** провайдера — файрвол перед сервером. Хорошая практика — закрывать порты и там, и на сервере.

## Шаг 6. Проверить результат

```bash
sudo ss -tulpn                  # какие порты слушаются и кем
sudo ufw status
sudo grep -i "Failed password" /var/log/auth.log | tail   # попытки подбора паролей
last -n 10                      # последние входы
```

- [x] Отдельный пользователь с sudo

- [x] Файрвол: открыты только нужные порты

## Практика

- [ ] Создать ВМ (локально или в облаке) и пройти все шаги этой темы вручную
- [ ] Убедиться со второй машины, что `ssh root@сервер` и вход по паролю не работают, а вход по ключу работает
- [ ] Проверить итоговые настройки sshd через `sshd -T` и найти, какие файлы в `sshd_config.d` есть в вашем образе
- [ ] Настроить ufw: открыть только SSH и HTTP, проверить с другой машины через `nc -zv сервер 80` и `nc -zv сервер 8080`
- [ ] Через сутки посмотреть в `auth.log`, сколько было попыток подбора пароля
- [ ] Записать все шаги в конспект — потом это станет плейбуком Ansible

## Тест

### Зачем создавать отдельного пользователя с sudo вместо работы под root?
- [x] Ошибочная команда под обычным пользователем не уничтожит систему без явного sudo

- [ ] Root не может подключаться к интернету
- [ ] Под root нельзя установить пакеты
> Работа под root — частая причина аварий и плохой практики безопасности.

- [ ] Нужно перезагрузить сервер

- [ ] Файлы в sshd_config.d не читаются
- [ ] PasswordAuthentication работает только для root
> Назовите файл так, чтобы он читался первым (00-…), и проверьте итог через `sshd -T`.

### Какой командой посмотреть итоговые значения всех параметров sshd?
= sudo sshd -T
= sshd -T
> В выводе видно, какое значение реально применяется.

### Что обязательно сделать до команды ufw enable на удалённом сервере?

- [ ] Удалить iptables

- [ ] Запретить всё входящее и исходящее
