# Процессы — ps и kill

**Программа** — файл на диске. **Процесс** — запущенный экземпляр программы: код в памяти, открытые файлы, переменные окружения, владелец и состояние. Одну программу можно запустить много раз — получится много процессов.

Процессы — тема номер один по Linux на собеседованиях. Начнём с того, как их найти и остановить.

## PID, PPID и дерево процессов

- **PID** — уникальный номер процесса.
- **PPID** — PID родителя: каждый процесс кто-то запустил.
- **PID 1** — первый процесс, его запускает ядро. В современных системах это `systemd`, он — предок всех остальных.
- **UID** — от чьего имени работает процесс, это определяет его права.

```bash
pstree -p          # дерево процессов с PID
echo $$            # PID текущей оболочки
```

## ps — снимок процессов

```bash
ps aux             # все процессы всех пользователей (BSD-синтаксис)
ps -ef             # то же в стиле System V: видно PPID
ps aux --sort=-%mem | head    # самые «прожорливые» по памяти
ps -eo pid,ppid,user,%cpu,%mem,stat,cmd --sort=-%cpu | head
ps -u www-data     # процессы пользователя
ps -fp 1234        # один процесс
```

Колонки `ps aux`:

| Колонка | Значение |
| --- | --- |
| USER | Владелец |
| PID | Номер процесса |
| %CPU / %MEM | Доля процессора и памяти |
| VSZ / RSS | Виртуальная память / реально занятая в ОЗУ (КБ) — подробнее в теме «Память в Linux» |
| TTY | Терминал (`?` — процесс без терминала, например служба) |
| STAT | Состояние: R, S, D, Z, T — разберём в следующей теме |
| START / TIME | Когда запущен / сколько процессорного времени израсходовал |
| COMMAND | Команда с аргументами |

`ps` — снимок на момент запуска. Чтобы смотреть в динамике, используют `top` и `htop`.

## Найти процесс

```bash
ps aux | grep nginx       # классика (в выводе будет и сам grep)
ps aux | grep [n]ginx     # трюк: сам grep не попадёт в результат
pgrep -a nginx            # PID и команда
pgrep -u postgres         # по пользователю
pidof sshd                # PID по точному имени программы
```

## kill — отправить сигнал

`kill` не «убивает», а **отправляет сигнал**. Процесс сам решает, как на него реагировать, — кроме двух сигналов, которые нельзя перехватить.

```bash
kill 1234          # по умолчанию SIGTERM (15) — вежливая просьба завершиться
kill -15 1234      # то же явно (или kill -TERM 1234)
kill -9 1234       # SIGKILL — ядро уничтожает процесс немедленно
kill -l            # список сигналов
pkill -f "python app.py"   # по шаблону командной строки
killall nginx      # по имени программы
```

### kill -15 или kill -9

| | SIGTERM (15) | SIGKILL (9) |
| --- | --- | --- |
| Можно перехватить | Да | Нет |
| Что делает программа | Корректно завершается: дописывает данные, закрывает соединения, удаляет временные файлы | Ничего — её уничтожает ядро |
| Когда использовать | Всегда первым | Только если процесс не реагирует на SIGTERM |

После `kill -9` может остаться повреждённый файл, незавершённая транзакция или «висящий» lock-файл. Поэтому правильный порядок: `kill PID` → подождать несколько секунд → только потом `kill -9 PID`. Так же работают systemd, `docker stop` и Kubernetes: сначала SIGTERM, а SIGKILL — по истечении таймаута.

Обычный пользователь может отправлять сигналы только своим процессам, root — любым.

## Потоки

Процесс может состоять из нескольких **потоков**. Они делят память процесса. Для ядра Linux поток — почти такая же задача, как процесс.

```bash
ps -eLf | grep java    # строка на каждый поток (LWP — номер потока)
ps -T -p 1234
```

## Тест

### Чем процесс отличается от программы?
- [ ] Ничем, это синонимы
- [x] Программа — файл на диске, процесс — её запущенный экземпляр с памятью, открытыми файлами и состоянием
- [ ] Процесс — это часть программы
- [ ] Программа работает в ядре, а процесс — в пространстве пользователя
> Одну программу можно запустить много раз, и каждый запуск — отдельный процесс со своим PID.

### Что такое PPID?
- [ ] PID процесса в другой системе
- [x] PID родительского процесса
- [ ] Приоритет процесса
- [ ] Номер терминала процесса
> По цепочке PPID любой процесс можно проследить до PID 1.

### Какой процесс в современных дистрибутивах имеет PID 1?
= systemd
> Его запускает ядро. Он запускает остальные службы и «усыновляет» процессы-сироты.

### Какой сигнал отправляет kill без указания номера?
- [ ] SIGKILL (9)
- [x] SIGTERM (15)
- [ ] SIGHUP (1)
- [ ] SIGINT (2)
> SIGTERM — просьба корректно завершиться.

### Чем kill -9 отличается от kill -15?
- [x] SIGKILL (9) нельзя перехватить: ядро уничтожает процесс сразу, без корректного завершения
- [x] SIGTERM (15) программа может обработать: дописать данные, закрыть соединения и выйти
- [ ] kill -9 работает только для root
- [ ] kill -15 завершает только дочерние процессы
> Сначала всегда пробуйте SIGTERM, а SIGKILL оставьте на случай, если процесс завис.

### Почему не стоит сразу использовать kill -9?
- [ ] Он перезагружает сервер
- [x] Процесс не успеет корректно завершиться: могут остаться повреждённые файлы, незавершённые транзакции и lock-файлы
- [ ] Он не работает с потоками
- [ ] kill -9 удаляет программу с диска
> Базы данных особенно чувствительны к SIGKILL: после него часто нужна процедура восстановления.

### Как вывести все процессы всех пользователей с владельцем, потреблением CPU и памяти?
= ps aux
> Альтернатива в стиле System V — `ps -ef`; в ней видно PPID.

### Как найти PID процесса nginx, не листая весь список процессов?
- [x] pgrep nginx
- [x] pidof nginx
- [ ] kill -l nginx
- [ ] ps nginx
> `pgrep -a` покажет ещё и командную строку.

### Почему в выводе ps aux | grep nginx появляется строка с самим grep?
- [ ] Это ошибка ps
- [x] grep — тоже процесс, и в его командной строке есть слово nginx
- [ ] nginx запускает grep
- [ ] grep копирует процесс nginx
> Трюк `grep [n]ginx` или `pgrep` решает проблему.

### Что показывает колонка RSS в ps aux?
- [ ] Размер файла программы
- [x] Объём физической памяти (ОЗУ), реально занятой процессом
- [ ] Число потоков
- [ ] Процент процессора
> VSZ — виртуальная память, она почти всегда больше RSS. Подробности — в теме «Память в Linux».

### Как завершить все процессы, в командной строке которых есть «python app.py»?
- [ ] kill python app.py
- [x] pkill -f "python app.py"
- [ ] killall app.py -f
- [ ] ps -k "python app.py"
> `-f` ищет по полной командной строке, а не только по имени программы.

### Как ведут себя systemd, docker stop и Kubernetes при остановке процесса?
- [ ] Сразу отправляют SIGKILL
- [x] Отправляют SIGTERM, ждут таймаут и только потом отправляют SIGKILL
- [ ] Отправляют SIGHUP
- [ ] Перезагружают сервер
> Поэтому приложение должно уметь корректно завершаться по SIGTERM за отведённое время.

### Пользователь alice пытается выполнить kill для процесса пользователя bob и получает Operation not permitted. Почему?
- [ ] Процесс в состоянии зомби
- [x] Обычный пользователь может отправлять сигналы только своим процессам; чужим — только root
- [ ] Нужно указать -9
- [ ] kill работает только с PID меньше 1000
> Через sudo это сработает, но сначала стоит выяснить, чей это процесс и зачем он нужен.
