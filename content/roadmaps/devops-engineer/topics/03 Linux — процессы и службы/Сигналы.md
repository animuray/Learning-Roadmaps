# Сигналы

**Сигнал** — асинхронное уведомление, которое ядро доставляет процессу: «завершись», «перечитай конфиг», «тебя прервали с клавиатуры», «у тебя завершился ребёнок». Сигналы отправляют ядро, другие процессы (`kill`) и терминал (Ctrl+C).

В Linux 64 сигнала: стандартные с номерами 1–31 и сигналы реального времени 34–64. Знать нужно десяток. Список: `kill -l`.

## Главные сигналы

| № | Сигнал | Откуда берётся | Действие по умолчанию / применение |
| --- | --- | --- | --- |
| 1 | **SIGHUP** | Закрыли терминал (hang up) | Завершение. Демоны по договорённости **перечитывают конфиг** |
| 2 | **SIGINT** | Ctrl+C | Прерывание |
| 3 | SIGQUIT | Ctrl+\ | Завершение с core dump |
| 9 | **SIGKILL** | `kill -9` | Немедленное уничтожение. **Нельзя перехватить** |
| 10 | **SIGUSR1** | Пользовательский | Смысл задаёт программа: nginx переоткрывает лог-файлы |
| 12 | **SIGUSR2** | Пользовательский | Смысл задаёт программа |
| 15 | **SIGTERM** | `kill` по умолчанию | Вежливая просьба завершиться |
| 17 | SIGCHLD | Ядро | Дочерний процесс завершился или остановился |
| 18 | SIGCONT | `kill -CONT`, `fg`, `bg` | Продолжить остановленный процесс |
| 19 | SIGSTOP | `kill -STOP` | Остановить. **Нельзя перехватить** |
| 20 | SIGTSTP | Ctrl+Z | Остановить (можно перехватить) |

Номера приведены для x86 и ARM — самых распространённых архитектур. В скриптах надёжнее писать имена: `kill -TERM`, `kill -HUP`.

## Как процесс реагирует

Для каждого сигнала процесс может:

1. выполнить **действие по умолчанию** — завершиться, остановиться или проигнорировать;
2. **проигнорировать** сигнал;
3. **перехватить** его своим обработчиком: например, корректно завершиться или перечитать конфиг.

**SIGKILL** и **SIGSTOP** нельзя ни перехватить, ни проигнорировать — их обрабатывает ядро.

## Сигналы в жизни DevOps

- **Перезагрузка конфига без остановки:** `systemctl reload nginx` и `nginx -s reload` отправляют мастер-процессу nginx SIGHUP. Он перечитывает конфиг и плавно заменяет рабочие процессы, не обрывая соединения.
- **Ротация логов:** после переименования лог-файла nginx получает SIGUSR1 и открывает новый файл (так настроен `postrotate` в logrotate).
- **Корректная остановка:** systemd, `docker stop` и Kubernetes отправляют **SIGTERM** и ждут: Docker по умолчанию 10 секунд, Kubernetes — `terminationGracePeriodSeconds`, по умолчанию 30. Потом приходит **SIGKILL**. Приложение должно ловить SIGTERM: перестать принимать новые запросы, доработать текущие и выйти.
- **SIGHUP при закрытии терминала** завершает запущенные из него процессы. Как этого избежать, разберём в теме «Фоновые процессы».

## trap — обработка сигналов в bash

```bash
#!/usr/bin/env bash
TMP=$(mktemp)

cleanup() {
  echo "Убираю за собой"
  rm -f "$TMP"
}
trap cleanup EXIT              # выполнится при любом выходе из скрипта
trap 'echo "Ctrl+C пойман"; exit 130' INT
trap 'echo "Получен SIGTERM"; exit 143' TERM
trap '' HUP                    # игнорировать SIGHUP

echo "PID $$, работаю..."
sleep 1000
```

- `EXIT` — псевдосигнал bash: срабатывает при любом выходе из скрипта. Идеален для удаления временных файлов и снятия блокировок.
- Код возврата процесса, убитого сигналом, равен **128 + номер сигнала**: 130 — SIGINT, 137 — SIGKILL, 143 — SIGTERM. Код **137** вы будете часто видеть в Docker и Kubernetes: это SIGKILL, нередко от OOM Killer.

## Отправка сигналов

```bash
kill -HUP $(pidof -s nginx)    # то же, что nginx -s reload (pidof -s вернёт один PID)
kill -USR1 1234
pkill -TERM -f myapp
systemctl kill -s HUP myapp    # всем процессам службы
```

## Практика

- [ ] Вывести список сигналов `kill -l` и найти номера SIGHUP, SIGTERM, SIGKILL, SIGUSR1
- [ ] Написать скрипт с `trap` на INT, TERM и EXIT; проверить реакцию на Ctrl+C, `kill` и `kill -9`
- [ ] Проверить коды возврата: `sleep 100`, затем Ctrl+C, затем `echo $?`. Повторить с `kill -9` из другого терминала
- [ ] Установить nginx, изменить конфиг и применить его через `kill -HUP` мастер-процесса; убедиться в логах, что nginx не перезапускался
- [ ] Узнать, сколько секунд ждёт `docker stop` до SIGKILL и как это изменить

- [ ] SIGTERM
- [x] SIGINT
- [ ] SIGTSTP
- [ ] SIGQUIT
> Ctrl+Z — SIGTSTP, Ctrl+\ — SIGQUIT.

- [ ] Немедленно завершаются

> Изначально SIGHUP означал обрыв терминальной линии, но у демонов нет терминала, и сигнал стали использовать для перезагрузки конфига.

### Для чего нужны SIGUSR1 и SIGUSR2?
- [ ] Для завершения процессов пользователя
- [x] Это пользовательские сигналы: их смысл определяет сама программа
- [ ] Только для отладки ядра
- [ ] Для переключения пользователей
> Например, nginx по SIGUSR1 переоткрывает лог-файлы.

### Контейнер завершился с кодом 137. Что это значит?
- [ ] Приложение вернуло ошибку 137
- [x] Процесс убит сигналом SIGKILL (128 + 9), часто из-за OOM Killer или по истечении таймаута остановки
- [ ] Не найден образ
- [ ] Нет прав на запуск
> Код процесса, убитого сигналом, равен 128 + номер сигнала. 143 — SIGTERM, 130 — SIGINT.

### Как в bash-скрипте удалить временный файл при любом выходе из скрипта?
- [ ] trap 'rm -f "$TMP"' KILL
- [x] trap 'rm -f "$TMP"' EXIT
- [ ] on exit rm -f "$TMP"
- [ ] signal EXIT rm -f "$TMP"
> EXIT — псевдосигнал bash. На KILL поставить обработчик невозможно.

### Что делают docker stop и Kubernetes при остановке контейнера?
- [ ] Сразу отправляют SIGKILL
- [x] Отправляют SIGTERM, ждут таймаут (10 и 30 секунд по умолчанию) и затем отправляют SIGKILL
- [ ] Отправляют SIGHUP
- [ ] Ставят процесс на паузу
> Приложение должно обрабатывать SIGTERM, иначе его каждый раз будут убивать жёстко.

### Что делает trap '' HUP в скрипте?
- [ ] Отправляет SIGHUP себе
- [x] Заставляет скрипт игнорировать SIGHUP
- [ ] Восстанавливает обработчик по умолчанию
- [ ] Выводит список сигналов
> Пустая команда — игнорировать. Вернуть поведение по умолчанию: `trap - HUP`.

### Какой командой посмотреть список всех сигналов?
= kill -l
> Подробное описание — в `man 7 signal`.

### Какой сигнал получают процессы, запущенные из терминала, когда терминал закрывается?
- [ ] SIGTERM
- [x] SIGHUP
- [ ] SIGKILL
- [ ] SIGCHLD
> Поэтому команды, запущенные просто через `&`, умирают при выходе из SSH. Как этого избежать — в теме про фоновые процессы.

### Какой сигнал ядро отправляет родителю, когда дочерний процесс завершился?
- [ ] SIGTERM
- [ ] SIGUSR1
- [x] SIGCHLD
- [ ] SIGCONT
> По нему родитель понимает, что пора вызвать wait и забрать код возврата.

### Какой командой без остановки службы заставить nginx перечитать конфигурацию?
- [x] nginx -s reload
- [x] systemctl reload nginx
- [ ] kill -9 nginx
- [ ] systemctl restart nginx
> restart останавливает и запускает службу заново и обрывает соединения. reload отправляет мастер-процессу SIGHUP.
