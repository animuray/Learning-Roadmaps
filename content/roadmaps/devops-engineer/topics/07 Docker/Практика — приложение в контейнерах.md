# Практика — приложение в контейнерах

В разделе Linux вы развернули приложение «руками»: systemd-сервис, PostgreSQL, nginx. Теперь то же самое — в контейнерах. Это проект, который стоит положить в GitLab/GitHub и показывать на собеседовании.

## Целевая схема

```
              :80 / :443
 браузер ──► nginx (статика + reverse proxy)
                │  frontend
                ▼
              app (Python/Node/Go, слушает 0.0.0.0:8000)
                │  backend
        ┌───────┴────────┐
        ▼                ▼
   db (PostgreSQL)   cache (Redis)
   том pgdata
```

## Шаг 1. Dockerfile для приложения

Требования:

- multi-stage, если есть этап сборки;
- фиксированная версия базового образа (`-slim` или `-alpine`);
- зависимости копируются и ставятся **до** кода;
- `.dockerignore`;
- непривилегированный пользователь;
- `CMD` в exec-форме, приложение слушает `0.0.0.0`;
- конфигурация через переменные окружения (`DATABASE_URL`, `REDIS_URL`);
- эндпоинт `/health` и `HEALTHCHECK`.

## Шаг 2. nginx со своим конфигом

`nginx/default.conf`:

```nginx
upstream app {
    server app:8000;
}

server {
    listen 80;
    server_name _;

    location /static/ {
        alias /usr/share/nginx/html/static/;
        expires 7d;
    }

    location / {
        proxy_pass http://app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Конфиг и статика монтируются в контейнер nginx через **bind mount** в режиме только для чтения, наружу публикуется порт 80.

## Шаг 3. compose.yaml

Используйте пример из темы «Docker Compose»: сервисы `app`, `db`, `cache`, `nginx`, том `pgdata`, сети `frontend` и `backend`, healthcheck базы и `depends_on: condition: service_healthy`, пароли в `.env`.

Миграции базы — отдельным одноразовым сервисом:

```yaml
  migrate:
    image: registry.gitlab.com/team/app:${APP_TAG:-dev}
    command: ["python", "manage.py", "migrate"]
    depends_on:
      db:
        condition: service_healthy
    networks: [backend]
```

а у `app` — `depends_on: migrate: condition: service_completed_successfully`.

## Шаг 4. Реестр

```bash
docker login registry.gitlab.com
docker build -t registry.gitlab.com/ВАШ_НИК/app:$(git rev-parse --short HEAD) .
docker push registry.gitlab.com/ВАШ_НИК/app:$(git rev-parse --short HEAD)
```

На сервере — только `compose.yaml`, `.env` и конфиг nginx: `docker compose pull && docker compose up -d`. Исходники и компилятор на сервере больше не нужны.

## Шаг 5. Проверки «как в проде»

- перезагрузить сервер — всё поднимается само (`restart: unless-stopped`, Docker включён в systemd);
- `docker compose down && docker compose up -d` — данные базы на месте;
- с другой машины недоступны порты 5432 и 6379;
- `docker stop` приложения завершается быстро (сигналы доходят);
- логи всех сервисов — через `docker compose logs`, ротация настроена в `daemon.json`;
- обновление: новый тег → `docker compose up -d app` → пересоздаётся только приложение.

## Лаборатория

### Наружу — только nginx

В `~/shop-stack` описан стек: приложение `app` (счётчик посещений, порт 8000), `cache` (Redis) и прокси `nginx` (`nginx.conf` рядом проксирует на `app:8000`). Сейчас всё в одной сети, а `app` и `cache` опубликованы на хост — так в проде нельзя. Переделайте `compose.yaml`:

- две сети: **`front`** (nginx и app) и **`back`** (app и cache);
- на хост публикуется **только nginx**, порт **8186** → 80;
- у `app` и `cache` опубликованных портов нет;
- nginx **не имеет** доступа к сети с cache.

Стек должен работать: `curl localhost:8186` отвечает `visits: N`.

```bash setup
lab_drm() { docker rm -f "$@" >/dev/null 2>&1; true; }
# образ есть локально или скачивается (если ученик почистил образы через prune)
lab_img() { for i in "$@"; do docker image inspect "$i" >/dev/null 2>&1 || docker pull -q "$i" >/dev/null; done; }
# lab_wait_http URL [строка] — дождаться ответа
lab_wait_http() { for i in $(seq 60); do curl -s --max-time 1 "$1" 2>/dev/null | grep -q "${2:-.}" && return 0; sleep 0.25; done; return 1; }
# lab_visits_app каталог — приложение «счётчик посещений» (Python + Redis по сырому протоколу) и его Dockerfile
lab_visits_app() {
  mkdir -p "$1"
  cat > "$1/app.py" <<'EOF'
import os, socket
from http.server import BaseHTTPRequestHandler, HTTPServer

HOST = os.environ.get("REDIS_HOST", "localhost")
PASSWORD = os.environ.get("REDIS_PASSWORD", "")

def redis(*args):
    """Минимальный клиент Redis: одна команда — один ответ."""
    with socket.create_connection((HOST, 6379), timeout=3) as s:
        def cmd(*a):
            parts = [f"*{len(a)}\r\n".encode()]
            for x in a:
                b = str(x).encode()
                parts.append(b"$" + str(len(b)).encode() + b"\r\n" + b + b"\r\n")
            s.sendall(b"".join(parts))
            return s.recv(4096).decode().strip()
        if PASSWORD:
            cmd("AUTH", PASSWORD)
        return cmd(*args)

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        try:
            r = redis("INCR", "visits")
            if not r.startswith(":"):
                raise RuntimeError(r)
            code, body = 200, f"visits: {r[1:]}"
        except Exception as e:
            code, body = 500, f"redis error: {e}"
        self.send_response(code)
        self.end_headers()
        self.wfile.write(body.encode())

HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()
EOF
  cat > "$1/Dockerfile" <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
USER 10001
EXPOSE 8000
CMD ["python3", "app.py"]
EOF
}
lab_img python:3.12-slim redis:7-alpine nginx:1.27-alpine
[ -d /home/student/shop-stack ] && (cd /home/student/shop-stack && docker compose down -v --remove-orphans >/dev/null 2>&1)
docker rm -f $(docker ps -aq --filter label=com.docker.compose.project=shop-stack) >/dev/null 2>&1
rm -rf /home/student/shop-stack
lab_visits_app /home/student/shop-stack
cat > /home/student/shop-stack/nginx.conf <<'EOF'
server {
    listen 80;
    location / {
        proxy_pass http://app:8000;
        proxy_set_header Host $host;
    }
}
EOF
cat > /home/student/shop-stack/compose.yaml <<'EOF'
services:
  nginx:
    image: nginx:1.27-alpine
    ports:
      - "8186:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:

  app:
```

```bash check
p=shop-stack
cid() { docker ps -q --filter label=com.docker.compose.project=$p --filter label=com.docker.compose.service=$1 | head -1; }
for s in nginx app cache; do [ -n "$(cid $s)" ] || fail "Сервис $s не запущен"; done
pub() { docker inspect -f '{{range $p, $c := .NetworkSettings.Ports}}{{range $c}}{{.HostPort}} {{end}}{{end}}' $(cid $1) | xargs -n1 | sort -u | xargs; }
[ "$(pub nginx)" = 8186 ] || fail "nginx опубликован на «$(pub nginx)», нужен только 8186"

[ -z "$(pub cache)" ] || fail "У cache опубликованы порты: $(pub cache)"

[ "$(nets app | wc -l)" = 2 ] || fail "app должен быть в двух сетях (сейчас: $(nets app | xargs))"
```

```bash solution
cd ~/shop-stack
cat > compose.yaml <<'EOF'
services:
  nginx:
    image: nginx:1.27-alpine
    ports:
      - "8186:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - app
    networks: [front]

  app:
    build: .
    environment:
      REDIS_HOST: cache
    networks: [front, back]

  cache:
    image: redis:7-alpine
    networks: [back]

networks:
  front:
  back:
EOF
docker compose up -d --build --remove-orphans
sleep 2
curl -s localhost:8186; echo
```

```text review
Эталон: сети `front`/`back`, порты только у nginx.

- Принцип: наружу смотрит один вход (прокси), всё остальное — во внутренних сетях. Взломанный nginx не видит базу и кэш напрямую.
- Сеть `back` можно пометить `internal: true` — у её контейнеров не будет выхода в интернет (но и `apt install` внутри не сработает).
- Опубликованный порт Docker открывает в обход ufw — лишняя строка `ports:` у базы = база в интернете.
- В проде к этому добавляют: пароли в `.env`, healthcheck и `depends_on: condition`, тома для данных, лимиты (`deploy.resources.limits`), `restart: unless-stopped`.
```

## Тест

### Почему nginx в контейнере обращается к приложению как app:8000, а не localhost:8000?
- [ ] localhost запрещён в nginx
- [x] У каждого контейнера свой сетевой namespace: localhost внутри nginx — это сам nginx, а приложение доступно по имени сервиса в общей сети
- [ ] Так быстрее
- [ ] Это требование Compose v2
> Имя сервиса резолвит встроенный DNS Docker.

### Какие порты в этом проекте нужно публиковать на хост?
- [x] Только 80 и 443 у nginx
- [ ] 80, 8000, 5432 и 6379
- [ ] Только 5432
- [ ] Никакие
> Остальные сервисы общаются по внутренним сетям.

### Почему приложение внутри контейнера должно слушать 0.0.0.0, а не 127.0.0.1?
- [ ] 127.0.0.1 не поддерживается в Linux
- [x] Запросы от nginx приходят на сетевой интерфейс контейнера, а не на его loopback
- [ ] Так требует PostgreSQL
- [ ] Иначе не работает healthcheck
> Healthcheck изнутри контейнера как раз сработает и на 127.0.0.1 — это частая путаница.

### Как выполнить миграции базы до старта приложения в Compose?
- [ ] Запустить их вручную через SSH после каждого деплоя
- [x] Отдельным одноразовым сервисом migrate, от которого app зависит с condition: service_completed_successfully
- [ ] Поместить в HEALTHCHECK
- [ ] В RUN при сборке образа
> При сборке образа базы ещё нет, и образ должен быть одинаковым для всех окружений.

### Где хранить пароль базы в этом проекте?
- [ ] В Dockerfile через ENV
- [ ] В compose.yaml в git
- [x] В файле .env, который не коммитится, и подставлять в compose.yaml через переменные
- [ ] В образе nginx
> В git — только пример `.env.example` без реальных значений.

### Что нужно на сервере для развёртывания, если образ лежит в реестре?
- [x] compose.yaml, .env и конфиги, которые монтируются в контейнеры
- [x] Docker с плагином Compose и доступ к реестру
- [ ] Исходный код и компилятор
- [ ] Node.js или Python на хосте
> Сервер только скачивает и запускает готовый образ.

### Как сделать, чтобы после перезагрузки сервера контейнеры поднялись сами?
- [ ] Добавить docker compose up в .bashrc
- [x] Указать restart: unless-stopped (или always) и включить службу docker в systemd
- [ ] Использовать --rm
- [ ] Это происходит всегда автоматически
> Без restart-политики контейнеры после перезагрузки останутся остановленными.

### Как обновить только приложение на новую версию образа?
- [ ] docker compose down и up всего проекта
- [x] Поменять APP_TAG и выполнить docker compose pull app и docker compose up -d app
- [ ] Удалить том pgdata
- [ ] docker exec app git pull
> Compose пересоздаёт только сервисы с изменившейся конфигурацией или образом.

### Как правильно сделать бэкап PostgreSQL, работающего в Compose?
- [ ] Скопировать каталог тома на работающей базе через cp
- [x] docker compose exec db pg_dump -U app app > backup.sql
- [ ] docker commit db
- [ ] docker save postgres
> Копия файлов работающей базы может быть несогласованной.

### Почему конфиг nginx монтируют через bind mount, а не копируют в образ?
- [ ] Bind mount быстрее
- [x] Конфиг можно менять и перечитывать без пересборки образа, а официальный образ nginx остаётся неизменным
- [ ] nginx не умеет читать файлы из образа
- [ ] Так требует Compose
> Альтернатива — собрать свой образ nginx с конфигом, если он часть релиза.

### Как проверить, что порт PostgreSQL не доступен снаружи?
- [x] С другой машины выполнить nc -zv IP_сервера 5432 и получить отказ
- [x] На сервере посмотреть ss -tlnp и docker compose ps — у db нет опубликованных портов
- [ ] Выполнить psql внутри контейнера db
- [ ] Посмотреть docker images
> Внутри контейнера база доступна всегда — это не проверка.
