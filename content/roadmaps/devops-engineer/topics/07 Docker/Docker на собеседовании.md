# Docker на собеседовании

Ответы — коротко, как их стоит формулировать вслух. Подробности — в темах раздела.

## Теория

**Чем контейнеризация отличается от виртуализации?**
ВМ виртуализирует железо: у каждой своё ядро и ОС, изоляция через гипервизор. Контейнер — процесс на общем ядре хоста, изолированный механизмами ядра. Контейнеры легче и быстрее, ВМ изолированы сильнее и позволяют запускать другую ОС.

**На чём основана изоляция?**
namespaces (pid, net, mnt, uts, ipc, user, cgroup) — что процесс видит; cgroups — сколько ресурсов может потребить; плюс capabilities, seccomp, AppArmor/SELinux и overlayfs для файловой системы.

**Образ и контейнер?**
Образ — неизменяемые слои + метаданные. Контейнер — запущенный экземпляр с тонким слоем записи (copy-on-write).

**Что такое слой и почему важен порядок инструкций?**
RUN/COPY/ADD создают слои. Кэш инвалидируется на изменившейся инструкции и всех ниже. Поэтому зависимости ставим до копирования кода.

**Multi-stage — зачем?**
Собираем в «толстом» образе с компилятором, копируем только артефакт в маленький итоговый. Меньше размер и уязвимостей, нет исходников и секретов сборки.

**CMD и ENTRYPOINT?**
CMD — команда/аргументы по умолчанию, целиком заменяются аргументами `docker run`. ENTRYPOINT — сама программа, аргументы дописываются к ней. Вместе: ENTRYPOINT — программа, CMD — её аргументы по умолчанию. Обе — в exec-форме.

**COPY и ADD?**
COPY просто копирует. ADD ещё распаковывает локальные tar и скачивает по URL. По умолчанию — COPY.

**ARG и ENV?**
ARG — только при сборке, ENV — и в контейнере. Секреты — ни туда, ни туда.

**Как уменьшить образ?**
Маленький базовый образ, multi-stage, чистка кэша пакетного менеджера в том же RUN, `--no-install-recommends`, .dockerignore, без dev-зависимостей.

**Сети?**
bridge (по умолчанию, NAT), host (стек хоста), none, overlay (несколько хостов), macvlan (свой MAC в LAN). В пользовательских сетях есть DNS по именам контейнеров.

**Volume и bind mount?**
Volume управляется Docker и не зависит от путей хоста — для данных. Bind mount — любой путь хоста — для конфигов и разработки. tmpfs — в памяти.

**Что такое docker-compose и где его границы?**
Описание многоконтейнерного приложения в YAML на одном хосте. Нет кластера, отказоустойчивости, rolling update — это Kubernetes.

## Безопасность

- Не от root (`USER`), `--read-only`, `--cap-drop ALL` + только нужные `--cap-add`, без `--privileged`.
- Доступ к `docker.sock` = root на хосте.
- Фиксированные версии, сканирование (trivy), регулярная пересборка.
- Опубликованные порты обходят ufw.

## Разбор поломок

| Симптом | Куда смотреть |
| --- | --- |
| Контейнер сразу завершается | `docker ps -a` (Exit code), `docker logs`. Частое: процесс ушёл в фон (демон) и PID 1 завершился, нет нужной переменной, неверная команда (127) |
| Exit code 137 | OOMKilled в `docker inspect` → лимит памяти или утечка; либо kill/таймаут stop |
| Порт не открывается | Приложение слушает 127.0.0.1 внутри, не опубликован порт, не тот порт в `-p`, файрвол |
| Контейнеры не видят друг друга | Разные сети, стандартный bridge без DNS, обращение к localhost |
| `docker stop` ждёт 10 секунд | Shell-форма CMD, приложение не обрабатывает SIGTERM, нет `exec` в entrypoint |
| Закончилось место | `docker system df`, логи json-file без ротации, висячие образы, кэш сборки, анонимные тома |
| Сборка медленная | Нет .dockerignore, плохой порядок слоёв, нет кэша в CI |
| Permission denied на томе | Разные UID в контейнере и на хосте |

## Тест

### Чем контейнер отличается от виртуальной машины?
- [x] Контейнер использует общее ядро хоста, а у ВМ своё ядро и гостевая ОС
- [x] Контейнеры легче и запускаются быстрее, но изолированы слабее
- [ ] Контейнеры могут запускать любую ОС
- [ ] ВМ не используют гипервизор
> Ключевая мысль — общее ядро.

### Какие механизмы ядра обеспечивают изоляцию и ограничение ресурсов контейнера?
- [x] namespaces
- [x] cgroups
- [ ] systemd units
- [ ] crontab
> Дополнительно — capabilities, seccomp, AppArmor или SELinux.

### Контейнер с ENTRYPOINT ["python", "app.py"] запускают командой docker run образ --debug. Что выполнится?
- [ ] --debug
- [x] python app.py --debug
- [ ] python --debug
- [ ] Ошибка
> Аргументы docker run дописываются к ENTRYPOINT.

### В Dockerfile есть только CMD ["python", "app.py"]. Что выполнит docker run образ bash?
- [ ] python app.py bash
- [x] bash
- [ ] Ошибку
- [ ] python bash
> CMD целиком заменяется аргументами.

### Когда оправдано использовать ADD вместо COPY?
- [ ] Всегда
- [x] Когда нужно автоматически распаковать локальный tar-архив в образ
- [ ] Когда копируется один файл
- [ ] Для копирования между этапами
> Между этапами копируют через `COPY --from`.

### Какие способы реально уменьшают размер образа?
- [x] Multi-stage build
- [x] Минимальный базовый образ (slim, alpine, distroless)
- [x] Чистка кэша пакетного менеджера в том же RUN, где ставились пакеты
- [ ] Удаление файлов отдельной инструкцией RUN rm в конце Dockerfile
> Удаление в отдельном слое не уменьшает предыдущие слои.

### Контейнер сразу завершается с кодом 0 после docker run -d nginx-custom, где CMD ["nginx"]. Почему?
- [ ] Ошибка в конфиге nginx
- [x] nginx по умолчанию уходит в фон как демон, PID 1 завершается, и контейнер останавливается; нужно daemon off
- [ ] Не опубликован порт
- [ ] Нет тома
> Процесс в контейнере должен работать на переднем плане.

### docker stop контейнера каждый раз занимает ровно 10 секунд. Вероятные причины?
- [x] CMD в shell-форме, и sh не передаёт SIGTERM приложению
- [x] Приложение не обрабатывает SIGTERM
- [x] Entrypoint-скрипт запускает приложение без exec
- [ ] Медленный диск
> Через 10 секунд Docker отправляет SIGKILL.

### Чем volume отличается от bind mount?
- [ ] Volume хранится в памяти
- [x] Volume управляется Docker и не зависит от путей хоста, bind mount монтирует конкретный путь хоста
- [ ] Bind mount удаляется вместе с контейнером
- [ ] Ничем
> Для данных баз — volume, для конфигов — bind mount.

### Два контейнера в стандартной сети bridge не могут обратиться друг к другу по имени. Как исправить?
- [ ] Использовать --network none
- [x] Создать пользовательскую сеть через docker network create и подключить к ней оба контейнера
- [ ] Прописать IP в /etc/hosts хоста
- [ ] Опубликовать порты
> В пользовательских сетях работает встроенный DNS.

### Почему доступ к /var/run/docker.sock считается эквивалентом root?
- [ ] Сокет принадлежит root
- [x] Через API Docker можно запустить привилегированный контейнер с монтированием файловой системы хоста и получить полный доступ к хосту
- [ ] Через сокет можно читать /etc/shadow напрямую
- [ ] Это не так
> Не монтируйте docker.sock в контейнеры без крайней необходимости.

### На сервере закончилось место, и виноват Docker. Что проверить первым?
- [x] docker system df — образы, контейнеры, тома, кэш сборки
- [x] Размер логов контейнеров в /var/lib/docker/containers и настройку ротации
- [x] Висячие образы и неиспользуемые тома
- [ ] Удалить /var/lib/docker
> Чистят через prune-команды, понимая, что удаляется.

### Как корректно передать пароль от базы в контейнер?
- [ ] ENV в Dockerfile
- [ ] ARG при сборке
- [x] Переменной окружения или файлом-секретом при запуске (Compose secrets, секреты Kubernetes), не встраивая в образ
- [ ] В коде приложения
> Всё, что попало в образ, может увидеть любой, кто скачал образ.

### Зачем в продакшене использовать неизменяемые теги образов (версия, SHA коммита)?
- [x] Всегда понятно, какая версия запущена
- [x] Откат — это просто развёртывание предыдущего тега
- [ ] Так образ меньше весит
- [ ] latest не работает в Docker Hub
> Тег latest может указывать на разные образы в разное время.
