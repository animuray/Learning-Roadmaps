# Сборщики логов

**Сборщик** (агент, шиппер) читает логи там, где они появляются, и надёжно доставляет в хранилище. Задачи:

- **читать** файлы (как `tail -f`, с запоминанием позиции), journald, syslog, stdout контейнеров;
- **парсить** строки в поля (JSON, регулярки, форматы nginx);
- **обогащать** метаданными: хост, namespace, под, метки;
- **фильтровать** и маскировать: выбросить healthcheck, скрыть токены;
- **буферизовать** и повторять отправку, если хранилище недоступно;
- **маршрутизировать**: ошибки — в одно место, аудит — в другое.

## Fluentd и Fluent Bit

Оба — проекты CNCF (graduated), лицензия Apache 2.0, общая модель: **input → parser → filter → buffer → output**, маршрутизация по **тегам**.

| | Fluentd | Fluent Bit |
| --- | --- | --- |
| Язык | Ruby + C | C |
| Память | Десятки МБ и больше | Около 1 МБ |
| Плагины | Более 1000 внешних | Более 100 встроенных |
| Роль | **Агрегатор**: сложная обработка и маршрутизация | **Агент** на каждом узле, высокая производительность |
| Сигналы | Логи | Логи, метрики, трейсы |

Классическая схема — Fluent Bit на узлах → Fluentd-агрегатор → хранилища. Сейчас многие обходятся только Fluent Bit; облачные провайдеры перешли на него ради производительности.

Конфигурация Fluent Bit (YAML-формат):

```yaml
service:
  flush: 1
  log_level: info

pipeline:
  inputs:
    - name: tail
      path: /var/log/containers/*.log
      tag: kube.*
      multiline.parser: docker, cri
      db: /var/lib/fluent-bit/tail.db
      mem_buf_limit: 50MB

  filters:
    - name: kubernetes
      match: kube.*
      merge_log: on
    - name: grep
      match: kube.*
      exclude: log /healthz

  outputs:
    - name: loki
      match: kube.*
      host: loki
      port: 3100
      labels: job=fluent-bit, namespace=$kubernetes['namespace_name'], app=$kubernetes['labels']['app']
    - name: opensearch
      match: audit.*
      host: opensearch
      port: 9200
      tls: on
```

- `tail` + `db` — файл позиций: после перезапуска агент продолжит с того места, где остановился, без дублей и пропусков.
- `kubernetes` filter — добавляет namespace, под, контейнер и метки пода из API Kubernetes; `merge_log` разбирает JSON-строку приложения в поля.
- `multiline.parser` — склейка многострочных записей (stack trace Java/Python) в одно событие.

Fluentd (классический формат):

```
<source>
  @type forward
  port 24224
</source>

<filter app.**>
  @type parser
  key_name log
  <parse>
    @type json
  </parse>
</filter>

<match app.**>
  @type opensearch
  host opensearch
  port 9200
  logstash_format true
  <buffer>
    @type file
    path /var/log/fluentd/buffer
    flush_interval 5s
    retry_max_times 10
  </buffer>
</match>
```

## Filebeat

Лёгкий агент Elastic на Go (семейство **Beats**). Для каждого файла запускает **harvester**, отправляет в Elasticsearch или Logstash. Есть **модули** для nginx, system, postgresql и др. — с готовым парсингом и дашбордами Kibana.

```yaml
filebeat.inputs:
  - type: filestream
    id: nginx-access
    paths:
      - /var/log/nginx/access.log
    fields:
      service: nginx

  - type: filestream
    id: app
    paths:
      - /var/log/app/*.log
    parsers:
      - ndjson:
          target: ""
      - multiline:
          type: pattern
          pattern: '^\d{4}-\d{2}-\d{2}'
          negate: true
          match: after

processors:
  - add_host_metadata: ~
  - drop_event:
      when:
        contains:
          message: "/health"

output.logstash:
  hosts: ["logstash:5044"]
```

Elastic развивает **Elastic Agent** (централизованное управление через Fleet), внутри которого работают те же Beats.

## Другие сборщики

- **Vector** (Datadog, Rust) — быстрый, с языком преобразований VRL; источники, трансформы, приёмники.
- **Grafana Alloy** — агент Grafana на базе OpenTelemetry Collector: логи (в Loki), метрики, трейсы; замена Promtail.
- **OpenTelemetry Collector** — вендор-нейтральный стандарт для всех сигналов (OTLP); набирает популярность как единый агент.
- **rsyslog / syslog-ng** — классика Linux для syslog, пересылка по сети.

## Надёжность доставки

- **Позиции чтения** (registry/db): без них при рестарте агент перечитает файлы (дубли) или пропустит строки.
- **Буфер** в памяти и на диске: хранилище недоступно — логи копятся и отправляются позже. Буфер в памяти без ограничения → OOM агента.
- **Backpressure**: если хранилище не успевает, агент замедляет чтение; при переполнении буфера часть логов теряется — это нужно мониторить.
- **Ротация**: агент должен корректно обрабатывать переименование и усечение файлов (logrotate `copytruncate` может привести к потере строк).
- **Мониторинг самого агента**: у Fluent Bit, Vector, Alloy есть метрики для Prometheus (ошибки отправки, ретраи, размер буфера).
- Между агентами и хранилищем для больших объёмов ставят **Kafka** как буфер.

## Как выбрать

| Ситуация | Выбор |
| --- | --- |
| Kubernetes + Loki/Grafana | Grafana Alloy или Fluent Bit |
| Elastic Stack | Filebeat / Elastic Agent |
| Много разных назначений, сложная маршрутизация | Fluent Bit (+ Fluentd или Vector как агрегатор) |
| Единый агент для логов, метрик и трейсов | OpenTelemetry Collector / Alloy |
| Минимум ресурсов на узле | Fluent Bit, Vector |

- [ ] Установить Fluent Bit на ВМ, читать /var/log/nginx/access.log через tail с файлом позиций и выводить в stdout
- [ ] Перезапустить Fluent Bit и убедиться, что строки не дублируются благодаря db
- [ ] Отправить логи из Fluent Bit в Loki и в OpenSearch одновременно с разной маршрутизацией по тегам
- [ ] Настроить склейку многострочного stack trace в одно событие
- [ ] Отфильтровать запросы healthcheck и замаскировать токены в логах
- [ ] Установить Filebeat с модулем nginx и посмотреть готовый дашборд в Kibana
- [ ] В Kubernetes поставить Fluent Bit через Helm как DaemonSet и проверить, что у логов есть namespace, под и метки
- [ ] Остановить хранилище на несколько минут и проверить, что после восстановления логи дошли из буфера

## Тест

### Какие задачи решает сборщик логов?
- [x] Читает логи из файлов, journald и stdout контейнеров
- [x] Парсит строки и обогащает их метаданными
- [x] Буферизует и повторяет отправку, если хранилище недоступно
- [ ] Хранит логи годами и строит по ним индекс
> Хранение и поиск — задача Elasticsearch, OpenSearch или Loki.

### Чем Fluent Bit отличается от Fluentd?
- [x] Fluent Bit написан на C и потребляет около мегабайта памяти — подходит как агент на каждом узле
- [x] Fluentd на Ruby и C, с тысячей внешних плагинов, чаще используется как агрегатор со сложной обработкой
- [ ] Fluent Bit не умеет отправлять в Elasticsearch
- [ ] Fluentd — платный продукт
> Оба — проекты CNCF под Apache 2.0.

### Зачем сборщику файл позиций (db или registry)?
- [ ] Для хранения паролей
- [x] Чтобы после перезапуска продолжить чтение с того же места — без дублей и пропусков
- [ ] Для сжатия логов
- [ ] Для авторизации в хранилище
> Без него агент перечитает файлы с начала или пропустит строки.

### Что делает фильтр kubernetes во Fluent Bit?
- [ ] Перезапускает поды
- [x] Добавляет к логам метаданные из API Kubernetes: namespace, имя пода, контейнер, метки
- [ ] Удаляет логи системных подов
- [ ] Отправляет логи в etcd
> С merge_log он ещё и разбирает JSON-строку приложения в поля.

### Как правильно обработать многострочный stack trace?
- [ ] Каждая строка трейсбека — отдельное событие
- [x] Настроить многострочный парсер, который склеит строки трейсбека в одно событие по шаблону начала записи
- [ ] Удалить трейсбеки
- [ ] Логировать только первую строку
> Иначе ошибка разлетится на десятки бессвязных записей.

### Какой агент из семейства Beats предназначен для доставки файлов логов в Elastic Stack?
= Filebeat
> Для каждого файла он запускает harvester.

### Что произойдёт, если хранилище логов недоступно, а у агента настроен буфер?
- [ ] Логи сразу теряются
- [x] Логи накапливаются в буфере в памяти или на диске и отправляются после восстановления — пока буфер не переполнится
- [ ] Агент удаляет исходные файлы
- [ ] Приложение останавливается
> Размер буфера нужно ограничивать и мониторить.

### Какой вендор-нейтральный агент собирает логи, метрики и трейсы по стандарту OTLP?
- [ ] Filebeat
- [x] OpenTelemetry Collector
- [ ] Logstash
- [ ] rsyslog
> Grafana Alloy построен на его основе.

### Как в Kubernetes разворачивают Fluent Bit для сбора логов всех подов?
- [ ] Как Deployment с одной репликой
- [x] Как DaemonSet — по агенту на каждом узле
- [ ] Как Job
- [ ] Как sidecar в каждом поде обязательно
> Sidecar используют, только когда приложение пишет логи исключительно в файлы.

### Зачем между агентами и хранилищем иногда ставят Kafka?
- [ ] Для красивых дашбордов
- [x] Как надёжный буфер: сглаживает пики нагрузки и позволяет нескольким потребителям читать один поток логов
- [ ] Для замены хранилища
- [ ] Для парсинга grok
> Это характерно для больших объёмов логов.

### Почему агент сбора логов тоже нужно мониторить?
- [ ] Не нужно, он всегда работает
- [x] Ошибки отправки, переполнение буфера и отставание означают потерю логов именно тогда, когда они нужны
- [ ] Чтобы считать число пользователей
- [ ] Чтобы ускорить приложение
> Fluent Bit, Vector и Alloy отдают метрики для Prometheus.

### Какой сборщик написан на Rust и использует язык преобразований VRL?
= Vector
> Его развивает Datadog.
