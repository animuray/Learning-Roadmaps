# Markdown и репозиторий-конспект

**Markdown** — простой текстовый формат разметки. Файл читается глазами как обычный текст, а GitHub, GitLab, Obsidian и этот сайт превращают его в красивую страницу. На Markdown пишут README, документацию к проектам и инструкции. Нейросети тоже отвечают в Markdown.

## Стандарты

- Markdown придумал Джон Грубер в 2004 году. Исходное описание было неточным, и разные программы понимали его по-разному.
- **CommonMark** — строгая спецификация Markdown, чтобы документ везде отображался одинаково.
- **GitHub Flavored Markdown (GFM)** — диалект GitHub на основе CommonMark. Добавляет таблицы, чек-листы, зачёркивание и автоссылки.

## Синтаксис, который нужен каждый день

````markdown
# Заголовок первого уровня
## Заголовок второго уровня
### Третьего

Обычный абзац. **Жирный**, *курсив*, ~~зачёркнутый~~, `команда в строке`.

- пункт списка
- ещё пункт
  - вложенный пункт (отступ два пробела)

1. Нумерованный
2. Список

[Текст ссылки](https://git-scm.com)
![Описание картинки](images/schema.png)

> Цитата или важное замечание

```bash
git add . && git commit -m "Конспект по Git" && git push
```

| Команда | Что делает |
| --- | --- |
| git init | Создать репозиторий |

- [x] Выполненная задача
- [ ] Невыполненная задача

---
\*звёздочка как символ, а не курсив\*
````

Главное:

- Пустая строка разделяет абзацы.
- Блок кода — тройные обратные кавычки; после них указывают язык (`bash`, `yaml`, `python`) для подсветки.
- Символ разметки, который нужен как есть, экранируют обратным слешем: `\*`, `\#`.

## README.md

`README.md` в корне репозитория GitHub и GitLab показывают на главной странице проекта. Хороший README отвечает на вопросы:

1. Что это за проект и зачем он нужен.
2. Как запустить: зависимости, команды, переменные окружения.
3. Как устроен: структура каталогов, основные компоненты.
4. Как помочь проекту или к кому обращаться.

Для DevOps-инженера README — это ещё и эксплуатационная документация: как развернуть, где логи, как откатить релиз.

## Репозиторий-конспект: привычка на весь путь

Главная практика блока Git: завести репозиторий, в котором вы весь путь ведёте конспекты, и **каждый день** коммитить и пушить то, что изучили. К концу раздела Linux команды `git add`, `git commit` и `git push` будут набираться сами, а у вас появится публичная история обучения — её можно показать на собеседовании.

Пример структуры:

```
devops-notes/
├── README.md          # оглавление и план обучения
├── 01-git/
│   ├── basics.md
│   └── branching.md
├── 02-linux/
│   ├── processes.md
│   └── disks.md
└── labs/              # скрипты, конфиги, docker-compose из практики
```

> [!tip] Этот сайт тоже работает на Markdown
> Темы на этом сайте — Markdown-заметки из хранилища Obsidian. Освоив Markdown, вы сможете дописывать конспекты и тесты к роадмапу сами.

## Практика

- [ ] Создать на GitHub или GitLab репозиторий `devops-notes` и склонировать его
- [ ] Написать README.md с оглавлением и планом: разделы роадмапа как чек-лист `- [ ]`
- [ ] Написать конспект по разделу Git в `01-git/` с таблицей команд, блоками кода и ссылками на источники
- [ ] Проверить, как GitHub отображает файл: заголовки, таблицы, подсветку кода, чек-лист
- [ ] Поставить напоминание и с этого дня каждый день: написать конспект → `git commit` → `git push`

## Тест

### Как в Markdown сделать заголовок второго уровня?
- [ ] `== Заголовок ==`
- [x] `## Заголовок`
- [ ] `<h2>` в начале строки обязательно
- [ ] `**Заголовок**`
> Количество решёток — уровень заголовка, от 1 до 6.

### Как оформить многострочный блок кода с подсветкой синтаксиса bash?
- [ ] Обернуть каждую строку в одинарные обратные кавычки
- [x] Тройные обратные кавычки на отдельных строках, а сразу после открывающих — название языка: bash
- [ ] Начать каждую строку с символа >
- [ ] Выделить текст жирным
> Язык после открывающих кавычек включает подсветку: bash, yaml, python, json и другие.

### Как в Markdown записать ссылку?
- [x] `[текст](https://адрес)`
- [ ] `(текст)[https://адрес]`
- [ ] `<link>https://адрес</link>`
- [ ] `{текст}(https://адрес)`
> Картинка записывается так же, но с восклицательным знаком в начале.

### Как вставить картинку?
- [ ] `[img](путь)`
- [x] `![описание](путь/к/картинке.png)`
- [ ] `@image(путь)`
- [ ] `{{картинка}}`
> Текст в квадратных скобках — альтернативное описание (alt).

### Как сделать чек-лист, который GitHub покажет с галочками?
- [ ] `* (x) задача`
- [x] `- [ ] задача` и `- [x] выполненная задача`
- [ ] `[] задача`
- [ ] `TODO: задача`
> Чек-листы — расширение GitHub Flavored Markdown.

### Что такое GitHub Flavored Markdown?
- [ ] Отдельный язык программирования GitHub
- [x] Диалект Markdown на основе стандарта CommonMark с расширениями: таблицы, чек-листы, зачёркивание, автоссылки
- [ ] Формат файлов конфигурации GitHub Actions
- [ ] Платная версия Markdown
> Отсюда разница: таблица может отображаться на GitHub, но не в другом редакторе без поддержки GFM.

### Как выделить текст жирным?
- [ ] `_текст_`
- [x] `**текст**`
- [ ] `~~текст~~`
- [ ] `#текст#`
> Одна звёздочка или подчёркивание — курсив, две тильды — зачёркивание.

### Как выделить команду внутри обычного предложения моноширинным шрифтом?
- [ ] Тройными кавычками на отдельных строках
- [x] Одинарными обратными кавычками: `git status`
- [ ] Знаком > в начале строки
- [ ] Двумя звёздочками
> Внутри обратных кавычек разметка не работает: звёздочки и подчёркивания остаются как есть.

### Зачем нужен файл README.md в корне репозитория?
- [ ] Без него Git не создаст репозиторий
- [x] Чтобы описать проект: что это, как запустить и как устроен; GitHub и GitLab показывают его на главной странице репозитория
- [ ] В нём хранятся настройки CI/CD
- [ ] Это список игнорируемых файлов
> Хороший README экономит часы коллегам и вам самим через полгода.

### Как показать звёздочку как символ, чтобы она не превратилась в курсив?
- [x] Экранировать обратным слешем: `\*`
- [ ] Написать её два раза
- [ ] Заключить в круглые скобки
- [ ] Никак, в Markdown это невозможно
> Обратный слеш отменяет специальное значение любого символа разметки.

### Какая строка в таблице Markdown отделяет заголовок от остальных строк?
- [ ] `=== | === | ===`
- [x] `| --- | --- |`
- [ ] `+---+---+`
- [ ] Пустая строка
> Двоеточия в этой строке задают выравнивание: `:---` влево, `:---:` по центру, `---:` вправо.

### Чем вести конспект в Git-репозитории лучше, чем в заметках на телефоне?
- [x] Видна история изменений, а копия хранится на сервере
- [x] Ежедневные add, commit и push закрепляют работу с Git
- [x] Конспект можно показать на собеседовании или отправить коллегам
- [ ] Git автоматически проверяет правильность конспекта
> Публичная история обучения — хороший аргумент на собеседовании для джуна.
