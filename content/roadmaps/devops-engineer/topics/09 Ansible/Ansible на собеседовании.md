# Ansible на собеседовании

## Короткие ответы

**Что такое Ansible и как он работает?**
Инструмент управления конфигурацией. Agentless: с control node по SSH копирует модули на хосты, выполняет их Python'ом, получает JSON. Push-модель. Inventory — какие хосты, playbook — что сделать, модули — как.

**Идемпотентность?**
Повторный запуск не меняет систему, если она уже в нужном состоянии. Модули проверяют текущее состояние. `command`/`shell` не идемпотентны — нужны `creates`, `removes`, `changed_when`.

**Playbook, play, task, module, role?**
Модуль — единица работы. Task — вызов модуля. Play — задачи для группы хостов. Playbook — файл с плеями. Role — переиспользуемый набор задач, handlers, шаблонов, файлов и переменных со стандартной структурой.

**Handler?**
Задача, которая выполняется только по `notify` от изменившейся задачи, в конце плея и один раз. Типично — перезапуск сервиса после изменения конфига. `flush_handlers` — выполнить сейчас.

**Приоритеты переменных?**
Минимальный — defaults роли. Дальше group_vars (all → группы), host_vars, факты, vars плея, vars роли, vars блока/задачи, set_fact/register, параметры роли. Максимальный — extra vars (`-e`). Правило: настраиваемое — в defaults, окружения — в group_vars.

**defaults и vars в роли?**
defaults — низший приоритет, интерфейс роли. vars — высокий, внутренние константы.

**import и include?**
import — статически при разборе (теги и list-tasks видят задачи, нельзя loop). include — динамически при выполнении (можно loop и условия на весь include).

**Facts?**
Данные о хосте от модуля setup: ОС, IP, ресурсы. Отключение — `gather_facts: false`. Можно кэшировать.

**Секреты?**
Ansible Vault (файлы или `encrypt_string`), пароль вне Git, `no_log: true`. Для крупных систем — внешний менеджер секретов через lookup.

**Как ускорить Ansible?**
`forks`, `pipelining = True`, SSH ControlPersist, `gather_facts: false` или кэш фактов, пакеты списком вместо цикла, стратегия `free`, асинхронные задачи (`async`/`poll`), меньше `shell`.

**Ansible или Terraform?**
Ansible — настройка ОС и приложений, без state. Terraform — создание инфраструктуры, со state. Часто вместе.

**Ansible или bash-скрипт?**
Идемпотентность, декларативность, параллельность на сотни хостов, inventory и переменные, роли, check/diff, обработка ошибок.

## Разбор ошибок

| Симптом | Причина |
| --- | --- |
| `UNREACHABLE` | Нет SSH: неверный хост/порт/пользователь/ключ, `host key verification failed`, файрвол |
| `Missing sudo password` | Нужен `-K` или NOPASSWD в sudoers |
| `/usr/bin/python: not found` | Нет Python или неверный `ansible_python_interpreter`; поставить через `raw` |
| `couldn't resolve module/action` | Не установлена коллекция — `ansible-galaxy collection install` |
| Ошибка синтаксиса YAML при `{{` | Значение, начинающееся с `{{`, не взято в кавычки |
| Handler не сработал | Задача не дала changed; плей упал раньше конца; опечатка в имени handler |
| Задача всегда changed | `command`/`shell` без `changed_when`; шаблон с датой; `state: latest` |
| Переменная «не та» | Определена в нескольких местах — смотреть приоритеты и `ansible-inventory --host` |
| Права файлов странные | `mode: 644` без кавычек |

## Тест

### Как Ansible выполняет задачу на управляемом хосте?
- [ ] Через постоянно работающего агента
- [x] Подключается по SSH, копирует модуль, выполняет его на хосте и получает результат в JSON
- [ ] Через REST API хоста
- [ ] Через базу данных
> Agentless и push-модель.

### Что такое идемпотентность и почему она важна?
- [x] Повторный запуск не меняет систему, если она уже в нужном состоянии
- [x] Плейбук можно безопасно запускать многократно, например по расписанию или в CI
- [ ] Плейбук выполняется только один раз
- [ ] Каждый запуск выполняет все команды заново
> Модули проверяют текущее состояние перед изменением.

### Где разместить переменную, которую пользователь роли должен легко переопределить?
- [ ] В vars/main.yml роли
- [x] В defaults/main.yml роли
- [ ] В tasks/main.yml
- [ ] В meta/main.yml
> defaults имеют самый низкий приоритет.

### Переменная задана в defaults роли, в group_vars и через -e. Какое значение победит?
- [ ] Из defaults
- [ ] Из group_vars
- [x] Из -e (extra vars)
- [ ] Ansible выдаст ошибку
> Extra vars всегда имеют наивысший приоритет.

### Чем handler отличается от обычной задачи?
- [x] Выполняется только по notify от задачи, которая дала changed
- [x] Выполняется один раз в конце плея, даже если уведомлён несколько раз
- [ ] Выполняется всегда первым
- [ ] Не может перезапускать сервисы
> Немедленный запуск — meta: flush_handlers.

### Handler перезапуска nginx не сработал, хотя задача с notify есть. Возможные причины?
- [x] Задача не изменила файл и дала ok вместо changed
- [x] Плей упал раньше, чем дошёл до выполнения handlers
- [x] Имя в notify не совпадает с именем handler
- [ ] Handlers работают только в ролях
> При падении помогает флаг --force-handlers.

### Чем import_tasks отличается от include_tasks?
- [ ] Ничем
- [x] import подключает задачи статически при разборе плейбука, include — динамически во время выполнения (можно использовать с loop)
- [ ] include работает только в ролях
- [ ] import нельзя использовать с переменными
> С import теги и --list-tasks видят все подключённые задачи.

### Задача с модулем shell показывает changed при каждом запуске. Как исправить?
- [x] Заменить shell подходящим модулем, если он есть
- [x] Добавить creates, removes или changed_when
- [ ] Добавить ignore_errors: true
- [ ] Использовать serial: 1
> Проверочные команды помечают changed_when: false.

### Хост в выводе UNREACHABLE. Что проверить?
- [x] Доступность SSH: адрес, порт, пользователь, ключ
- [x] Проверку ключа хоста (known_hosts) и файрвол
- [ ] Версию Jinja2
- [ ] Наличие handlers
> Ошибка модуля на хосте выглядит как FAILED, а не UNREACHABLE.

### Как хранить пароли для плейбуков в Git?
- [ ] Открытым текстом в group_vars
- [x] Зашифровать Ansible Vault и передавать пароль vault вне репозитория
- [ ] В комментариях к коммиту
- [ ] В inventory без шифрования
> Плюс no_log: true у задач с секретами.

### Какие способы реально ускоряют выполнение плейбуков?
- [x] Увеличить forks и включить pipelining
- [x] Отключить или кэшировать сбор фактов там, где они не нужны
- [x] Ставить пакеты одним вызовом со списком вместо цикла
- [ ] Заменить все модули на shell
> Ещё — SSH ControlPersist, стратегия free и async-задачи.

### Ошибка couldn't resolve module/action community.docker.docker_container. Что делать?
- [ ] Переустановить Python на хосте
- [x] Установить коллекцию: ansible-galaxy collection install community.docker
- [ ] Перезапустить sshd
- [ ] Удалить inventory
> Зависимости коллекций фиксируют в requirements.yml.

### Чем Ansible лучше набора bash-скриптов для настройки серверов?
- [x] Идемпотентные модули и декларативное описание состояния
- [x] Параллельное выполнение на многих хостах с inventory и переменными
- [x] Режимы --check и --diff, роли для переиспользования
- [ ] Ansible не требует SSH
> SSH Ansible как раз использует.

### Зачем при запуске указывают --limit?
- [ ] Чтобы ограничить время выполнения
- [x] Чтобы применить плейбук только к части хостов, например сначала к одному серверу
- [ ] Чтобы ограничить число задач
- [ ] Чтобы ограничить память
> Удобно для осторожной выкатки рискованных изменений.
