# Практика — плейбук для нового сервера

В разделе Linux вы руками делали «первичную настройку сервера» и «приложение без Docker». Теперь то же самое — кодом, для группы серверов сразу. Результат — репозиторий, который за 5 минут приводит любую свежую ВМ к эталону.

## Что должен делать плейбук

1. Обновить систему и поставить базовые пакеты (curl, vim, htop, git, chrony, unattended-upgrades).
2. Настроить часовой пояс и hostname.
3. Создать пользователя `deploy` с SSH-ключом и sudo.
4. Защитить SSH: запрет входа root и по паролю (drop-in в `/etc/ssh/sshd_config.d/`), с проверкой конфига.
5. Включить файрвол: SSH, 80, 443.
6. Установить Docker из официального репозитория и добавить `deploy` в группу docker.
7. Развернуть приложение: каталог `/opt/app`, `compose.yaml` из шаблона, `.env` с секретами из Vault, запуск через Compose.
8. Повторный запуск — **0 changed**.

## Фрагменты ролей

`roles/ssh_hardening/tasks/main.yml`:

```yaml
- name: Drop-in конфиг sshd
  ansible.builtin.template:
    src: 00-hardening.conf.j2
    dest: /etc/ssh/sshd_config.d/00-hardening.conf
    mode: "0644"
    validate: /usr/sbin/sshd -t -f %s
  notify: Reload sshd
```

`roles/ssh_hardening/templates/00-hardening.conf.j2`:

```
# {{ ansible_managed }}
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
AllowUsers {{ ssh_allowed_users | join(' ') }}
```

`roles/docker/tasks/main.yml` (Debian/Ubuntu):

```yaml
- name: Каталог для ключей
  ansible.builtin.file:
    path: /etc/apt/keyrings
    state: directory
    mode: "0755"

- name: GPG-ключ Docker
  ansible.builtin.get_url:
    url: https://download.docker.com/linux/ubuntu/gpg
    dest: /etc/apt/keyrings/docker.asc
    mode: "0644"

- name: Репозиторий Docker
  ansible.builtin.apt_repository:
    repo: "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu {{ ansible_facts['distribution_release'] }} stable"
    filename: docker
    state: present

- name: Пакеты Docker
  ansible.builtin.apt:
    name: [docker-ce, docker-ce-cli, containerd.io, docker-buildx-plugin, docker-compose-plugin]
    state: present
    update_cache: true

- name: Docker запущен
  ansible.builtin.service:
    name: docker
    state: started
    enabled: true

- name: deploy в группе docker
  ansible.builtin.user:
    name: deploy
    groups: docker
    append: true
```

`roles/app/tasks/main.yml`:

```yaml
- name: Каталог приложения
  ansible.builtin.file:
    path: /opt/app
    state: directory
    owner: deploy
    mode: "0750"

- name: compose.yaml
  ansible.builtin.template:
    src: compose.yaml.j2
    dest: /opt/app/compose.yaml
    owner: deploy
    mode: "0640"
  notify: Restart app

- name: .env с секретами
  ansible.builtin.template:
    src: env.j2
    dest: /opt/app/.env
    owner: deploy
    mode: "0600"
  no_log: true
  notify: Restart app

- name: Приложение запущено
  community.docker.docker_compose_v2:
    project_src: /opt/app
    state: present
```

`roles/app/handlers/main.yml`:

```yaml
- name: Restart app
  community.docker.docker_compose_v2:
    project_src: /opt/app
    state: restarted
```

## Лаборатория

```bash lib
# «Серверы» для Ansible — контейнеры lab-web1, lab-web2, lab-db1 (Python, sudo, sshd); подключение — community.docker.docker
lab_host_image() {
  docker image inspect lab-ansible-host:2 >/dev/null 2>&1 && return
  docker image inspect python:3.12-slim >/dev/null 2>&1 || docker pull -q python:3.12-slim >/dev/null
  docker build -q -t lab-ansible-host:2 - >/dev/null <<'EOF'
FROM python:3.12-slim
RUN apt-get update -q && apt-get install -y -q --no-install-recommends sudo openssh-server \
 && mkdir -p /run/sshd && rm -rf /var/lib/apt/lists/*
CMD ["sleep", "infinity"]
EOF
}
lab_hosts() { lab_host_image; for h in ${*:-lab-web1 lab-web2 lab-db1}; do docker rm -f $h >/dev/null 2>&1; docker run -d --name $h --hostname $h lab-ansible-host:2 >/dev/null; done; }
# lab_inv каталог — ansible.cfg и inventory.ini: web = lab-web1, lab-web2; db = lab-db1
lab_inv() {
  mkdir -p "$1"
  printf '[defaults]\ninventory = inventory.ini\ninterpreter_python = /usr/local/bin/python3\n' > "$1/ansible.cfg"
  printf '[web]\nlab-web1\nlab-web2\n\n[db]\nlab-db1\n\n[all:vars]\nansible_connection=community.docker.docker\n' > "$1/inventory.ini"
}
lab_own() { chown -R student:student "$1"; }
# lab_play каталог аргументы — ansible-playbook от имени ученика, вывод — в /tmp/lab-ans.log
lab_play() { su - student -c "cd $1 && ANSIBLE_NOCOLOR=1 ansible-playbook $2" > /tmp/lab-ans.log 2>&1; }
# сумма changed по всем хостам из итогов последнего прогона
lab_changed() { grep -E '^lab-[a-z0-9]+ +:' /tmp/lab-ans.log | grep -oE 'changed=[0-9]+' | cut -d= -f2 | awk '{s += $1} END {print s + 0}'; }
lab_anslog() { grep -E 'fatal|ERROR|FAILED|error' /tmp/lab-ans.log | head -2 | tr '\n' ' ' | cut -c1-300; }
```

### Новый сервер одной командой

«Свежие серверы» — `lab-web1` и `lab-web2` (Debian, в образе уже есть `sudo` и `openssh-server`). В `~/ansible-server` создайте проект из **трёх ролей** и плейбук `site.yml`, который применяет их к группе `web`:

1. **`common`** — пакеты `curl`, `htop`, `git` (с обновлением списков) и файл `/etc/timezone` с `Europe/Moscow`;
2. **`users`** — пользователь **`deploy`** (bash), его **открытый ключ** из `files/deploy.pub` роли — в `authorized_keys`, и правило sudo без пароля для всех команд в `/etc/sudoers.d/deploy` с **проверкой visudo**;
3. **`ssh_hardening`** — файл `/etc/ssh/sshd_config.d/10-hardening.conf` с `PermitRootLogin no` и `PasswordAuthentication no`, установленный с **проверкой `sshd -t -f %s`**.

Открытый ключ для `deploy` уже лежит в `~/deploy_key.pub`. Плейбук должен быть **идемпотентным**: второй прогон — `changed=0`.

```bash setup
lab_hosts lab-web1 lab-web2
rm -rf /home/student/ansible-server
lab_inv /home/student/ansible-server
rm -f /home/student/deploy_key /home/student/deploy_key.pub
su - student -c 'ssh-keygen -q -t ed25519 -N "" -C deploy@lab -f ~/deploy_key'
lab_own /home/student/ansible-server
```

```bash check
d=/home/student/ansible-server
for r in common users ssh_hardening; do [ -f $d/roles/$r/tasks/main.yml ] || fail "Нет роли $r (roles/$r/tasks/main.yml)"; done
[ -f $d/site.yml ] || fail "Нет ~/ansible-server/site.yml"
grep -rqE 'validate:.*visudo' $d/roles/users || fail "Правило sudo ставится без проверки visudo"
grep -rqE 'validate:.*sshd\s+-t\s+-f\s+%s' $d/roles/ssh_hardening || fail "Конфиг sshd ставится без проверки sshd -t -f %s"
lab_play $d site.yml || fail "Плейбук падает: $(lab_anslog)"
pub=$(cut -d' ' -f1-2 /home/student/deploy_key.pub)
for h in lab-web1 lab-web2; do
  for p in curl htop git; do docker exec $h dpkg-query -W -f='${Status}' $p 2>/dev/null | grep -q 'install ok installed' || fail "На $h не установлен $p"; done
  [ "$(docker exec $h cat /etc/timezone 2>/dev/null)" = Europe/Moscow ] || fail "На $h /etc/timezone не Europe/Moscow"
  [ "$(docker exec $h getent passwd deploy | cut -d: -f7)" = /bin/bash ] || fail "На $h нет deploy с bash"
  docker exec $h grep -qF "$pub" /home/deploy/.ssh/authorized_keys 2>/dev/null || fail "На $h ключ deploy не в authorized_keys"
  [ "$(docker exec $h stat -c '%U %a' /home/deploy/.ssh/authorized_keys)" = "deploy 600" ] || fail "На $h права authorized_keys: $(docker exec $h stat -c '%U %a' /home/deploy/.ssh/authorized_keys)"
  docker exec $h sudo -l -U deploy 2>/dev/null | grep -qE 'NOPASSWD: ALL' || fail "На $h у deploy нет sudo без пароля"
  c=$(docker exec $h sshd -T 2>/dev/null)
  echo "$c" | grep -qx 'permitrootlogin no' && echo "$c" | grep -qx 'passwordauthentication no' || fail "На $h итоговые настройки sshd не запрещают root и пароли"
done
lab_play $d site.yml || fail "Повторный прогон падает: $(lab_anslog)"
c=$(lab_changed); [ "$c" = 0 ] || fail "Второй прогон не идемпотентен: changed=$c ($(grep -E '^changed:' /tmp/lab-ans.log | head -3 | tr '\n' ' '))"
ok "три роли настроили оба сервера, второй прогон — changed=0"
```

```text hint
1. Создать скелеты трёх ролей. Открытый ключ скопировать в каталог файлов роли users.
2. common: модуль пакетов со списком и обновлением кэша; копирование содержимого в файл часового пояса.
3. users: модуль пользователей; модуль авторизованных ключей с чтением файла через lookup; копирование правила sudo с проверкой и правами 0440.
4. ssh_hardening: копирование drop-in файла с проверкой конфигурации sshd.
5. Плейбук: хосты web, права администратора, список ролей. Прогнать дважды.
```

```bash solution
cd ~/ansible-server
for r in common users ssh_hardening; do ansible-galaxy role init roles/$r >/dev/null; done
cp ~/deploy_key.pub roles/users/files/deploy.pub
cat > roles/common/tasks/main.yml <<'EOF'
- name: Базовые пакеты
  ansible.builtin.apt:
    name: [curl, htop, git]
    state: present
    update_cache: true
    cache_valid_time: 3600
- name: Часовой пояс
  ansible.builtin.copy:
    dest: /etc/timezone
    content: "Europe/Moscow\n"
    mode: "0644"
EOF
cat > roles/users/tasks/main.yml <<'EOF'
- name: Пользователь deploy
  ansible.builtin.user:
    name: deploy
    shell: /bin/bash
- name: Ключ deploy
  ansible.posix.authorized_key:
    user: deploy
    key: "{{ lookup('file', 'deploy.pub') }}"
- name: sudo для deploy
  ansible.builtin.copy:
    dest: /etc/sudoers.d/deploy
    content: "deploy ALL=(ALL) NOPASSWD: ALL\n"
    mode: "0440"
    validate: visudo -cf %s
EOF
cat > roles/ssh_hardening/tasks/main.yml <<'EOF'
- name: Запрет входа root и по паролю
  ansible.builtin.copy:
    dest: /etc/ssh/sshd_config.d/10-hardening.conf
    content: |
      PermitRootLogin no
      PasswordAuthentication no
    mode: "0644"
    validate: sshd -t -f %s
EOF
cat > site.yml <<'EOF'
- name: Новый сервер
  hosts: web
  become: true
  roles:
    - common
    - users
    - ssh_hardening
EOF
ansible-playbook site.yml && ansible-playbook site.yml | tail -4
```

```text review
Эталон — в «Решении».

- Это ровно тема «Первичная настройка сервера», но кодом: новый сервер настраивается одной командой одинаково, а изменения проходят ревью в Git.
- `cache_valid_time` у apt — не обновлять списки пакетов при каждом прогоне, иначе задача всегда `changed` и идемпотентности нет.
- `validate: sshd -t -f %s` для drop-in: sshd проверяет фрагмент как самостоятельный конфиг. Ошибка — Ansible упадёт, а рабочий sshd не тронут. На живом сервере после смены конфига — handler `reload ssh`, и **новый** вход проверяют до закрытия текущей сессии.
- Дальше в настоящем проекте: роли `firewall` (ufw/nftables из списка портов), `docker`, `app` (compose.yaml из шаблона, `.env` из Vault), разные inventory для stage и prod.
```

```text notes
update_cache:\s*(true|yes)(?![\s\S]*cache_valid_time) => Списки пакетов обновляются при каждом прогоне — задача всегда changed. Добавьте cache_valid_time.
```

## Тест

### Почему конфиг sshd кладут через template с validate: /usr/sbin/sshd -t -f %s?
- [ ] Чтобы ускорить перезапуск
- [x] Чтобы проверить новый конфиг до установки: с ошибкой он не заменит рабочий и sshd не перестанет пускать на сервер
- [ ] validate шифрует конфиг
- [ ] Так требует ufw
> Ошибка в sshd_config может лишить доступа к серверу.

### Как безопасно применять роль ужесточения SSH к новому серверу?
- [x] Сначала на одном хосте через --limit
- [x] Держать открытой вторую SSH-сессию и проверить вход в новой сессии
- [ ] Сразу на все хосты без проверки
- [ ] Отключить файрвол навсегда
> Если доступ потерян, остаётся только консоль провайдера.

### Почему перезапуск приложения сделан handler'ом, а не обычной задачей?
- [ ] Обычные задачи не умеют перезапускать
- [x] Чтобы приложение перезапускалось только при изменении compose.yaml или .env, а не при каждом прогоне
- [ ] Handlers работают быстрее
- [ ] Так требует Docker
> Несколько изменений вызовут один перезапуск.

### Что означает changed=0 при повторном запуске плейбука?
- [ ] Плейбук не выполнился
- [x] Сервер уже в описанном состоянии, и плейбук ничего не изменил — он идемпотентен
- [ ] Произошла ошибка подключения
- [ ] Все задачи пропущены из-за when
> Это главный критерий качества плейбука.

### Зачем у задачи с шаблоном .env указан no_log: true?
- [ ] Чтобы файл не создавался
- [x] Чтобы секреты из Vault не попали в вывод Ansible и логи CI
- [ ] Чтобы файл зашифровался на сервере
- [ ] Чтобы отключить diff
> И права 0600, чтобы файл читал только владелец.

### Какие права правильно поставить файлу .env с паролями на сервере?
= 0600
= 600
> Только владелец может читать и писать.

### Зачем отдельные inventory для stage и prod?
- [ ] Ansible не умеет работать с одним inventory
- [x] Чтобы у окружений были свои хосты и переменные, и изменение сначала проверялось на stage
- [ ] Чтобы ускорить плейбук
- [ ] Чтобы не нужен был Vault
> Запуск: ansible-playbook -i inventories/stage site.yml.

### Как убедиться, что плейбук действительно описывает сервер полностью?
- [ ] Посмотреть README
- [x] Пересоздать ВМ с нуля, прогнать плейбук и проверить, что всё работает без ручных действий
- [ ] Запустить плейбук один раз
- [ ] Проверить ansible --version
> Ручные изменения на сервере — признак неполного описания.

### Какой модуль используется для запуска приложения через Docker Compose v2?
- [ ] ansible.builtin.shell с docker compose up
- [x] community.docker.docker_compose_v2
- [ ] ansible.builtin.service
- [ ] community.general.compose
> Модуль идемпотентен в отличие от shell.

### Почему репозиторий Docker подключают через apt_repository с signed-by, а не скриптом curl | sh?
- [x] Это идемпотентно: повторный запуск не дублирует репозиторий
- [x] Ключ ограничен этим репозиторием через signed-by — так рекомендует официальная инструкция
- [ ] curl не работает в Ansible
- [ ] Скрипт установки удаляет Docker
> Удобные скрипты установки не предназначены для повторяемой настройки серверов.

### Что делает ansible-playbook с флагами --check --diff перед реальным запуском?
- [ ] Применяет изменения дважды
- [x] Показывает, какие задачи и какие строки в файлах изменились бы, ничего не меняя
- [ ] Проверяет пароли Vault
- [ ] Удаляет старые файлы
> Не все модули поддерживают check mode полностью.
