# Реляционная модель и таблицы

Почти любое приложение хранит данные в реляционной базе: пользователей, заказы, платежи, логи. SQL — язык, на котором с этой базой разговаривают. Его спрашивают у аналитиков, бэкенд-разработчиков, тестировщиков и DevOps-инженеров, и он почти не меняется десятилетиями. Выученное здесь пригодится в любой из этих профессий.

В курсе используется **PostgreSQL**. Базовый SQL одинаков почти во всех СУБД (MySQL, SQL Server, Oracle, SQLite), различия — в деталях. Где они важны, об этом будет сказано отдельно.

## Таблица, строка, столбец

Реляционная база хранит данные в **таблицах** (в теории их называют *отношениями*, отсюда «реляционная»).

| id | name | category | price | qty |
| --- | --- | --- | --- | --- |
| 1 | Смартфон Nova 8 | Смартфоны | 24990 | 12 |
| 2 | Наушники Echo Buds | Аудио | 4990 | 30 |
| 3 | Кабель USB-C 1 м | Аксессуары | 490 | 120 |

- **Столбец** (поле, атрибут) — одно свойство объекта: название, цена. У столбца есть имя и **тип**, все значения в столбце одного типа.
- **Строка** (запись, кортеж) — один объект: конкретный товар.
- Порядок строк в таблице **не определён**. Если нужен порядок — его задают в запросе (`ORDER BY`), а не надеются на «порядок вставки».

## Типы данных PostgreSQL, которые нужны чаще всего

| Тип | Что хранит | Пример |
| --- | --- | --- |
| `integer` (`int`) | целые числа до ~2 млрд | `42` |
| `bigint` | большие целые, идентификаторы | `9000000000` |
| `numeric(10,2)` | точные дробные — **деньги** | `1999.90` |
| `real`, `double precision` | приближённые дробные — измерения | `3.14` |
| `text`, `varchar(n)` | строки | `'Москва'` |
| `boolean` | истина/ложь | `true` |
| `date` | дата | `'2026-03-15'` |
| `timestamp`, `timestamptz` | дата и время (tz — с часовым поясом) | `'2026-03-15 10:30:00+03'` |

> [!warning] Деньги — только `numeric`
> `real` и `double precision` хранят числа приближённо: `0.1 + 0.2` там не равно `0.3`. Для денег и всего, что нужно считать точно, берите `numeric`.

Строки в SQL пишутся в **одинарных** кавычках: `'Москва'`. Двойные кавычки — для имён таблиц и столбцов, если в имени есть пробелы или заглавные буквы (`"Order Date"`). Лучше так не называть: пишите имена латиницей в нижнем регистре через подчёркивание — `order_date`.

## Первичный ключ

**Первичный ключ** (`PRIMARY KEY`) — столбец (или набор столбцов), значение которого уникально для каждой строки и не бывает пустым. По нему строку можно однозначно найти, изменить или сослаться на неё из другой таблицы.

Обычно это искусственный числовой `id`, который база выдаёт сама:

```sql
id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY
-- старый, но очень распространённый вариант:
id serial PRIMARY KEY
```

Почему не взять «натуральный» ключ, например email или номер паспорта? Они меняются: человек сменил почту — и пришлось бы менять ключ во всех таблицах, которые на него ссылаются.

## CREATE TABLE

```sql
CREATE TABLE products (
    id        integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name      text          NOT NULL,
    category  text          NOT NULL,
    price     numeric(10,2) NOT NULL,
    qty       integer       NOT NULL DEFAULT 0,
    added_at  date          NOT NULL DEFAULT current_date
);
```

- `NOT NULL` — значение обязательно.
- `DEFAULT` — значение, если при вставке столбец не указан.
- Таблицу удаляют командой `DROP TABLE products;` — вместе со всеми данными, без корзины.

## INSERT — добавляем строки

```sql
INSERT INTO products (name, category, price, qty)
VALUES ('Смартфон Nova 8', 'Смартфоны', 24990, 12);

-- несколько строк одной командой
INSERT INTO products (name, category, price)
VALUES
    ('Наушники Echo Buds', 'Аудио', 4990),
    ('Кабель USB-C 1 м', 'Аксессуары', 490);
```

- Список столбцов после имени таблицы пишите **всегда**. Без него значения раскладываются по порядку столбцов в таблице, и запрос сломается, как только в таблицу добавят новый столбец.
- `id` и `added_at` не указаны — база заполнит их сама (`IDENTITY` и `DEFAULT`).
- `qty` во второй команде не указан — подставится `DEFAULT 0`.

## Первый SELECT

Чтобы посмотреть, что лежит в таблице:

```sql
SELECT * FROM products;
```

`*` — «все столбцы». Для изучения данных это удобно, в коде приложения — нет: подробнее в теме [[SELECT — выборка данных]].

## NULL — «значение неизвестно»

`NULL` — это не ноль и не пустая строка, а **отсутствие значения**. Например, у товара без бренда в столбце `brand` будет `NULL`. Сравнения с `NULL` ведут себя необычно, этому посвящены отдельные части тем [[WHERE — условия отбора]] и [[Даты, строки и NULL]].

## Тренажёр

### Первый запрос

Выведите все столбцы и все строки таблицы `products`.

```sql seed
CREATE TABLE products (
    id       integer PRIMARY KEY,
    name     text NOT NULL,
    category text NOT NULL,
    price    integer NOT NULL,
    qty      integer NOT NULL DEFAULT 0
);
INSERT INTO products (id, name, category, price, qty) VALUES
    (1, 'Смартфон Nova 8', 'Смартфоны', 24990, 12),
    (2, 'Наушники Echo Buds', 'Аудио', 4990, 30),
    (3, 'Кабель USB-C 1 м', 'Аксессуары', 490, 120);
```

```sql check
SELECT * FROM products;
```

```text hint
Взять из таблицы товаров всё: все столбцы и все строки.
В конспекте есть короткое обозначение для «все столбцы».
```

```sql solution
SELECT * FROM products;
```

### Создать таблицу жанров

Создайте таблицу `genres` с двумя столбцами:

- `id` — целое число, первичный ключ;
- `name` — текст, обязательный (`NOT NULL`).

```sql check state
SELECT 1
WHERE (SELECT count(*) FROM information_schema.columns
       WHERE table_schema = current_schema() AND table_name = 'genres') = 2
  AND EXISTS (SELECT 1 FROM information_schema.columns
              WHERE table_schema = current_schema() AND table_name = 'genres'
                AND column_name = 'name' AND is_nullable = 'NO')
  AND EXISTS (SELECT 1 FROM information_schema.table_constraints
              WHERE table_schema = current_schema() AND table_name = 'genres'
                AND constraint_type = 'PRIMARY KEY');
```

```text hint
Создать таблицу «жанры» с двумя столбцами:
  номер — целое число, главный ключ;
  название — текст, пустым быть не может.
```

```sql solution
CREATE TABLE genres (
    id   integer PRIMARY KEY,
    name text NOT NULL
);
```

### Добавить товар

В таблицу `products` добавьте товар «Колонка Echo Mini» из категории «Аудио» с `id` = 4, ценой 3490 и количеством 7.

```sql seed
CREATE TABLE products (
    id       integer PRIMARY KEY,
    name     text NOT NULL,
    category text NOT NULL,
    price    integer NOT NULL,
    qty      integer NOT NULL DEFAULT 0
);
INSERT INTO products (id, name, category, price, qty) VALUES
    (1, 'Смартфон Nova 8', 'Смартфоны', 24990, 12),
    (2, 'Наушники Echo Buds', 'Аудио', 4990, 30),
    (3, 'Кабель USB-C 1 м', 'Аксессуары', 490, 120);
```

```sql check state
SELECT 1 FROM products
WHERE id = 4 AND name = 'Колонка Echo Mini' AND category = 'Аудио' AND price = 3490 AND qty = 7
  AND (SELECT count(*) FROM products) = 4;
```

```text hint
Добавить в «товары» одну строку: номер 4, название, категория, цена 3490, остаток 7.
Сначала перечислите столбцы, затем значения в том же порядке. Текст — в одинарных кавычках.
```

```sql solution
INSERT INTO products (id, name, category, price, qty)
VALUES (4, 'Колонка Echo Mini', 'Аудио', 3490, 7);
```

### Значение по умолчанию

Добавьте два товара одной командой, **не указывая количество** — пусть сработает `DEFAULT`:

- `id` 4, «Чехол для Nova 8», «Аксессуары», 990;
- `id` 5, «Зарядка 65 Вт», «Аксессуары», 2490.

```sql seed
CREATE TABLE products (
    id       integer PRIMARY KEY,
    name     text NOT NULL,
    category text NOT NULL,
    price    integer NOT NULL,
    qty      integer NOT NULL DEFAULT 0
);
INSERT INTO products (id, name, category, price, qty) VALUES
    (1, 'Смартфон Nova 8', 'Смартфоны', 24990, 12),
    (2, 'Наушники Echo Buds', 'Аудио', 4990, 30),
    (3, 'Кабель USB-C 1 м', 'Аксессуары', 490, 120);
```

```sql check state
SELECT 1
WHERE (SELECT count(*) FROM products
       WHERE (id, name, category, price, qty) IN ((4, 'Чехол для Nova 8', 'Аксессуары', 990, 0),
                                                  (5, 'Зарядка 65 Вт', 'Аксессуары', 2490, 0))) = 2
  AND (SELECT count(*) FROM products) = 5;
```

```text hint
Добавить две строки одной командой, перечислив только номер, название, категорию и цену.
Остаток не упоминайте вовсе — база подставит значение по умолчанию сама.
```

```sql solution
INSERT INTO products (id, name, category, price)
VALUES
    (4, 'Чехол для Nova 8', 'Аксессуары', 990),
    (5, 'Зарядка 65 Вт', 'Аксессуары', 2490);
```

### Таблица с автонумерацией

Создайте таблицу `customers`:

- `id` — целое, первичный ключ, генерируется базой (`GENERATED ALWAYS AS IDENTITY` или `serial`);
- `name` — текст, обязательный;
- `email` — текст;
- `created_at` — дата, по умолчанию текущая (`current_date`).

Затем одной командой добавьте покупателя «Анна» с почтой `anna@example.com`, указав только имя и почту.

```sql check state
SELECT 1 FROM customers
WHERE id IS NOT NULL AND name = 'Анна' AND email = 'anna@example.com' AND created_at = current_date
  AND (SELECT count(*) FROM information_schema.columns
       WHERE table_schema = current_schema() AND table_name = 'customers') = 4;
```

```text hint
Шаг 1: создать таблицу «покупатели» — номер (выдаёт база), имя (обязательно), почта, дата создания (по умолчанию сегодня).
Шаг 2: добавить покупателя, указав только имя и почту.
Две команды разделяются точкой с запятой.
```

```sql solution
CREATE TABLE customers (
    id         integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name       text NOT NULL,
    email      text,
    created_at date NOT NULL DEFAULT current_date
);
INSERT INTO customers (name, email) VALUES ('Анна', 'anna@example.com');
```

## Тест

### Как в реляционной модели называется таблица?
- [x] Отношение
- [ ] Кортеж
- [ ] Атрибут
- [ ] Домен
> Отсюда и название «реляционная» (relation — отношение). Кортеж — строка, атрибут — столбец.

### Какой тип выбрать для хранения цены товара в рублях с копейками?
- [ ] real
- [ ] double precision
- [x] numeric(10,2)
- [ ] text
> real и double precision хранят числа приближённо, при сложении копеек появятся ошибки округления. numeric — точный тип.

### Какие утверждения о первичном ключе верны?
- [x] Его значение уникально для каждой строки
- [x] Он не может быть NULL
- [ ] В таблице может быть несколько первичных ключей
- [ ] Это обязательно столбец с именем id
> Первичный ключ в таблице один, но он может состоять из нескольких столбцов. Имя столбца любое.

### В каком порядке вернёт строки запрос `SELECT * FROM products` без ORDER BY?
- [ ] В порядке вставки
- [ ] По возрастанию первичного ключа
- [x] Порядок не гарантирован
- [ ] По алфавиту первого текстового столбца
> Часто строки приходят «в порядке вставки», но это совпадение: после UPDATE, VACUUM или при параллельном чтении порядок меняется. Нужен порядок — пишите ORDER BY.

### Что делает `DEFAULT 0` в описании столбца?
- [ ] Запрещает значения меньше нуля
- [x] Подставляет 0, если при INSERT столбец не указан
- [ ] Заменяет NULL на 0 при чтении
- [ ] Делает столбец обязательным
> DEFAULT срабатывает только при вставке, когда значение столбца не передано.

### Какие кавычки используются для строковых значений в SQL?
- [x] Одинарные: 'Москва'
- [ ] Двойные: "Москва"
- [ ] Обратные: `Москва`
- [ ] Любые
> Двойные кавычки в стандартном SQL и PostgreSQL обозначают имена объектов (таблиц, столбцов). Обратные — особенность MySQL.

### Какая команда создаёт таблицу?
= CREATE TABLE
> Полная форма: CREATE TABLE имя (столбец тип ограничения, ...).

### Какая команда добавляет строки в таблицу?
= INSERT
= INSERT INTO
> INSERT INTO таблица (столбцы) VALUES (...).

### Что такое NULL?
- [ ] Ноль
- [ ] Пустая строка ''
- [x] Отсутствие значения, «неизвестно»
- [ ] Ошибка в данных
> NULL — особая метка «значения нет». 0 и '' — обычные известные значения.

### Почему в INSERT стоит всегда перечислять столбцы явно?
- [ ] Без этого INSERT не работает
- [x] Иначе запрос сломается или запишет данные не туда, если структуру таблицы изменят
- [ ] Так запрос выполняется быстрее
- [ ] Это требование PostgreSQL для таблиц с первичным ключом
> Без списка столбцов значения раскладываются по их текущему порядку в таблице. Добавили столбец — и старый запрос перестал работать.

### Чем `GENERATED ALWAYS AS IDENTITY` удобен для первичного ключа?
- [x] База сама выдаёт следующий номер при вставке
- [ ] Гарантирует, что номера идут без пропусков
- [ ] Шифрует идентификаторы
- [ ] Позволяет хранить в столбце текст
> Номер выдаёт последовательность. Пропуски бывают — например, после отката транзакции номер не возвращается.

### Есть таблица `users(id, email, name)`. Какие команды корректны?
- [x] INSERT INTO users (email, name) VALUES ('a@b.ru', 'Аня');
- [x] INSERT INTO users (name, email) VALUES ('Аня', 'a@b.ru'), ('Борис', 'b@b.ru');
- [ ] INSERT INTO users VALUES email = 'a@b.ru';
- [ ] INSERT users SET email = 'a@b.ru';
> Вариант с SET — синтаксис MySQL, в PostgreSQL он не работает.

### Какой тип подходит для даты и времени события с учётом часового пояса?
- [ ] date
- [ ] timestamp
- [x] timestamptz
- [ ] text
> timestamptz хранит момент времени в UTC и переводит его в часовой пояс сессии при выводе. Для событий из разных часовых поясов это самый безопасный выбор.

### Как удалить таблицу `tmp` вместе с данными?
= DROP TABLE tmp
= DROP TABLE tmp;
= DROP TABLE IF EXISTS tmp
> Восстановить данные после DROP TABLE можно только из бэкапа.
