# Вложенные запросы

Иногда для ответа нужно сначала что-то посчитать: «товары дороже **средней** цены» — сначала средняя цена, потом сравнение. Подзапрос — это `SELECT` внутри другого запроса, в круглых скобках. Он позволяет решить задачу одним запросом, без ручного копирования промежуточных чисел.

## Скалярный подзапрос — одно значение

Подзапрос, который возвращает **одну строку и один столбец**, можно использовать как обычное значение:

```sql
SELECT name, price
FROM products
WHERE price > (SELECT avg(price) FROM products);

-- насколько цена отличается от средней
SELECT name, price, price - (SELECT round(avg(price)) FROM products) AS diff
FROM products;
```

Если такой подзапрос вернёт больше одной строки — ошибка `more than one row returned by a subquery used as an expression`. Если ни одной — значение будет `NULL`.

## Подзапрос-список: IN и NOT IN

Подзапрос, который возвращает **один столбец**, можно подставить в `IN`:

```sql
-- товары тех брендов, у которых есть ноутбуки
SELECT name, brand
FROM products
WHERE brand IN (SELECT brand FROM products WHERE category = 'Ноутбуки');
```

> [!danger] NOT IN и NULL
> Если подзапрос в `NOT IN` вернул хотя бы один `NULL`, весь `NOT IN` не найдёт **ни одной строки**.
> `x NOT IN (1, 2, NULL)` означает `x <> 1 AND x <> 2 AND x <> NULL`, а последнее — всегда `NULL`.
> Либо отфильтруйте `NULL` в подзапросе (`WHERE brand IS NOT NULL`), либо используйте `NOT EXISTS`.
> Это любимый вопрос на собеседованиях.

## EXISTS — «есть ли хоть одна строка»

```sql
-- категории, в которых есть товар дороже 50 000
SELECT DISTINCT category
FROM products p
WHERE EXISTS (
    SELECT 1 FROM products p2
    WHERE p2.category = p.category AND p2.price > 50000
);
```

`EXISTS` истинно, если подзапрос вернул хотя бы одну строку; что именно в `SELECT` подзапроса — неважно, поэтому пишут `SELECT 1`. `NOT EXISTS` корректно работает с `NULL` и обычно так же быстр, как `NOT IN`.

## Коррелированный подзапрос

В примере выше подзапрос ссылается на внешнюю строку: `p2.category = p.category`. Такой подзапрос называется **коррелированным** — логически он выполняется заново для каждой строки внешнего запроса.

```sql
-- товары дороже средней цены СВОЕЙ категории
SELECT name, category, price
FROM products p
WHERE price > (SELECT avg(price) FROM products p2 WHERE p2.category = p.category);
```

Здесь обязательны **псевдонимы таблиц** (`p`, `p2`): одна и та же таблица используется дважды, и без них не понять, какой `category` откуда.

## ANY и ALL

```sql
WHERE price > ALL (SELECT price FROM products WHERE category = 'Аудио')  -- дороже всех аудио
WHERE price > ANY (SELECT price FROM products WHERE category = 'Аудио')  -- дороже хотя бы одного
```

`= ANY (...)` — то же самое, что `IN (...)`. На практике `ALL` и `ANY` встречаются редко: обычно их заменяют на `max` и `min`.

## Подзапрос в FROM — производная таблица

Результат подзапроса можно использовать как таблицу. Ей обязательно нужно имя:

```sql
-- средняя стоимость остатков на одну категорию
SELECT round(avg(stock_value)) AS avg_category_value
FROM (
    SELECT category, sum(price * qty) AS stock_value
    FROM products
    GROUP BY category
) AS t;
```

Так делают «агрегат от агрегата»: `avg(sum(...))` написать нельзя, а через подзапрос — можно. Более читаемый способ — CTE (`WITH`), он будет в теме [[CTE — WITH и рекурсия]].

## Подзапрос в SELECT

```sql
SELECT category,
       count(*) AS products,
       round(100.0 * count(*) / (SELECT count(*) FROM products), 1) AS share_pct
FROM products
GROUP BY category;
```

### Дороже среднего

Выведите название и цену товаров, которые дороже средней цены по всем товарам.

```sql check
SELECT name, price FROM products WHERE price > (SELECT avg(price) FROM products);
```

```sql solution
SELECT name, price
FROM products
WHERE price > (SELECT avg(price) FROM products);
```

### Самый дорогой

Выведите название и цену самого дорогого товара. Решите через подзапрос с `max`, без `ORDER BY` и `LIMIT`.

```sql check
SELECT name, price FROM products WHERE price = (SELECT max(price) FROM products);
```

```text hint
Шаг 1: найти максимальную цену среди всех товаров.
Шаг 2: оставить товары, у которых цена равна найденной.
Так, если самых дорогих окажется два, покажутся оба.
```

```sql solution
SELECT name, price
FROM products
WHERE price = (SELECT max(price) FROM products);
```

### Отклонение от средней

Выведите название, цену и разницу между ценой и средней ценой всех товаров. Среднюю округлите до целых **до** вычитания.

```sql check
SELECT name, price, price - (SELECT round(avg(price)) FROM products) FROM products;
```

```sql solution
SELECT name, price, price - (SELECT round(avg(price)) FROM products) AS diff
FROM products;
```

### Всё в наличии

Выведите категории, в которых **все** товары есть в наличии. Используйте `NOT EXISTS`.

```sql check
SELECT DISTINCT category FROM products p
WHERE NOT EXISTS (SELECT 1 FROM products p2 WHERE p2.category = p.category AND p2.qty = 0);
```

```text hint
Оставить категорию, если не существует товара этой же категории с нулевым остатком.
Каждую категорию выведите один раз.
```

```sql solution
SELECT DISTINCT category
FROM products p
WHERE NOT EXISTS (
    SELECT 1 FROM products p2
    WHERE p2.category = p.category AND p2.qty = 0
);
```

### Средняя по категориям

Посчитайте стоимость остатков (цена × количество) по каждой категории, а затем выведите **одно число** — среднюю стоимость остатков на категорию, округлённую до целых.

```sql check
SELECT round(avg(s)) FROM (SELECT sum(price * qty) AS s FROM products GROUP BY category) t;
```

```text hint
Шаг 1 (внутренний запрос): стоимость остатков по каждой категории.
Шаг 2 (внешний запрос): среднее этих сумм, округлить.
Вложить одну агрегатную функцию в другую напрямую нельзя — промежуточный результат нужен как отдельная таблица с именем.
```

```sql solution
SELECT round(avg(stock_value)) AS avg_category_value
FROM (
    SELECT category, sum(price * qty) AS stock_value
    FROM products
    GROUP BY category
) AS t;
```

### Доля категории

Выведите категорию, число товаров в ней и долю этих товаров от общего числа в процентах, округлённую до одного знака.

```sql check
SELECT category, count(*), round(100.0 * count(*) / (SELECT count(*) FROM products), 1)
FROM products GROUP BY category;
```

```text hint
Доля = 100 × (товаров в категории) ÷ (товаров всего), округлить до одного знака.
«Товаров всего» — маленький отдельный запрос внутри большого.
Осторожно с делением целых чисел.
```

```sql solution
SELECT category,
       count(*) AS products,
       round(100.0 * count(*) / (SELECT count(*) FROM products), 1) AS share_pct
FROM products
GROUP BY category;
```

- [ ] Возьмётся последняя

### Что вернёт скалярный подзапрос, если не нашёл ни одной строки?
- [ ] 0
- [x] NULL
- [ ] Ошибку
- [ ] Пустую строку
> Пустой скалярный подзапрос даёт NULL.

### Подзапрос в `NOT IN` вернул значения (1, 2, NULL). Сколько строк найдёт `WHERE id NOT IN (...)`?
- [ ] Все, кроме id = 1 и id = 2
- [x] Ни одной
- [ ] Все строки
- [ ] Ошибка
> id NOT IN (1, 2, NULL) раскрывается в id <> 1 AND id <> 2 AND id <> NULL, а последнее всегда NULL.

### Как надёжно найти клиентов без заказов?
- [x] WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.client_id = c.id)
- [x] WHERE id NOT IN (SELECT client_id FROM orders WHERE client_id IS NOT NULL)
- [ ] WHERE id NOT IN (SELECT client_id FROM orders)
- [ ] WHERE id <> (SELECT client_id FROM orders)
> Третий вариант сломается, если в orders.client_id есть NULL. Четвёртый — ошибка, если заказов больше одного.

### Что такое коррелированный подзапрос?
- [ ] Подзапрос в FROM
- [x] Подзапрос, который ссылается на столбцы внешнего запроса
- [ ] Подзапрос с агрегатной функцией
- [ ] Подзапрос, который возвращает один столбец
> Логически он вычисляется для каждой строки внешнего запроса.

### Что важно в SELECT подзапроса внутри EXISTS?
- [ ] Нужно выбирать первичный ключ
- [ ] Нужно выбирать все столбцы через *
- [x] Ничего: EXISTS проверяет только, есть ли строки
- [ ] Должен быть ровно один столбец
> Поэтому пишут SELECT 1.

### Что эквивалентно `x = ANY (подзапрос)`?
= IN
= x IN (подзапрос)

### Как записать «цена больше, чем у каждого товара категории Аудио»?
- [x] price > ALL (SELECT price FROM products WHERE category = 'Аудио')
- [x] price > (SELECT max(price) FROM products WHERE category = 'Аудио')
- [ ] price > ANY (SELECT price FROM products WHERE category = 'Аудио')
- [ ] price IN (SELECT max(price) FROM products WHERE category = 'Аудио')
> ANY — «больше хотя бы одного», то есть больше минимального.

### Почему подзапросу в FROM нужен псевдоним?
- [x] Это обязательное требование: производная таблица должна иметь имя
- [ ] Иначе подзапрос выполнится дважды
- [ ] Без псевдонима нельзя использовать агрегаты
- [ ] Это рекомендация, а не требование
> В PostgreSQL 16+ псевдоним стал необязательным, но в большинстве СУБД и в старых версиях без него ошибка — пишите всегда.

### Как посчитать «среднее от сумм по группам»?
- [ ] SELECT avg(sum(amount)) FROM orders GROUP BY client_id
- [x] SELECT avg(s) FROM (SELECT sum(amount) AS s FROM orders GROUP BY client_id) t
- [ ] SELECT sum(avg(amount)) FROM orders
- [ ] SELECT avg(amount) FROM orders GROUP BY sum(amount)
> Агрегаты нельзя вкладывать друг в друга напрямую — нужен подзапрос или CTE.

### Почему в коррелированном подзапросе по той же таблице нужны псевдонимы?
- [x] Иначе не различить столбцы внешней и внутренней таблицы
- [ ] Иначе подзапрос не станет коррелированным
- [ ] PostgreSQL запрещает повторять имя таблицы
- [ ] Псевдонимы ускоряют запрос
> В `WHERE category = category` оба столбца будут из внутренней таблицы — условие всегда истинно.
