# Практика в терминале на домашнем сервере (Proxmox)

Рабочий план второй части большой задачи: кроме тестов и SQL-тренажёра — настоящая командная строка Linux и Windows прямо на странице темы. Команды выполняются на домашнем сервере с Proxmox, задание проверяется автоматически. Сайт полностью автономен: никаких внешних API и ИИ — объяснения пишутся вместе с задачей (замечания и разбор).

Сейчас все ученики работают на **одном** стенде (`LAB_SSH_HOST`) — для личного обучения этого достаточно. Отдельный стенд на ученика и многоузловые лаборатории — с драйвером Proxmox (этап 4).

## Как это устроено

```
Браузер: страница темы
  ├─ xterm.js — терминал ───── WebSocket (wss://сайт/lab/ws?token=…) ─┐
  └─ «Проверить» ─ серверное действие Next.js ────────────────────────┤
                                                                       ▼
LXC «learn-web» (Debian)                                  lab-runner (Node.js)
  ├─ Next.js + PostgreSQL (docker compose)                  ├─ сессии, лимиты, таймауты
  ├─ cloudflared — туннель наружу                           ├─ Proxmox API: клон / удаление стендов
  └─ lab-runner ─────────── SSH ───────────────┐            └─ SSH: терминал и скрипты проверки
                                                ▼
              Изолированная сеть vmbr1 (без доступа в домашнюю сеть)
                ├─ CT 9xxx — Linux-стенд: linked clone шаблона, жив 30–120 мин
                ├─ CT 9xxx — второй узел для лабораторий по сети / Ansible
                └─ VM «win-lab» — Windows Server, откат к снимку перед сессией
```

Главная идея: **любой стенд — это SSH-цель**. Linux — контейнер LXC, клонированный из шаблона за 2–5 секунд: настоящий systemd, сеть, пакеты, как на работе. Windows — виртуальная машина с OpenSSH и PowerShell. Терминал в браузере и скрипты проверки работают через один и тот же SSH, разница только в том, как стенд создаётся.

Почему не Docker-контейнеры: в Docker нет полноценного systemd и сети как на реальном сервере, а темы Linux — службы, диски, сеть, пользователи — требуют именно настоящей системы. Proxmox клонирует LXC почти так же быстро.

````markdown
### Создать пользователя deploy
Создайте пользователя `deploy`, добавьте его в группу `sudo` и задайте оболочку `/bin/bash`.

```bash setup
apt-get install -y -q sudo >/dev/null
```

```bash check
id deploy && id -nG deploy | grep -qw sudo && [ "$(getent passwd deploy | cut -d: -f7)" = /bin/bash ]
```

```text hint
useradd -m -s ... ; usermod -aG ...
```

```bash solution
useradd -m -s /bin/bash deploy && usermod -aG sudo deploy
```
````

Проверка — код возврата скрипта `check`, выполненного на стенде от root: 0 — задача решена. Для Windows — блоки `powershell setup` / `powershell check`. Решения хранятся как в SQL-тренажёре (`lab_solve`), проверка контента — `npm run lab:check` поднимает стенд и прогоняет решения.

## Безопасность

У ученика root на стенде, а стенд стоит в домашней сети. Поэтому:

- **Отдельная сеть** `vmbr1` для стендов: доступ в интернет через NAT (для `apt install`) — да, в домашнюю сеть (`192.168.0.0/16` и т.п.) и к Proxmox — нет. Правила в файрволе Proxmox.
- **API-токен Proxmox** с правами только на пул `labs`: клонировать, запускать, удалять стенды. Остальные машины сервера ему не видны.
- **Список допущенных** `ALLOWED_EMAILS`: войти через Google может любой, а стенды — ресурсы домашнего сервера.
- **Лимиты**: не больше 2 стендов одновременно, 1 ядро и 1 ГБ ОЗУ на стенд, бездействие 30 минут — стенд удаляется, общий срок жизни — 2 часа.
- **Токен терминала** — короткоживущая подпись HMAC от сайта (пользователь + стенд + срок), lab-runner не доверяет браузеру.
- **Наружу без открытых портов** — Cloudflare Tunnel (WebSocket поддерживается) или Tailscale, если сайт нужен только себе.

## Что можно сделать без сервера

Сделано: формат «Лаборатории», терминал на странице темы, `lab-runner` с драйвером «статический SSH», `lab:check`, 40 задач по Git, Linux и systemd. Стенд для разработки — WSL (`npm run lab:stand:wsl`); тот же `scripts/lab-stand/provision.sh` готовит и контейнер Proxmox.

Дальше без сервера можно: Linux — процессы и диски (loop-устройства), Docker (поставить Docker в WSL-стенд), Terraform с Docker-провайдером, базы данных и очереди в стенде.

## Вопросы к владельцу сервера

1. Версия Proxmox, свободные ресурсы (ядра, ОЗУ, диск) и тип хранилища: ZFS или LVM-thin (от этого зависит, будут ли клоны мгновенными).
2. Как сайт будет доступен: свой домен + Cloudflare Tunnel, белый IP и проброс порта, или только для себя через Tailscale/VPN?
3. Сайт и стенды в одном LXC (проще) или сайт в LXC, а стенды отдельно (рекомендуется: побег из стенда не задевает сайт и базу)?
4. Windows: подходит ли Windows Server Evaluation (бесплатно 180 дней, продлевается) и сколько ОЗУ под неё не жалко (минимум 4 ГБ)?
5. Будет ли у Claude SSH-доступ к Proxmox, или команды настройки выполняются вручную по инструкции?
